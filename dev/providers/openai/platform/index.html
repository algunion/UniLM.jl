Language models · OpenAI

Platform APIs

Besides its model APIs, OpenAI serves APIs that hold what a request works with — files, conversations, code-interpreter containers — and that run work beside it: batches, fine-tuning jobs, moderation, the webhooks that report on them, the safety records behind some of those webhooks, and provenance checks. UniLM wraps each with verbs of its own, on OPENAIServiceEndpoint unless a call names another service; OPENAIServiceEndpoint() returns that same type. The vector stores of file search are on Retrieval & file search, and images, speech and the Realtime API on Images, audio & realtime; which of these APIs other providers serve is on Capabilities by provider. Every verb, type and keyword is in the API reference: Files, Uploads, Conversations, Containers, Skills, Batch, Fine-tuning, Moderations, Webhooks and Safety & Provenance. UniLM does not wrap OpenAI's Agents API, which "gives your application access to the Codex harness through an OpenAI-managed API" (Agents API).

These calls are not recorded, so their output on this page is quoted from dated runs.

What the platform verbs share

  • Results. A verb returns a typed result, and throws only for what it refuses before sending (Limits and refusals): a *Success; a *Failure for an error status, holding the status, the body as response and the x-request-id header as request_id; or a *CallError when no usable reply came — a transport failure, a timeout, a cancel, a reply that does not decode —, holding the text as error and the exception as cause. FileSuccess, FileFailure and FileCallError are the Files family, and the others are named alike (Results).
  • One attempt. Each call but moderate makes a single attempt, bounded by the call's config, a RequestConfig; max_attempts does not change it. A create is never sent again: a POST that timed out, or drew a gateway 5xx after OpenAI stored its object, may still have made it, so a failed upload_file does not prove that no file was made. moderate, which is free and changes nothing when it is sent again, is sent again after a transient status or a transport failure, as a Chat is (Timeouts & Retries).
  • The key is read when the call is made: without OPENAI_API_KEY the result is the family's call error, whose cause is the KeyError naming it (Setup). The checkpoint-permission verbs send an admin key instead (Fine-tuning).
  • Cancellation. Each takes cancel, a CancelToken: the ambient one of with_cancel unless given. With the key set, a token already cancelled sends nothing, and a cancel during the call aborts it, either way with the call error, whose cause is a UniLMCancelled (Cancellation).
  • Cost. The results carry no usage: token_usage and estimated_cost throw for them. What OpenAI charges for storage and containers is on its pricing page. A batch's requests are the exception: batch_results returns each as a Chat or an embeddings result, priced at the Batch rates (Batches).
  • Deletes. A delete that OpenAI answers with a deletion record — of a file, a vector store, a container, a skill, a conversation, a checkpoint permission or a webhook endpoint — counts only when the record says "deleted": true: a reply without it, or with false, is the call error, the object being in place as far as UniLM can tell. The record of a vector store, a container, a file in either, a skill, a skill's version, a checkpoint permission, a webhook endpoint or a stored chat completion must also carry the id it deleted (the requested one is not put in its place) and name what it deleted as its object — "vector_store.deleted", "vector_store.file.deleted", "container.deleted", "container.file.deleted", "skill.deleted", "skill.version.deleted", "checkpoint.permission", "webhook_endpoint.deleted" or "chat.completion.deleted"; one without them, or naming another kind, is the call error. delete_conversation_item is answered with the conversation, which UniLM returns as it came.
  • Pages and statuses. A list reply, and a page of search results or of a file's content, must carry its data and has_more, and a vector store, a batch of its files, a file in it, a container, a fine-tuning job and a Batch API batch their status, as OpenAI's reference requires: a reply without them is the call error, never an empty last page or a status read as unknown.
  • Capabilities. Each verb first checks that its service has the capability it needs — :files, :uploads, :vector_stores, :conversations, :stored_completions, :containers, :skills, :batch, :fine_tuning, :moderation, :webhooks, :safety, :content_provenance, :transcription (which :audio implies) or :realtime —, all of which OPENAIServiceEndpoint declares (realtime_connect, which throws rather than returning a result and does not observe the token, is on Realtime sessions), and refuses an endpoint that declares its capabilities without it, or declares none (Limits and refusals; Capabilities by provider).

Files and uploads

upload_file(path, purpose) sends a file to POST /v1/files as multipart/form-data, with the purpose "assistants", "batch", "fine-tune", "vision" or "user_data"; the Evals API's "evals" is refused (Limits and refusals), since OpenAI's Evals "become read-only" on 31 October 2026 and "are scheduled to shut down" on 30 November 2026 (deprecations). "Individual files can be up to 512 MB, and each project can store up to 2.5 TB of files in total"; the Batch API "only supports .jsonl files up to 200 MB in size", and fine-tuning .jsonl files (Upload file). expires_after sets the seconds from the upload until the file expires, 3600 (one hour) to 2592000 (30 days), sent as OpenAI's expires_after with the anchor created_at; outside that range it is refused before the request, as OpenAI answers HTTP 400. Without it "files with purpose=batch expire after 30 days and all other files are persisted until they are manually deleted"; the time a file expires is its record's expires_at, in raw. list_files takes a purpose, a limit — "between 1 and 10,000, and the default is 10,000" —, after, the id of the last file of the page before (its has_more says whether one follows), and an order by creation time, "asc" or "desc"; a page without data or has_more is a FileCallError. retrieve_file reads one file's record, file_content its bytes, and delete_file removes it, which also is to "remove it from all vector stores" (Files); its result names the id and the object of OpenAI's reply. The same verbs reach Anthropic's and Gemini's Files APIs (Files API).

write("questions.jsonl", """{"custom_id": "q1", "method": "POST", "url": "/v1/responses", "body": {"model": "gpt-6-sol", "input": "Name a prime number."}}\n""")
up = upload_file("questions.jsonl", "batch")
up isa FileSuccess || error("upload failed: $up")
f = up.response
f.filename, f.purpose, f.bytes
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# ("questions.jsonl", "batch", 127)

listed = list_files(purpose="batch", limit=5)
listed isa FileListSuccess || error("listing failed: $listed")
any(x -> x.id == f.id, listed.response.data)
# true

content = file_content(f.id)
content isa FileContentSuccess || error("the download failed: $content")
save_file_content(content, "questions_copy.jsonl")
# "questions_copy.jsonl"

delete_file(f.id)
# FileDeleteSuccess("file-UYtK7VGBUPApXVa8Uz7epn", true, "file")
Evidence

Runs of 25 October 2026, 16:29–16:47 UTC, with UniLM's development branch after 0.26.0: OpenAI answered file_content of a file uploaded with the purpose "user_data" with HTTP 502 or 503 on each of three tries, while files with the purpose "batch" downloaded; four of ten delete_file calls drew HTTP 503 and succeeded when sent again; one upload_file drew HTTP 502, and a listing afterwards showed that no file had been made.

save_file_content writes the bytes atomically: to a temporary file beside the target, then renamed over it, so a failed write leaves an existing file whole; the file keeps its permission bits, a symbolic link is written through, and a directory is refused. An uploaded file goes to a Respond as input by its id, input_file(; id=…) for a document and input_image(; file_id=…) for an image (Input).

The Uploads API takes a large file in parts: "an Upload can accept at most 8 GB in total and expires after an hour after you create it", "Each Part can be at most 64 MB", and "The number of bytes uploaded upon completion must match the number of bytes initially specified when creating the Upload object" (Uploads). create_upload takes the Files purposes, "evals" refused as above (Limits and refusals) — "user_data" too, which the Uploads reference does not list and the API accepted on 16 November 2026 —, and the expires_after of upload_file, for the file the completed upload makes; add_upload_part sends one part, the bytes you give it; complete_upload joins the parts in the order the list gives their ids, checking an md5 of the whole file when given one, and returns the upload with its file; cancel_upload ends one. UniLM does not split a file: a file larger than a part is sent a slice at a time, as the second block below does.

data = read("requests.jsonl")
up = create_upload(filename="requests.jsonl", purpose="batch", bytes=length(data), mime_type="text/jsonl")
up isa UploadSuccess || error("create_upload failed: $up")
up.response.status, up.response.bytes
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# ("pending", 456)

half = length(data) ÷ 2
p1 = add_upload_part(up.response.id, data[1:half])
p2 = add_upload_part(up.response.id, data[half+1:end])
(p1 isa UploadPartSuccess && p2 isa UploadPartSuccess) || error("a part failed: $p1, $p2")
done = complete_upload(up.response.id, [p1.response.id, p2.response.id])
done isa UploadSuccess || error("complete_upload failed: $done")
done.response.status, done.response.file.filename, done.response.file.bytes, done.response.file.purpose
# ("completed", "requests.jsonl", 456, "batch")

A file larger than a part goes up a slice at a time, each slice a part:

parts = String[]
for slice in Iterators.partition(data, 50_000_000)
    part = add_upload_part(up.response.id, collect(slice))
    part isa UploadPartSuccess || error("a part failed: $part")
    push!(parts, part.response.id)
end
done = complete_upload(up.response.id, parts)

Conversations

A conversation of OpenAI's Conversations API holds a conversation's items on OpenAI's side, with "its own durable identifier", and works with the Responses API (conversation state). create_conversation(; items, metadata) makes one — "You may add up to 20 items at a time" — and conversation_id reads its id, which a Respond's conversation takes: "Items from this conversation are prepended to input_items for this response request. Input items and output items from this response are automatically added to this conversation after this response completes" (Create a model response, conversation).

c = create_conversation(metadata=Dict("topic" => "ferries"))
c isa ConversationSuccess || error("create failed: $c")
conv = conversation_id(c.response)
r1 = respond("Which planet of the solar system is the largest?"; conversation=conv,
             instructions="You are a concise assistant: answer in one short sentence.")
r1 isa ResponseSuccess || error("respond failed: $r1")
output_text(r1)
# Run on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-6-sol:
# "Jupiter is the largest planet in the solar system."

r2 = respond("And the smallest?"; conversation=conv,
             instructions="You are a concise assistant: answer in one short sentence.")
r2 isa ResponseSuccess || error("respond failed: $r2")
output_text(r2), r2.response.raw["conversation"]["id"] == conv, token_usage(r2).prompt_tokens
# ("Mercury is the smallest planet in the solar system.", true, 57)

items = list_conversation_items(conv; order="asc")
items isa ConversationItemListSuccess || error("listing failed: $items")
[(item.type, item.raw["role"]) for item in items.response.data]
# 4-element Vector{Tuple{String, String}}:
#  ("message", "user")
#  ("message", "assistant")
#  ("message", "user")
#  ("message", "assistant")

delete_conversation(conv)
# ConversationDeleteSuccess("conv_6ade313d1634819582bab2425f6f512a0c45c1ed494760a4", true)

conversation is sent as given, the id or a Dict("id" => …), and a Respond refuses it together with previous_response_id (Limits and refusals); the conversation's turns come back from OpenAI, so the second request sends only its question, and tool_loop chains through the conversation when the Respond sets one (Tools). "Conversation objects and items in them are not subject to the 30 day TTL" of a stored response (conversation state). retrieve_conversation and update_conversation(id, metadata) read and change the conversation's record, add_conversation_items appends items without a response, list_conversation_items pages through them (limit, order, after), retrieve_conversation_item(id, item_id; include) reads one, "a single item from a conversation", as a ConversationItemSuccess, and delete_conversation_item removes one, returning the conversation.

Code interpreter and containers

The code interpreter, a hosted tool of the Responses API, runs Python that the model writes, and "requires a container object", "a fully sandboxed virtual machine that the model can run Python code in" (Code Interpreter). code_interpreter() sends an auto container, {"type": "auto"}, which "automatically creates a new container, or reuses an active container that was used by a previous code_interpreter_call item in the model's context"; container takes OpenAI's other forms:

  • a Dict, sent as given: an auto container with its own settings;
  • a String, the id of a container made with create_container, sent as "container": "cntr_…".

file_ids, the ids of uploaded files, and memory_limit, the container's memory — "1g" (the default), "4g", "16g" or "64g", which "applies for the entire life of that container" — go inside the container Dict, the auto one unless you give another. With a container id, or beside a Dict that names the same key itself, they are refused, as is a memory limit not among those four (Limits and refusals): a container made beforehand has the memory it was made with, and takes its files through create_container(; file_ids) and add_container_file.

UniLM.encode_agentic shows the tool each form sends, with no key and no request:

sent(tool) = UniLM.encode_agentic(OPENAIServiceEndpoint, Respond(input="Total the prices.", tools=[tool]))
println(sent(code_interpreter()))
println(sent(code_interpreter(memory_limit="4g", file_ids=["file-abc123"])))
println(sent(code_interpreter(container="cntr_abc123")))

refusal = try code_interpreter(container="cntr_abc123", file_ids=["file-abc123"]); nothing catch err; err end
refusal isa ArgumentError || error("expected the request to be refused")
print(refusal.msg)

A run in a container made beforehand, with tool_choice="required" so that the model runs the tool, and include=["code_interpreter_call.outputs"] for what the code printed:

write("prices.csv", "item,price\nlantern,24.50\nrope,12.00\ncompass,38.75\n")

code_interpreter_outputs returns the response's code_interpreter_call items as OpenAI sent them, each with the code the model ran, the container_id it ran in and, with the include, its outputs. "A container expires if it is not used for 20 minutes. When this happens, using the container in v1/responses will fail", and its data is discarded: "You should download any files you may need from the container while it is active" (Code Interpreter). create_container(; name, file_ids, expires_after, memory_limit, network_policy, skills) makes a container: memory_limit as above, OpenAI's default "1g" when not given; network_policy, its outbound access, ContainerNetworkDisabled() or ContainerNetworkAllowlist(domains; domain_secrets), whose ContainerDomainSecret(domain, name, value)s OpenAI injects for an allowlisted domain (UniLM never prints a secret's value); and skills, the skills it loads (Skills): SkillReference(skill_id; version)s to skills made with create_skill, version a positive integer or "latest", the skill's default version when not given, and InlineSkill(zip; name, description)s, whose zip goes with the request. An organization whose policy disables container network access gets OpenAI's 400 for an allowlist: "Network policy 'allowlist' is not permitted because the organization policy disables container network access" (16 November 2026). retrieve_container, list_containers(; limit, order, after, name) — name keeps the containers of that name — and delete_container read, list and delete containers. add_container_file(id, path) uploads a file into one, and add_container_file(id; file_id) copies one uploaded through the Files API, either returning a ContainerSuccess whose response is the file's record, its path where the code sees it; a path that is no file is refused before anything is sent (Limits and refusals). list_container_files, retrieve_container_file and delete_container_file list, read and delete the files in a container — those the code wrote too, whose source is "assistant" — and container_file_content downloads one as a FileContentSuccess, which save_file_content writes to disk. A container bills "1 GB $0.03, 4 GB $0.12, 16 GB $0.48, 64 GB $1.92 per 20-minute session per container", and "Eligible container sessions will be billed by the minute, with a 5-minute minimum per session" (pricing), which estimated_cost leaves out (Cost and usage).

Skills

A skill is "a directory with a SKILL.md manifest containing front matter and instructions" (Skills), which a container loads. create_skill(path) uploads one: the folder, each file a part named by its path under the folder's name — its hidden entries (a name starting with ., such as .env or .git/) never sent —, or a .zip of it; a folder without a SKILL.md at its root, a path that is neither, and more than 500 files to send are refused before anything is sent. The SkillObject holds its name and description, from the SKILL.md, its default_version — the one a reference without a version loads — and its latest_version. create_skill_version(id, path; default) uploads the whole skill again as its next version, default=true making it the default, and update_skill(id; default_version) moves the default; retrieve_skill, list_skills(; limit, order, after), list_skill_versions and retrieve_skill_version read them back, a version by its number. OpenAI notes that "A newly uploaded version can briefly return 404". skill_content(id; version) downloads the zip, of the default version without version, as a FileContentSuccess; delete_skill_version deletes a version other than the default (the last one, the skill), and delete_skill the skill with its versions. The same verbs reach Anthropic's Skills API (Skills API).

A container loads a skill by reference, or inline, its zip sent with the request: across a container's inline skills OpenAI's API specification allows "at most 50 MiB" of zip, and create_container refuses more before sending (OpenAI answered a 51 MiB zip with HTTP 400 string_above_max_length, 17 November 2026). An inline skill is named and described as its SKILL.md names and describes it: OpenAI answers other values with HTTP 400 "Inline skill name/description must match the values in SKILL.md/Skills.md front matter." Just after a version is deleted, list_skill_versions may still list it for a moment.

s = create_skill("skills/csv-sum")          # csv-sum/SKILL.md and the files beside it
s isa SkillSuccess || error("upload failed: $s")
v = create_skill_version(s.response.id, "skills/csv-sum"; default=true)
v.response.version, retrieve_skill(s.response.id).response.default_version
# ("2", "2")
one = skill_content(s.response.id; version=1)   # version 1's zip, named and described as s
c = create_container(name="sandbox", skills=[SkillReference(s.response),
                     InlineSkill(one.content; name=s.response.name, description=s.response.description)])
delete_skill(s.response.id)

Batches

The Batch API runs requests "with 50% lower costs, a separate pool of significantly higher rate limits, and a clear 24-hour turnaround time" (Batch API). Its input is a .jsonl file, uploaded with the purpose "batch", each of whose lines is one request: a unique custom_id, the method, the url — /v1/responses, /v1/chat/completions, /v1/embeddings, /v1/completions, /v1/moderations, /v1/images/generations or /v1/images/edits — and the body, "the same as the parameters for the underlying endpoint"; "each input file can only include requests to a single model", and "A single batch may include up to 50,000 requests". The bodies can be the ones UniLM would send, so its request rules hold for them: UniLM.encode_agentic of a Respond, or UniLM.encode_request of a Chat.

using JSON
questions = ["What is the capital of Norway?", "What is the capital of Peru?"]
lines = [JSON.json(Dict("custom_id" => "capital-$i", "method" => "POST", "url" => "/v1/responses",
                        "body" => JSON.parse(UniLM.encode_agentic(OPENAIServiceEndpoint,
                                      Respond(input=q, instructions="Answer with the city's name only.")))))
         for (i, q) in enumerate(questions)]
write("capitals.jsonl", join(lines, "\n") * "\n")
lines[1]
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# "{\"body\":{\"input\":\"What is the capital of Norway?\",\"instructions\":\"Answer with the city's name only.\",\"model\":\"gpt-6-sol\"},\"custom_id\":\"capital-1\",\"method\":\"POST\",\"url\":\"/v1/responses\"}"

input = upload_file("capitals.jsonl", "batch")
input isa FileSuccess || error("upload failed: $input")
batch = create_batch(input.response.id, "/v1/responses"; metadata=Dict("job" => "capitals"))
batch isa BatchSuccess || error("the batch was not created: $batch")
batch.response.status, get(batch.response.raw, "completion_window", nothing)
# ("validating", "24h")

seen = retrieve_batch(batch.response.id)   # one read
seen isa BatchSuccess || error("the read failed: $seen")
seen.response.status
# "validating"

stopped = cancel_batch(batch.response.id)
stopped isa BatchSuccess || error("the cancel failed: $stopped")
stopped.response.status
# "cancelling"

Read back once the cancel had settled:

settled = retrieve_batch(batch.response.id)
settled isa BatchSuccess || error("the read failed: $settled")
settled.response.status, settled.response.request_counts, settled.response.output_file_id
# Read on 25 October 2026, eleven minutes after the cancel:
# ("cancelled", Dict{String, Any}("completed" => 0, "failed" => 0, "total" => 0), nothing)

create_batch(input_file_id, endpoint; completion_window="24h", metadata, output_expires_after) sends the endpoint as given — "the completion window can only be set to 24h" —, and output_expires_after, when set, as the seconds after which the batch's output and error files expire, counted from each file's creation, from 3600 (1 hour) to 2592000 (30 days); a value outside that range is refused with an ArgumentError before anything is sent. retrieve_batch, list_batches and cancel_batch read, list and cancel batches. A batch moves through OpenAI's statuses: validating, in_progress, finalizing and completed; failed when "the input file has failed the validation process"; expired when it "was not able to be completed within the 24-hour time window"; and cancelling, which "may take up to 10 minutes", then cancelled. poll_batch reads a batch until it is completed, failed, cancelled or expired (Long-running jobs).

The results are files: output_file_id names the output, which "will have one response line for every successful request line in the input file", and error_file_id the errors; "the output line order may not match the input line order", so match lines by custom_id. Either id is nothing while the batch has no such file, as for the batch cancelled above, so read it before calling file_content:

done = poll_batch(batch.response.id)
done isa BatchSuccess || error("the batch did not finish: $done")
out = done.response.output_file_id
if !isnothing(out)
    content = file_content(out)
    content isa FileContentSuccess || error("the download failed: $content")
    save_file_content(content, "capitals_out.jsonl")
end

An expired batch's "unfinished requests within that batch are cancelled, and any responses to completed requests are made available via the batch's output file. You will be charged for tokens consumed from any completed requests." The batch.completed, batch.cancelled, batch.expired and batch.failed webhooks report the end without a poll (Webhooks). OpenAI's Batch API deletes no batch and updates none: delete_batch and update_batch throw ArgumentError here; delete_file removes a batch's files.

A batch of chat requests needs no file of yours: create_batch(requests) takes them as custom_id => Chat pairs, writes the input file — one /v1/chat/completions line per request, its body the one chatrequest! sends —, uploads it with the purpose "batch" and creates the batch, metadata and output_expires_after as above. A streamed Chat, an empty or repeated custom id, a Chat for another endpoint and Chats for two models (one input file, one model, as above) are refused with an ArgumentError before anything is sent; should the create fail after the upload, the file stays, under the purpose "batch". batch_results reads the output file's lines, then the error file's, and returns each request's result by its custom id: a 200 is the LLMSuccess chatrequest! returns for its body, its usage naming the tier "batch", so estimated_cost bills it at the Batch rates (Cost and usage); another status is an LLMFailure with it; a request that got no response, such as one a batch expired before it ran, is an LLMCallError holding OpenAI's error object as JSON. A batch without either file yet is a BatchCallError naming its status, and one that ended without either — it failed validation, or expired or was cancelled before a request ran — a BatchCallError holding the batch's errors. A batch of another endpoint, such as the /v1/responses one above, is a BatchCallError naming file_content(output_file_id), which reads its output file. Pass the pairs that created the batch, batch_results(id; requests), and each result's self is its request's own Chat, a copy with the reply appended for a success, so the conversation goes on with chatrequest!.

luna() = Chat(model="gpt-6-luna", reasoning_effort="none", max_tokens=16,
              messages=[Message(Val(:user), "Reply with exactly: ok")])
batch = create_batch(["one" => luna(), "two" => luna()])
batch isa BatchSuccess || error("the batch was not created: $batch")
batch.response.status, batch.response.endpoint
# ("validating", "/v1/chat/completions")

done = poll_batch(batch.response.id; interval=30)

results isa BatchResultsSuccess || error("the results were not read: $results")

# 7 minutes:

A batch of embeddings goes the same way: create_batch(requests) takes custom_id => Embeddings pairs, each line a /v1/embeddings request whose body is the one embeddingrequest! sends — a text or a vector of them —, to one model, and at most 50,000 inputs across the batch: "/v1/embeddings batches are also restricted to a maximum of 50,000 embedding inputs across all requests in the batch" (more are refused before anything is sent). batch_results returns each request's result as embeddingrequest! returns it: an EmbeddingSuccess whose usage names the tier "batch", an EmbeddingFailure for an error status, an EmbeddingCallError for a request without a response or a reply that holds no vectors. The pricing page lists no Batch price for the embedding models, and the Batch guide gives a "50% cost discount compared to synchronous APIs" on every endpoint it batches, /v1/embeddings among them, so estimated_cost bills a batched embedding at half its model's rate. A success holds a stand-in Embeddings with the vectors (one empty text per vector, its model the reply's); with the requests, batch_results(id; requests), a copy of its request filled with them, the request unchanged.

small(x) = Embeddings(x; model="text-embedding-3-small", dimensions=8)

done = poll_batch(batch.response.id; interval=30)
results = batch_results(batch.response.id; requests)
[(id, r.usage.service_tier, embedding_vectors(r)) for (id, r) in results.results]

# file held one line per request, `response.body` the /v1/embeddings reply: one 8-dimension vector for "one",

Fine-tuning

"OpenAI is winding down the fine-tuning platform. The platform is no longer accessible to new users. Eligible existing customers can create training jobs until January 6, 2027, unless the base model shuts down earlier", and "Fine-tuned models remain available for inference until their base model shuts down" (supervised fine-tuning). The default model takes no fine-tuning: its model page lists v1/fine-tuning as "Not supported" (GPT-6 Sol). No job was run for this page, so this block has no output:

train = upload_file("train.jsonl", "fine-tune")
train isa FileSuccess || error("upload failed: $train")
job = create_fine_tuning_job(model=base_model, training_file=train.response.id,
                             method=Dict("type" => "supervised",
                                         "supervised" => Dict("hyperparameters" => Dict("n_epochs" => 2))))
job isa FineTuningSuccess || error("the job was not created: $job")
r = retrieve_fine_tuning_job(job.response.id)
r isa FineTuningSuccess || error("the read failed: $r")
r.response.status, r.response.fine_tuned_model

base_model is a model your organization may still fine-tune. create_fine_tuning_job sends model, training_file and, when set, validation_file, method — a Dict that names the "supervised", "dpo" or "reinforcement" method with its hyperparameters —, suffix, metadata, seed — "Passing in the same seed and job parameters should produce the same results, but may differ in rare cases", from 0 to 2147483647 — and integrations, a vector of WandbIntegrations that report the job's metrics to a Weights & Biases project. A job's status is one of "validating_files, queued, running, pausing, paused, succeeded, failed, or cancelled" (Fine-tuning), and fine_tuned_model names the model it made, which a Chat or a Respond takes as its model; a job reply without a status, or a list reply without data or has_more, is the FineTuningCallError. No verb waits for a job: read it with retrieve_fine_tuning_job, page through list_fine_tuning_events and list_fine_tuning_checkpoints (limit, after), or take the fine_tuning.job.succeeded, fine_tuning.job.failed and fine_tuning.job.cancelled webhooks (Webhooks). cancel_fine_tuning_job, pause_fine_tuning_job and resume_fine_tuning_job cancel, pause and resume a job — one that cannot pause in its state is OpenAI's 400 —, and list_fine_tuning_jobs lists jobs, only those whose metadata holds each pair of metadata=Dict(…) when it is given.

A checkpoint is shared with other projects of the organization by create_fine_tuning_checkpoint_permission(checkpoint, project_ids), and its permissions are listed and deleted by list_fine_tuning_checkpoint_permissions and delete_fine_tuning_checkpoint_permission. Each "requires an admin API key" (Fine-tuning), which is not the project key OPENAI_API_KEY holds: they send their admin_key keyword, else the OPENAI_ADMIN_KEY variable, as the request's only credential, and without either throw an ArgumentError naming both before any request. A project key sent as the admin key is refused, a FineTuningFailure (a 401 naming the missing scope api.fine_tuning.checkpoints.read, on 16 November 2026).

A reinforcement job scores its samples with the grader its method Dict holds, in OpenAI's form, sent as given. UniLM does not wrap the endpoints that run or validate a grader without a job: "OpenAI is deprecating graders as part of the evals and fine-tuning workflows they support" (graders).

It doesn't classify audio. The moderation endpoint is free to use, and image files can be up to 20 MB" (moderation). input is a string, a vector of strings, or a vector of content parts, text and image_url ones, which are one input together:

A ModerationResponse holds one ModerationResult per input — its flagged, its categories, each true or false, and its category_scores — and the model; each result keeps its row as raw. A reply whose rows do not match the inputs one for one, or a row without flagged, is a ModerationCallError: a verdict that cannot be matched to its input is no verdict. is_flagged is true when any row is flagged, and throws an ArgumentError for a ModerationFailure or a ModerationCallError rather than answering false, which would let unmoderated content through: check issuccess first, and decide what a missing verdict means. A Chat or a Respond can also moderate its own input and output with a ModerationConfig, whose results a Chat's result keeps as its moderation and a Respond's in result.response.raw["moderation"] (Chat Completions, Request options): ModerationConfig(; model, input_mode, output_mode) needs its model, and sends each mode set, "score" or "block", as the policy of its side. The moderation of an image request is another setting, the filtering level of the image models (Image generation).

Webhooks

OpenAI's webhooks "allow you to receive real-time notifications about events in the API, such as when a batch completes, a background response is generated, or a fine-tuning job finishes. Webhooks are delivered to an HTTP endpoint you control, following the Standard Webhooks specification", and each endpoint, made on OpenAI's dashboard or with create_webhook_endpoint (below), comes with "a signing secret to use for server-side verification of incoming webhook requests" (webhooks). verify_webhook(payload, headers, secret) checks a delivery against it, with no request: payload is the raw body, headers the request's headers, which hold webhook-id, webhook-timestamp and webhook-signature, and secret the signing secret, with or without its whsec_ prefix. It returns true when a fresh v1 signature of the delivery is valid, false otherwise. A stored delivery, here with a made-up secret, verifies with tolerance_seconds=Inf, which skips the time check:

secret = "whsec_dW5pbG0tZG9jcy1leGFtcGxlLXNlY3JldC0zMmJ5dGU="
payload = """{"object": "event", "id": "evt_6ade2f3c7a3881908e0a6a1f2c3b4d5e", "type": "batch.completed", "created_at": 1792946400, "data": {"id": "batch_6ade2f3a1b2c8190a7d6e5f4c3b2a190"}}"""
headers = Dict("webhook-id" => "wh_6ade2f3c90f48190b5e1c2a7d4f61b0e", "webhook-timestamp" => "1792946400",
               "webhook-signature" => "v1,KuH1/bBMozlJfbeUhblkBOne1gUNyD41q48+86kVGAQ=")
verify_webhook(payload, headers, secret; tolerance_seconds=Inf), verify_webhook(payload, headers, secret)

The second call keeps the default window, 300 seconds either side of now, and the delivery is older, so it fails, as a replayed delivery does. parse_webhook reads a verified payload into a WebhookEvent:

event = parse_webhook(payload)
event.type, event.data["id"], event.type in WEBHOOK_EVENTS

WEBHOOK_EVENTS lists the event types: responses, batches and fine-tuning jobs that end, incoming calls of the Realtime and Live APIs, a Live session that connects (live.transport.connected), safety notices, whose records Safety and provenance reads, and the sessions of OpenAI's Agents API and their environments (agent.session.*, agent.environment.*). It leaves out the eval.run.* events, which OpenAI sends until the Evals API shuts down on 30 November 2026, and video.completed and video.failed, the events of the Videos API, which shut down on 24 September 2026 (deprecations) though list_webhook_event_types still returned them on 16 November 2026, so a filter on it drops them. On a server, the payload is the request's body as it arrived, before any JSON parsing, here in an HTTP.serve handler, with handle_batch your own function:

using HTTP
HTTP.serve("0.0.0.0", 8000) do req
    payload = String(req.body)
    verify_webhook(payload, req.headers, ENV["OPENAI_WEBHOOK_SECRET"]) || return HTTP.Response(400)
    event = parse_webhook(payload)
    event.type == "batch.completed" && Threads.@spawn handle_batch(event.data["id"])
    return HTTP.Response(200)
end

OpenAI asks for a quick 2xx: "If the endpoint doesn't return a successful (2xx) status code, or doesn't respond within a few seconds, the webhook request will be retried. OpenAI will continue to attempt delivery for up to 72 hours with exponential backoff", and it "may deliver duplicate copies of the same webhook event. You can use the webhook-id header as an idempotency key to deduplicate" (webhooks). A negative or NaN tolerance is refused, and so is a secret that is not base64 after its whsec_ prefix, such as a placeholder like whsec_*** or misplaced padding; whitespace around the secret is ignored. An empty secret — "", as an unset variable read with a default gives, or whsec_ alone — is refused whatever the delivery, since anyone can sign with an empty key (Limits and refusals).

A project's endpoints are managed with its API key (the :webhooks capability). create_webhook_endpoint(; name, url, event_types) makes one, OpenAI delivering the event_types to the HTTPS url, and returns it with its signing_secret, which OpenAI returns only then and from rotate_webhook_endpoint_secret — whose keep_old_secret_active_for_24_hours=true keeps the previous secret valid for a day —, so keep it for verify_webhook; a reply without one is the WebhookEndpointCallError. A printed or logged endpoint, or a result or page holding one, shows the secret as <not shown> and leaves raw out; the field still holds it. list_webhook_endpoints (limit, after, newest first), retrieve_webhook_endpoint, update_webhook_endpoint (name, url and the whole new set of event_types) and delete_webhook_endpoint read, change and remove endpoints; test_webhook_endpoint(id, event_type) has OpenAI send a sample delivery and returns the HTTP status the endpoint answered with; list_webhook_event_types returns the event types the project may subscribe to.

Safety and provenance

The safety.warning_issued and safety.deactivation_issued webhooks carry the id of a safety case, and safety.alert.created the id of a project safety alert. retrieve_safety_case reads a case as a SafetyCase: the entity_identifier it concerns — a safety_identifier your requests sent —, its reason and its notice, "warning" or "deactivation". retrieve_safety_alert reads an alert as a SafetyAlert: the request_id, response_id and model of the request it concerns, request_paused — "Whether block registration succeeded for this request. This does not confirm that response execution stopped" (API specification) —, its error_type and its reason, nothing for a zero-data-retention request. A case or an alert the key may not read, or none, is OpenAI's 404, a SafetyFailure; reading a case also needs the key's api.safety.read scope, without which OpenAI answered 403 on 16 November 2026.

check_content_provenance(path) asks whether an image, an audio file or a PDF carries OpenAI's provenance signals, sending the file as the one multipart part file, its media type on the part: the one the extension names, or mime_type. Each signal that applies is a ProvenanceResult: "c2pa", C2PA Content Credentials, with the manifest's validation_state and issuer, or "synthid", a SynthID watermark, each with its outcome, "detected" or "not_detected", and the model and generated_at time it records. "If not_detected, it means the tool did not find supported signals in the uploaded file. The content could still have been generated by OpenAI if the metadata was stripped or has evidence of tampering, the watermark was degraded, it comes from a legacy generation model, or it was created before provenance signals were available" (content provenance). The guide limits a file to 50 MiB and audio to 60 seconds, which OpenAI checks.

If store is omitted or set to false for a background request, the response is deleted after roughly 10 minutes" (background mode).
