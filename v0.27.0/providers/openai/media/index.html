Language models · OpenAI

Images, audio & realtime

Image generation

generate_image sends an ImageGeneration to OpenAI's Images API, POST /v1/images/generations, and edit_image an ImageEdit to POST /v1/images/edits, as multipart/form-data with each image and the mask as a file. Both take gpt-image-2.5-sunburst unless the request names another model; the request's model field stays "" until the request is serialized, so JSON.json(ig) shows the model that goes. OpenAI's options are sent as given, for OpenAI to judge:

  • size: "1024x1024", "1536x1024", "1024x1536" or "auto", or a WIDTHxHEIGHT of the GPT Image 2 and 2.5 models, where "Width and height must be multiples of 16, the aspect ratio must be between 1:3 and 3:1, and neither edge may exceed 3840 pixels. The total pixel count must be between 655,360 and 8,294,400 (4K)" (image generation).
  • quality: "low", "medium", "high" or "auto", and "xhigh" and "max" on the 2.5 models, which "default to auto"; "Use quality: "low" for quick drafts" (image generation).
  • background, output_format, output_compression: "transparent", "opaque" or "auto", a transparent one with "png" or "webp"; the format "png", the default, "jpeg" or "webp"; the compression from 0 to 100 of a JPEG or WebP, which "defaults to 100".
  • n: how many images one request makes, "between 1 and 10", which image_data lists in order.
  • moderation: "auto", the default, or "low" "for less restrictive filtering": the filtering of the image models' prompts and images, a setting of the Images API and not the Moderations API (Moderation).
  • safety_identifier: "A stable identifier for an end user in your organization", for which OpenAI asks you to "Hash a username or email address to avoid sending identifying information"; it takes the place of the deprecated user, which the image requests do not have, and UniLM checks that it is 1 to 128 characters (Limits and refusals).

The quoted words are from OpenAI's Images reference unless the line names the guide. An image request is not recorded, so its output here is quoted from a live run, at the smallest size and the lowest quality:

result = generate_image("A lighthouse on a rocky coast at dusk, flat vector illustration";
                        size="1024x640", quality="low", output_format="jpeg")
result isa ImageSuccess || error("the image request failed: $result")
save_image(image_data(result)[1], "lighthouse.jpg")
# Generated on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-image-2.5-sunburst:
# "lighthouse.jpg"

u = token_usage(result)
(; u.prompt_tokens, u.completion_tokens)
# (prompt_tokens = 18, completion_tokens = 107)

OpenAI's image models "always return base64-encoded images" (Images), which image_data lists and save_image decodes into a file, and the reply repeats the size, quality, output_format and background it used, in result.response.raw. An edit sends the image as a file, with the prompt:

edited = edit_image("lighthouse.jpg", "Make it a winter night with snow on the rocks";
                    size="1024x640", quality="low", output_format="jpeg")
edited isa ImageSuccess || error("the edit failed: $edited")
save_image(image_data(edited)[1], "lighthouse_winter.jpg")
eu = token_usage(edited)
(; eu.prompt_tokens, eu.completion_tokens)
# Edited on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-image-2.5-sunburst:
# (prompt_tokens = 666, completion_tokens = 107)

image is a path or a vector of paths, "up to 16 images", and mask the path of an image whose transparent area marks what to change: "The image to edit and mask must be of the same format and size (less than 50MB in size)", and "The mask image must also contain an alpha channel" (image generation). input_fidelity is sent as given; OpenAI's reference documents it for gpt-image-1.5 and gpt-image-1-mini and says "For gpt-image-2, omit this parameter". UniLM reads the files as it sends the request, so a path that is no file makes the result an ImageCallError, not a throw.

token_usage reads the reply's usage: the prompt's text tokens, and an edit's input image too, as input — 640 image and 26 text tokens in the edit above, by the input_tokens_details of its response.usage — and the image as output. UniLM does not price images: estimated_cost throws ArgumentError for an ImageSuccess unless you pass model=, which it prices by a pricing row of your own. OpenAI bills gpt-image-2.5-sunburst text input at $5, image input at $8 and image output at $30 per million tokens (GPT-Image-2.5 Sunburst): the generation above came to about $0.0033 and the edit to about $0.0085.

A request is sent again after a transient status, as a Chat is (When something fails), and a cancel of its cancel token, the ambient one unless given, ends it with an ImageCallError whose cause is a UniLMCancelled. A prompt or image the filters stop is an ImageFailure whose response holds OpenAI's error, type "image_generation_user_error" and code "moderation_blocked", which OpenAI asks not to send again as it is: "Don't automatically retry these errors without modifying the prompt or input images" (image generation). image_data of a failure throws an LLMResultError. The gpt-image-1-mini, gpt-image-1.5 and chatgpt-image-latest models shut down on 1 December 2026, with gpt-image-2.5-sunburst or gpt-image-2.5-flare the replacements (deprecations). A Respond makes images with the image_generation_tool (Hosted tools), and the verbs every provider shares are on Image Generation; every field is in the Image Generation API reference.

Audio

speak reads text aloud through a session of OpenAI's Realtime API, not the Speech API: OpenAI's tts-1, tts-1-hd and gpt-4o-mini-tts "are deprecated and will shut down on January 6, 2027", and their replacement, gpt-realtime-2.1-mini, "isn't a supported model for /v1/audio/speech" (text to speech). UniLM opens wss://api.openai.com/v1/realtime on gpt-realtime-2.1-mini unless model names another, sets the voice, 24 kHz 16-bit mono PCM output and instructions to read the text word for word, sends the text as a user message, asks for a response and collects its audio; instructions follow its own as delivery directions. Realtime models are conversational, and a session's instructions "are not guaranteed to be followed by the model" (Realtime client events, instructions).

  • voice: "marin", the default, or one of OpenAI's other built-in voices, "alloy", "ash", "ballad", "coral", "echo", "sage", "shimmer", "verse" and "cedar": "We recommend marin and cedar for best quality". A custom voice, which a session takes by its id, is refused (Limits and refusals).
  • speed: from 0.25 to 1.5 — "1.0 is the default speed" —, "a post-processing adjustment to the audio after it is generated".
  • response_format: "wav", the default, a WAV file with a 44-byte header, or "pcm", the samples alone (content_type "audio/pcm").

The quoted words are from the session's audio.output in OpenAI's Realtime client events.

Speech is not recorded, so its output here is quoted from a live run:

s = speak("The Harbor Club ferry leaves pier 7 at nine fifteen.";
          instructions="calm and clear, like a station announcement")
s isa SpeechSuccess || error("speech failed: $s")
s.content_type, length(s.audio)
# Spoken on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-realtime-2.1-mini:
# ("audio/wav", 175244)

(length(s.audio) - 44) / (24_000 * 2)   # seconds of 16-bit mono at 24 kHz, after the WAV header
# 3.65

save_audio(s, "ferry.wav")

transcribe uploads an audio file to POST /v1/audio/transcriptions, on gpt-transcribe unless model names another. "Files can be up to 25 MB. Supported input formats are mp3, mp4, mpeg, mpga, m4a, wav, and webm" (file transcription). prompt, keywords and languages give the model context — "Literal terms that may appear in the audio" and "A list of expected input languages" — and gpt-transcribe uses "languages instead of the singular language field" (transcription): UniLM sends a singular language as a one-element languages to a gpt-transcribe model, and as language to the others.

t = transcribe("ferry.wav"; keywords=["Harbor Club"], languages=["en"])
t isa TranscriptionSuccess || error("transcription failed: $t")
transcript_text(t)
# Transcribed on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-transcribe:
# "The Harbor Club ferry leaves Pier 7 at 9:15."

t.raw
# Dict{String, Any} with 3 entries:
#   "usage"     => Dict{String, Any}("seconds"=>4, "type"=>"duration")
#   "text"      => "The Harbor Club ferry leaves Pier 7 at 9:15."
#   "languages" => Any[Dict{String, Any}("code"=>"en")]

transcript_text reads the text, and raw keeps the JSON reply: the languages gpt-transcribe detected — "When the model can't make a reliable language prediction, it returns "languages": []" (file transcription) — and the usage, here a duration. A response_format of "text", "srt" or "vtt" returns plain text, which raw does not hold; subtitles, timestamps and speaker labels come from models OpenAI deprecated, which "will shut down on February 26, 2027" with /v1/audio/translations (transcription). The default model is gpt-transcribe on OpenAI, and on an endpoint of your own that declares :audio or :transcription; an endpoint that declares its capabilities without either cannot transcribe: transcribe throws ArgumentError before any request (Limits and refusals), and one that declares none, a MethodError (Platform APIs).

translate streams the speech of a WAV file through a Realtime translation session, wss://api.openai.com/v1/realtime/translations on gpt-realtime-translate, into language (English unless named), and returns the translated transcript as a TranscriptionSuccess; the translated speech the session also sends is not kept. OpenAI's translation sessions take "base64-encoded 24 kHz PCM16 audio" over WebSockets (Realtime translation), so UniLM reads a 16-bit PCM WAV file of any rate and channel count, mixes it down to one channel, resamples it by linear interpolation, with no anti-aliasing filter, and sends it in 200 ms frames; any other file is refused (Limits and refusals).

tr = translate("ferry.wav"; language="fr")
tr isa TranscriptionSuccess || error("translation failed: $tr")
transcript_text(tr)
# Translated on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-realtime-translate:
# "La navette du Harbor Club quitte le quai 7 à 9 h 15."

Speech already in the target language can come back as empty text, and a short clip's translation varies from call to call, as the translate reference reports.

What speak and translate return when they fail:

  • AudioFailure for what OpenAI reports: an HTTP error status, a refused WebSocket upgrade included (a bad key is a 401, response then HTTP.jl's report of the status); or, inside a session, an error event or a response.done that did not complete, with status nothing and the event's JSON as response, as for a language the session does not translate into.
  • AudioCallError for a session that closed before its result, with the close's status and reason in error and the close as cause, a timeout, a cancel, and a reply without usable audio. Audio received before a failure is never returned.

Each makes one attempt. total_deadline bounds the whole call whatever the socket does, connect_timeout the WebSocket's open, and stream_idle_timeout every send and every wait for the next event. Both observe the ambient CancelToken: a token already cancelled sends nothing, and a cancel ends the call at once with an AudioCallError whose cause is a UniLMCancelled. transcribe is one HTTP request, sent again after a transient status, as a Chat is, the whole file each time (Timeouts & Retries); its results are typed as a platform verb's are (Platform APIs).

UniLM prices none of them: token_usage and estimated_cost throw for a SpeechSuccess and a TranscriptionSuccess. OpenAI bills gpt-transcribe at "$0.0045 / minute", gpt-realtime-translate at "$0.034 / minute", and a speech session at the Realtime model's token rates (pricing). A Chat on an audio model answers in speech too (Audio replies), and every type is in the Audio API reference.

Realtime sessions

realtime_connect(handler; model="gpt-realtime-2.1") opens a WebSocket to OpenAI's Realtime API, wss://api.openai.com/v1/realtime, and runs handler(session) once it is open. Inside the handler, realtime_send sends a client event, a Dict that session_update, input_audio_append, response_create and realtime_event build, and realtime_receive returns the next server event as a Dict. The socket closes when the handler returns, and realtime_connect returns what it returned. Audio travels as base64 PCM inside the events: UniLM covers the WebSocket transport, not WebRTC or SIP, and not GPT-Live's sessions at wss://api.openai.com/v1/live/sessions (WebSockets). A session is not recorded, so its output here is quoted from a live run:

events, reply = String[], IOBuffer()
realtime_connect(config=RequestConfig(connect_timeout=10.0, stream_idle_timeout=30.0)) do session
    realtime_send(session, session_update(Dict("type" => "realtime", "output_modalities" => ["text"],
                                               "instructions" => "Answer in one short sentence.")))
    realtime_send(session, realtime_event("conversation.item.create";
        item=Dict("type" => "message", "role" => "user",
                  "content" => [Dict("type" => "input_text", "text" => "Which is the largest moon of Saturn?")])))
    realtime_send(session, response_create())
    while true
        event = realtime_receive(session)
        push!(events, event["type"])
        event["type"] == "response.output_text.delta" && print(reply, event["delta"])
        event["type"] in ("response.done", "error") && break
    end
    session.model
end
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# "gpt-realtime-2.1"

String(take!(reply))
# "Saturn’s largest moon is Titan."

length(events), events[1], events[2], events[end]
# (21, "session.created", "session.updated", "response.done")

The events and the session's fields are OpenAI's (Realtime client events): session.type "realtime", output_modalities, and the output audio under audio.output. UniLM does not read a session's usage: estimated_cost has nothing to price, and OpenAI bills the session at the model's Realtime rates (pricing). A session is bounded in two phases, and deliberately not in a third:

  • Opening is bounded by connect_timeout. A peer that accepts the TCP connection but never finishes the upgrade throws UniLMTimeout(:connect, …); an open that fails for another reason, such as an upgrade answered with 401, throws that error, even when it fails just before the bound; an upgrade that completes only after the timeout is closed without running the handler.
  • realtime_receive is bounded by the stream_idle_timeout of the config the session took at connect time, and a breach throws UniLMTimeout(:stream_idle, …). A parked socket read cannot be polled out of, so the bound ends the read and the connection, without a close handshake and without HTTP.jl's send lock: the breach surfaces just after the limit on ws://, and on wss:// up to about 5 s later, the time the TLS close may wait to send its close notice, even while a realtime_send on another task is parked on a peer that stopped reading (that send throws too); the session is closed afterwards. On a WebSocket opened over your own stream (HTTP.WebSockets.open(io)), the stream stays yours: the breach ends the read, and a parked send waits until you close the stream. Inf disables the bound.
  • The session's lifetime is not bounded: once the handler runs, how long it stays connected is yours to decide, since a Realtime session is meant to sit idle waiting for input.

Unlike the other verbs, realtime_connect throws rather than returning a typed result, makes a single attempt, which max_attempts does not change, and refuses another service before any I/O (Limits and refusals). A realtime_connect session — its open and realtime_receive — does not observe the CancelToken; speak and translate run Realtime sessions of their own, and those do observe it (Audio).

mint_realtime_secret makes a client secret, POST /v1/realtime/client_secrets: "Client secrets are short-lived tokens that can be passed to a client app, such as a web frontend or mobile client, which grants access to the Realtime API without leaking your main API key" (Create client secret). session is an optional session configuration; UniLM sends no expires_after, so a secret lasts OpenAI's default, "600 seconds (10 minutes)":

secret = mint_realtime_secret()
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# RealtimeSecretSuccess(value="ek_6…[redacted]", raw=<3 keys>)

The verb makes one bounded attempt and returns a RealtimeSecretSuccess, whose value is the secret — shown redacted, so a log or the REPL does not hand it out —, a RealtimeFailure with the status of an error, or a RealtimeCallError, also for a 200 that carries no secret. Every type is in the Realtime API reference.
