Language models · Google Gemini

Google Gemini

Google makes the Gemini models and serves them through two native APIs, both of which GEMINIServiceEndpoint speaks: generateContent, which a Chat reaches through chatrequest! and tool_loop!, and the Interactions API, which respond and the tool_loop that takes an input or a Respond reach. Image generation and speech go through generateContent too. GEMINIOpenAIServiceEndpoint speaks Google's OpenAI-compatible endpoint, which UniLM uses for embeddings. Of Google's other APIs — the Files, Batch, Live and token-counting APIs, explicit context caching, managed agents such as Deep Research, music and video generation — none is available. The verbs of the capabilities the table below lists as not available refuse both endpoints, but one kind: the lifecycle verbs of stored responses read, cancel and delete stored interactions (Background requests). speak reads aloud through Gemini TTS, and transcribe refuses both endpoints (Audio).

Setup

Set your API key in the environment Julia starts from:

export GEMINI_API_KEY="your-gemini-key"

UniLM reads the variable each time a request is sent, and reads no other: not GOOGLE_API_KEY, which Google's own SDKs also read. A call without it returns its call-error result — LLMCallError from chatrequest!, ResponseCallError from respond, and so on — whose cause is the KeyError naming the variable. Both endpoints read the same key. A Chat or a Respond reaches Gemini with service=GEMINIServiceEndpoint, the bare type (GEMINIServiceEndpoint() is the type too), and with no model it takes the default model named at the top of this page. generateContent requests go to https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent, a streamed one to :streamGenerateContent?alt=sse, and Interactions requests to https://generativelanguage.googleapis.com/v1beta/interactions, each with the key in x-goog-api-key.

A Chat sends its max_completion_tokens, else its max_tokens, as maxOutputTokens, and a Chat that sets neither sends none: the model's own output limit applies. The limit counts the thinking with the answer, so a low one can end a turn with finish_reason == "length" before any text (Reasoning).

Google calls the Interactions API "the best way to build with Gemini models and agents" and recommends it "for all new projects", and generateContent legacy, though it "remains fully supported"; "all new models, multimodal capabilities, tools, and agentic features will launch on the Interactions API" (Interactions overview). In UniLM, Chat and its verbs speak generateContent, and respond speaks Interactions: The Interactions API has what differs there. A Chat sent to GEMINIOpenAIServiceEndpoint reaches the same models on the OpenAI-compatible wire, with fewer of the rules on these pages (The OpenAI-compatible endpoint); to code that does not already use a client of that wire, Google recommends that you "call the Gemini API directly" (OpenAI compatibility).

First call

A Chat starts with its system message; chatrequest! sends it and returns a typed result, and text reads the reply — or throws, on a failure:

chat = Chat(service=GEMINIServiceEndpoint)
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "In one sentence: what is a prime number?"))
result = chatrequest!(chat)
text(result)

result.model, result.message.finish_reason

result.model is the model that served the reply, from the reply's modelVersion: Google routes a deprecated id to its successor (Models), which then names itself here — as both routed ids did on 22 October 2026 — and is the model estimated_cost prices. The reply's finishReason becomes finish_reason (Finish reasons and safety).

u = result.usage
(; u.prompt_tokens, u.completion_tokens, u.reasoning_tokens, u.service_tier, cost = estimated_cost(result))

prompt_tokens counts all the input — the cache hits (cached_tokens) and the input a tool read (toolUsePromptTokenCount) included — and completion_tokens all the output, thinking included, of which reasoning_tokens is the thinking. service_tier is the tier that billed the call, and prompt_audio_tokens the input that was audio. How these become a price is in Cost and usage; the result types are on Results.

Conversations

A Chat keeps the conversation: each reply is appended to it, and the next chatrequest! sends the whole conversation again.

chat = Chat(service=GEMINIServiceEndpoint)
push!(chat, Message(Val(:system), "You are a concise assistant: answer in one short sentence."))
push!(chat, Message(Val(:user), "Which planet of the solar system is the largest?"))
text(chatrequest!(chat))

push!(chat, Message(Val(:user), "And the smallest?"))
text(chatrequest!(chat))

[m.role for m in chat.messages], cumulative_cost(chat)

A reply keeps the parts it arrived in, in its message's provider_content, and goes back as those parts, their thought signatures intact:

[collect(keys(part)) for part in chat.messages[3].provider_content.blocks]

Google asks for the signatures back — "passing back thought signatures is mandatory for function calling" — and for each part as it came: "Don't merge a Part containing a signature with one that does not" (function calling). A reply that holds none of Gemini's parts — written by hand, or answered by another provider — goes as its text and one functionCall part per tool call. A reply that holds no part, no text and no function call — a refusal, say, or a turn whose output went to thinking — is left out. What push! refuses is the same on every provider (Conversations with Chat).

Every system message becomes part of the request's systemInstruction, in order, joined with a blank line: one pushed later changes the instructions for the whole conversation, not from where it stands. The results of a reply's tool calls go back as one user turn of functionResponse parts (Tools).

From Gemini 3.6 Flash and 3.5 Flash-Lite on, "If the last non-empty turn in the request is a model turn, the API returns a 400 error" (what's new in Gemini 3.6): a request that ends with an assistant message, a response prefill (a Chat with history=false), is refused on those models before it is sent (Limits and refusals). With history=true, chatrequest! throws InvalidConversationError for such a conversation on every model, since the reply could not be appended.

Models

The listing is the endpoint's models capability: list_models with service=GEMINIServiceEndpoint asks Google's Models API (GET /v1beta/models) which models your key can use, fetches every page of the answer, and returns a ModelListSuccess whose models are ProviderModels. Each holds the model's id (its name without models/) and display_name, its input_token_limit and output_token_limit, the capabilities Google reports — supportedGenerationMethods and whether the model thinks (thinking) — and the entry as sent in raw; the listing carries no dates, so created, deprecated and retires are nothing (Model Listings). An error status on any page is a ModelListFailure; a call that brings no listing — no key, no connection, a timeout, a reply that is not the listing — is a ModelListCallError. list_models throws ArgumentError for GEMINIOpenAIServiceEndpoint: UniLM lists no models through it, though Google's compatible endpoint has a listing of its own, GET /v1beta/openai/models (OpenAI compatibility).

A listing bills no tokens and is not recorded, so its output here is quoted from a live run:

r = list_models(service=GEMINIServiceEndpoint)
r isa ModelListSuccess || error("the listing failed: $r")
chat_models = [m for m in r.models if "generateContent" in get(m.capabilities, "supportedGenerationMethods", [])]

Of the ids that line lists, the aliases bill at the rows of the models that serve them, since a reply names its serving model (on 22 October 2026, gemini-flash-latest answered as gemini-3.8-flash and gemini-pro-latest as gemini-3.1-pro-preview); the image and speech models serve verbs that estimated_cost does not price (Images, speech, embeddings & the compatible endpoint); the others would be estimated at 0.0.

Limits and refusals

A model's input and output token limits are in its list_models entry (Models); UniLM checks a request against neither, nor the size of its media (Attachments), except one rule of the Interactions API below. Rate limits are on When something fails.

A field a Gemini API has no counterpart for is refused, not dropped, since dropping it would send a request other than the one asked for. The one exception is a Chat's parallel_tool_calls, which a Chat with tools sets on its own and which is not sent, whatever its value (Tools). Each request in the table below that the API would answer with an error is refused too. chatrequest!, tool_loop!, respond, tool_loop, generate_image, edit_image, speak and embeddingrequest! throw these ArgumentErrors before anything is sent. A row that names the thinking table holds for the ids of its rows (Reasoning); an id no row names meets only the other rules.

When something fails

chatrequest! and respond return what the service or the network did as a typed result, and do not throw it (Results). An LLMFailure or a ResponseFailure holds an HTTP status and, as response, the body that came with it; an LLMCallError or a ResponseCallError holds, as error, the text of an exception or of an error the reply reported, and the exception as cause when there is one. UniLM sends a request again after a transient status — 408, 429, 500, 502 to 504, 520 to 524 and 529 — as often as the call's RequestConfig allows, and then returns the last answer (Timeouts & Retries); a streamed request is sent again only while none of its callbacks has run. Google sends rate limits as 429: on generateContent a RESOURCE_EXHAUSTED for "one of the API's rate limits (RPM, TPM, RPD, spend, etc.)", which UniLM sends again, and on the Interactions API rate_limit_exceeded and too_many_requests, which it sends again, or quota_exceeded, "your daily quota", which it returns at once (generateContent errors, Interactions errors).
