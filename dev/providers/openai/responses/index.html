Language models · OpenAI

Responses & hosted tools

On OPENAIServiceEndpoint a Respond goes to OpenAI's Responses API, POST /v1/responses, as its own JSON, which writes each field the Respond sets under the API's name. respond(input; kwargs...) builds the Respond from its keywords and sends it, respond(r) sends one built before, and tool_loop runs the function calls of a response until the model answers. Before anything is sent, the request is checked against OpenAI's rules and the model's row in the rule table, and a request that breaks one is refused (Limits and refusals). The verb every provider of an agentic API shares is on Agentic respond.

Respond fieldResponses APIRules
input, instructionsinput: a string, or InputMessages and other input items; instructionsInput
tools, tool_choice, parallel_tool_calls, max_tool_callsthe same fields; tool_choice a string or a tool_choice_… objectTools, Hosted tools
texttext: the output format and verbosityStructured output on Responses
reasoningreasoning: effort, summary, context, modeReasoning
store, background, previous_response_id, conversationthe same fieldsStored responses, Conversations
stream, stream_optionsthe same fieldsStreaming
prompt_cache_options, prompt_cache_key, prompt_cache_retentionthe same fieldsPrompt caching
temperature, top_p, top_logprobs, include, max_output_tokens, truncation, service_tier, metadata, safety_identifier, moderation, context_managementthe same fieldsRequest options
user, seedrefusedLimits and refusals

Input

input is a string, the user's message, or a vector of input items: InputMessages, with the role "user", "assistant", "system" or "developer", and items given as Dicts, such as a tool_result, a configuration_update or an mcp_approval_response. instructions is "A system (or developer) message inserted into the model's context", and with previous_response_id, "the instructions from a previous response will not be carried over" (Create a model response).

An InputMessage's content is a string or a vector of parts: input_text, input_image — an image URL, a base64 data URL, or the file_id of an uploaded file, with a detail level — and input_file — a file URL, a file id, or base64 file_data; input_file(document) makes the part of a DocumentAttachment. An attachment itself is refused in a Responses input, an AudioAttachment among them (Limits and refusals).

An assistant message you replay, rather than chain with previous_response_id, keeps the phase the model gave it, "commentary" for an intermediate update or "final_answer": OpenAI asks callers, for "models like gpt-5.3-codex and beyond", to "preserve and resend phase on all assistant messages — dropping it can degrade performance" (Create a model response, input). output_text leaves a "commentary" message out of the answer. UniLM.encode_agentic shows the body respond sends, with no key and no request:

r = Respond(service=OPENAIServiceEndpoint, instructions="You are a concise assistant.",
    input=[InputMessage(role="user", content=[input_text("What is in this picture?"),
                                              input_image("https://example.com/photo.jpg"; detail="low")]),
           InputMessage(role="assistant", content="I'll describe the picture first.", phase="commentary"),
           InputMessage(role="user", content="Go on.")])
print(UniLM.encode_agentic(r.service, r))

Tools

A function tool is a FunctionTool, made by function_tool(name, description; parameters, strict); it also takes async, allowed_callers, defer_loading and output_schema, each sent when set. A Chat Tool given to Respond becomes the equivalent FunctionTool. OpenAI's guide to its GPT-6 models routes tool calling to this API: "Use Responses for reasoning with tools" (GPT-6 guide), and UniLM checks no effort for tools here. A strict tool's schema follows the rules of Tools on Chat Completions, and a request whose strict schema misses them "will be rejected with details about the missing constraints" (function calling). A tool that sets no strict goes without one, and OpenAI decides: "If you omit strict, the default depends on the API: Responses requests will attempt to normalize your schema into strict mode when possible, and will fall back to non-strict, best-effort function calling if the schema cannot be made compatible with strict mode. When fallback happens, the response tool will show strict: false"; to keep best-effort calling, set strict=false.

function_calls reads a response's calls, each a Dict with its call_id, name and arguments (a JSON string), and tool_result(call_id, name, output) makes the input item that answers one on the next request. tool_loop does both until the model answers in text, chaining the requests with previous_response_id, or with conversation when the Respond sets one:

weather = CallableTool(
    function_tool("get_weather", "The current weather in a city";
        parameters=Dict("type" => "object", "properties" => Dict("city" => Dict("type" => "string")),
                        "required" => ["city"], "additionalProperties" => false), strict=true),
    (name, args) -> "18 °C and sunny in $(args["city"])")
loop = tool_loop("What is the weather in Oslo and in Lima?"; tools=[weather], service=OPENAIServiceEndpoint,
                 instructions="You are a concise assistant.")
output_text(loop.response)

[(oc.tool_name, oc.arguments) for oc in loop.tool_calls], loop.turns_used

The Respond sets no parallel_tool_calls, and the model asked for both cities in one response; a Chat with tools sends false and gets a turn per call (Tools on Chat Completions).

tool_choice is "auto", "none" or "required", or an object a builder makes: tool_choice_function(name), tool_choice_hosted(type), tool_choice_mcp(label; name), tool_choice_custom(name) or tool_choice_allowed(mode, tools). parallel_tool_calls, "Whether to allow the model to run tool calls in parallel", is sent only when set, and left to the API's default otherwise. The loop runs a response's calls only when its status is completed or requires_action, and stops, with completed=false, on a call the application must carry out itself (computer_call, apply_patch_call, custom_tool_call, a shell_call that OpenAI did not run, or an mcp_approval_request); the loop every provider shares is on Tool Calling.

Hosted tools

The other tools of a Respond are OpenAI's built-in tools: most run on OpenAI's side, and their results come back in the response's output items; the last row's are calls the application carries out:

ToolMade byIts results
web searchweb_search(; context_size, location, filters)the answer's url_citations; web_search_results
file searchfile_search(vector_store_ids; max_results, ranking, filters)file_search_results; the stores on Retrieval & file search
code interpretercode_interpreter()code_interpreter_outputs; its settings on Platform APIs
image generationimage_generation_tool(; size, quality, action, …)the images as base64, image_generation_results
remote MCP serversmcp_tool(label, url; require_approval, allowed_tools, …)mcp_call_outputs; mcp_approval_requests
computer use, shell, patches, custom toolscomputer_tool, shell, apply_patch_tool, custom_toolcalls the application carries out; a shell call only when OpenAI did not run it
result = respond("What is the latest stable release of the Julia programming language? " *
                 "Answer in one plain-text sentence."; service=OPENAIServiceEndpoint, tools=[web_search()])
output_text(result)

[c["url"] for c in url_citations(result)]

mcp_tool sends require_approval="never" unless it is given another value, while OpenAI's own default is to "request your approval before any data is shared with a connector or remote MCP server"; with approvals, a request for one is an mcp_approval_request item, and an mcp_approval_response in the next request's input answers it (MCP servers). The hosted tools bill beyond the tokens — web search per call, containers per session — which estimated_cost does not include (Cost and usage).

Structured output on Responses

text holds the output format: json_schema_format(name, description, schema; strict) for a reply that follows a JSON Schema, json_object_format() for any JSON object, and text_format(; verbosity) for plain text, each a TextConfig whose verbosity is "low", "medium" or "high". A strict schema follows the rules of Structured output.

using JSON
fmt = json_schema_format("planets", "The planets of the solar system in order",
    Dict("type" => "object",
         "properties" => Dict("planets" => Dict("type" => "array", "items" => Dict("type" => "string"))),
         "required" => ["planets"], "additionalProperties" => false); strict=true)
result = respond("List the planets of the solar system in order."; service=OPENAIServiceEndpoint, text=fmt)
JSON.parse(output_text(result))["planets"]

Stored responses

A response is stored unless its request sets store=false, "for at least 30 days" (Create a model response), and get_response, cancel_response, delete_response and list_input_items work on it by its id. get_response and cancel_response return a ResponseSuccess, or a ResponseFailure for a response whose status is "failed", as respond does; delete_response, list_input_items, compact_response and count_input_tokens return OpenAI's answer as a Dict; a failure of any of them is a ResponseFailure or a ResponseCallError. Each makes one attempt, never retried (When something fails).

r = respond("Say 'stored response test' and nothing else.", store=true, model="gpt-5.4-mini")
if r isa ResponseSuccess
    rid = r.response.id
    println("Stored response ID: ", rid)

    # Retrieve
    retrieved = get_response(rid)
    if retrieved isa ResponseSuccess
        println("Retrieved text: ", output_text(retrieved))
    end

    # List input items
    items = list_input_items(rid)
    if items isa Dict
        println("Input items: ", length(items["data"]))
    end

    # Delete
    del = delete_response(rid)
    if del isa Dict
        println("Deleted: ", del["deleted"])
    end
else
    println("Request failed — ", r)
end

count_input_tokens asks how many input tokens a request would use, "the exact count the model will receive", without generating (counting tokens); with no model it counts for the default model named at the top of the start page:

result = count_input_tokens(input="Tell me a joke about programming")
if result isa Dict
    println("Input tokens: ", result["input_tokens"])
else
    println("Request failed — see result for details")
end

tool = function_tool("search", "Search for information",
    parameters=Dict("type" => "object", "properties" => Dict(
        "query" => Dict("type" => "string")
    ), "required" => ["query"], "additionalProperties" => false),
    strict=true
)
result = count_input_tokens(
    input="Search for Julia language news",
    instructions="You are a helpful assistant.",
    tools=[tool]
)
if result isa Dict
    println("Tokens with tools: ", result["input_tokens"])
else
    println("Request failed — see result for details")
end

compact_response runs a compaction pass over a conversation's items, POST /v1/responses/compact: the window it returns "includes an encrypted compaction item" that is "opaque", to be passed on as the next request's input without pruning (compaction):

items = [
    Dict("role" => "user", "content" => "Hello, I want to learn about Julia."),
    Dict("type" => "message", "role" => "assistant", "status" => "completed",
         "content" => [Dict("type" => "output_text",
            "text" => "Julia is a high-performance programming language for technical computing.")])
]
result = compact_response(input=items, model="gpt-5.4-mini")
if result isa Dict
    println("Compact succeeded")
    println("Output items: ", length(result["output"]))
    println("Usage: ", result["usage"])
else
    println("Request failed — see result for details")
end

With background=true, respond returns as soon as OpenAI has queued the response, and cancel_response stops it:

started = respond("Write a long essay on the history of numerical computing."; service=OPENAIServiceEndpoint,
                  background=true)
response_status(started)

response_status(cancel_response(started.response.id))

A background response is read back with get_response until it leaves the queued and in-progress states, "Keep polling while the request is in the queued or in_progress state" (background mode):

r = get_response(started.response.id)
while response_status(r) in ("queued", "in_progress")
    sleep(2)
    r = get_response(started.response.id)
end

Request options

  • service_tier. "auto", "default", "flex", "scale", "fast" or its former name "priority", and "ultrafast" on the models whose Ultrafast tier cell in the rule table is "yes": "Ultrafast mode is the fastest service tier in the OpenAI API" (Ultrafast mode). The tier OpenAI reports is token_usage(result).service_tier, which Cost and usage prices.
  • max_output_tokens, truncation. max_output_tokens bounds the visible output and the reasoning together. With truncation="auto", an input over the context window loses items from the beginning of the conversation; with "disabled", the API's default, the request "will fail with a 400 error".
  • include. Extra output data, such as "web_search_call.action.sources", "file_search_call.results" or "message.output_text.logprobs", the last at the efforts the model's row takes log probabilities.
  • max_tool_calls. "The maximum number of total calls to built-in tools that can be processed in a response".
  • metadata, safety_identifier, prompt_cache_key. Sent as given; metadata holds up to 16 key-value pairs, and user, which OpenAI replaces with the other two, is refused (Limits and refusals).
  • moderation. A ModerationConfig runs a moderation model over the input and the output; the response's moderation holds the results, in result.response.raw["moderation"]. Text and images on their own are classified by moderate (Moderation).
  • context_management, stream_options. Sent as given: compaction settings, and the stream's include_obfuscation.

The quoted fields are from OpenAI's Create a model response and Retrieve a model response. refusals and reasoning_items read a response's output items as the hosted tools' accessors do, and incomplete_details and usage_details its incomplete_details and usage. UniLM.encode_agentic shows the body:

r = Respond(service=OPENAIServiceEndpoint, input="Count to five.", service_tier="flex", max_output_tokens=200,
            truncation="auto", metadata=Dict("ticket" => "T-1042"), safety_identifier="user-42",
            moderation=ModerationConfig(model="omni-moderation-latest", input_mode="block"))
print(UniLM.encode_agentic(r.service, r))
