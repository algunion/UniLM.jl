Embeddings API

Types and functions for the Embeddings API.

Embeddings Object

UniLM.EmbeddingsType#
Embeddings(input::Union{AbstractString,EmbeddingInput,Attachment}; service=OPENAIServiceEndpoint,
           model="", dimensions=nothing, encoding_format=nothing, user=nothing, task=nothing)
Embeddings(input::AbstractVector; service=OPENAIServiceEndpoint, model="", dimensions=nothing,
           encoding_format=nothing, user=nothing, task=nothing)

Create an embedding request for one or more texts. model="" resolves to the service's default embedding model — OpenAI's text-embedding-3-small (1536 dimensions), gemini-embedding-2 for GEMINIOpenAIServiceEndpoint —, and any other service needs an explicit model (ArgumentError otherwise). DeepSeek and Azure do not serve embeddings through UniLM: embeddingrequest! refuses them with an ArgumentError before any I/O, whatever the model, as it refuses every endpoint whose declared capabilities lack :embeddings. Embeddings work with OpenAI, GEMINIOpenAIServiceEndpoint, Ollama, GenericOpenAIEndpoint (Mistral included) and custom endpoints that declare :embeddings or no capabilities.

An input is a text, an EmbeddingInput, or an ImageAttachment or AudioAttachment on its own; a vector of them embeds each item as a vector of its own. A DocumentAttachment, or an image with a detail level, is an ArgumentError, as in an EmbeddingInput. A vector of strings is copied into a Vector{String} and sent as is, an empty string included. In a vector holding any other item, every item becomes an EmbeddingInput, so an empty string there is refused (ArgumentError: an item needs a non-empty text, an image or a sound clip).

The embeddings field is pre-allocated (something(dimensions, 1536) zeros per input), filled in place by embeddingrequest!, and resized to the length the model returns. The result aliases this struct, so use one Embeddings per concurrent call.

Fields

  • service::ServiceEndpointSpec: LLM provider (default: OPENAIServiceEndpoint).
  • model::String: The embedding model name.
  • input::Union{String,Vector{String},EmbeddingInput,Vector{EmbeddingInput}}: Text(s) or item(s) to embed.
  • embeddings::Union{Vector{Float64},Vector{Vector{Float64}}}: Pre-allocated embedding vector(s).
  • user::Union{String,Nothing}: Optional end-user identifier.
  • dimensions::Union{Int,Nothing}: Requested vector size, where the model supports it; a value that is not positive throws ArgumentError. On Mistral's host (MistralEndpoint) it goes out as output_dimension, Mistral's name for it.
  • encoding_format::Union{String,Nothing}: "float" or unset; any other format (e.g. "base64") throws ArgumentError, since the result stores Float64 vectors.
  • task::Union{Symbol,Nothing}: What the texts are for, as a task prompt (see below); nothing for none.

Task prompts (EmbeddingGemma, Gemini Embedding 2)

EmbeddingGemma models (embeddinggemma, embeddinggemma-2, on any service) and gemini-embedding-2 read a short prompt that says what a text is for, and neither Ollama nor the OpenAI-compatible request adds it: pass task and UniLM writes the model card's prompt in front of each text — :search_query, :question_answering, :fact_checking, :code_retrieval (the query side), :document (the corpus side, with each item's title), :classification, :clustering, :sentence_similarity — or task = :none to send the text as is. Without a task an EmbeddingGemma request is an ArgumentError; gemini-embedding-2 takes none, its text then sent as is (Google's embeddings guide recommends the prompts for text); any other model takes task = :none or none. EmbeddingGemma's dimensions are 768 (default), 512, 256 or 128. Through an OllamaEndpoint, an EmbeddingGemma 2 request carries the model's trained 8,192-token window (num_ctx and num_batch) unless the endpoint sets either (EmbeddingGemma v1 reads 2,048 tokens); with truncate=false, the default, a longer input is an EmbeddingFailure, never a vector of part of it (measured on Ollama 0.40.6 with 740m-q8_0, 740m-mxfp8, 270m-q8_0-text and v1).

Example

emb = Embeddings("Julia is a great language")
embeddingrequest!(emb)
emb.embeddings  # => Float64[...] (1536 dims)

# With Ollama
emb = Embeddings("test"; service=OllamaEndpoint(), model="nomic-embed-text")
UniLM.EmbeddingInputType#
EmbeddingInput(text; title=nothing)
EmbeddingInput(image::ImageAttachment)
EmbeddingInput(audio::AudioAttachment)
EmbeddingInput(text, media...)
EmbeddingInput(; text=nothing, title=nothing, image=nothing, audio=nothing)

One item for Embeddings, embedded as one vector: a text, an image, a sound clip, or a text with an image or a sound clip — one of them per item on an OllamaEndpoint, which refuses an item holding both before any request; a service that embeds text only refuses media. title names the document a text comes from; it is used by the :document task of models with task prompts (EmbeddingGemma, gemini-embedding-2) and refused with any other task or model. Images and audio go only to an OllamaEndpoint (Ollama's /api/embed takes them for models that see or hear, such as embeddinggemma-2:740m-q8_0, which embedded a text with its picture or clip as one item on Ollama 0.40.6). Ollama passes an item's image and clip to the model in a random order, which is why an item holding both is refused (on Ollama 0.40.6, ten requests of one such item to embeddinggemma-2:740m-q8_0 gave two different vectors): send the image and the audio as separate items. Two items are == when their texts, titles and media are. An empty text beside an image or clip is no text: the item holds the media alone (text === nothing), sent with no task prompt. An empty or whitespace-only title is no title (title === nothing): with task = :document the text is sent as "title: none | text: …", the model card's prompt for a document without one.

Throws ArgumentError for an item with nothing to embed (no image or clip, and no text or an empty one), a title without a non-empty text, more than one image or clip, an image with a detail level, or an attachment of any other kind, such as a DocumentAttachment: no embedding endpoint UniLM sends to takes a level or a document (OpenAI's and its compatibles take text, Ollama's /api/embed an image's or a clip's bytes alone).

EmbeddingInput("Refunds take 5 days."; title = "Refund policy")
EmbeddingInput("a red circle", ImageAttachment("red_circle.png"))

Construction 

using UniLM

# Single input
emb = Embeddings("Julia is a great language")
println("Model: ", emb.model)
println("Embedding dims: ", length(emb.embeddings))

# Batch input
batch = Embeddings(["Hello", "World", "Julia"])
println("Batch size: ", length(batch.input))
println("Each embedding dims: ", length(batch.embeddings[1]))

Request Function

UniLM.embeddingrequest!Function#
embeddingrequest!(emb::Embeddings; config=nothing, cancel=nothing) -> LLMRequestResponse

Send an Embeddings API request for the input in emb. Returns EmbeddingSuccess, EmbeddingFailure (non-2xx), or EmbeddingCallError (network/parse/timeout). The resulting vectors are filled into emb.embeddings in place and are also reachable via embedding_vectors(result).

Transient statuses (408/429/500/502–504/520–524/529) are retried with backoff and jitter under the resolved RequestConfig (config === nothing resolves the ambient configuration). Timeouts surface as EmbeddingCallError with status = nothing and the UniLMTimeout in cause. Inside a with_recorded_answers scope the request passes through the recordings, and one the scope cannot replay throws ReplayMissError instead of returning an EmbeddingCallError.

cancel::Union{Nothing,CancelToken} (nothing: the ambient token of with_cancel): a cancel ends the call with EmbeddingCallError(status=nothing, cause=UniLMCancelled(:token, …)), never retried; a pre-cancelled token sends nothing. A TCP connect or TLS handshake already in progress finishes (or reaches connect_timeout) before the cancel takes effect.

Throws ArgumentError before any network I/O when emb.service is an endpoint type that declares its capabilities and does not list :embeddings.

Result Types

UniLM.EmbeddingSuccessType#
EmbeddingSuccess(; embeddings, usage=nothing, raw)

Successful Embeddings API response. Vectors are in embeddings.embeddings (also filled in place on the request struct); embedding_vectors(r) returns them.

UniLM.EmbeddingFailureType#
EmbeddingFailure(; response, status)

HTTP-level failure from the Embeddings API (non-2xx).

UniLM.EmbeddingCallErrorType#
EmbeddingCallError(; error, status=nothing, cause=nothing)

Exception-level error during an Embeddings API call (network, parse, timeout, etc.). cause holds the underlying typed exception when one exists (e.g. a UniLMTimeout); status stays nothing for timeouts — no fabricated HTTP statuses.

UniLM.embedding_vectorsFunction#
embedding_vectors(r::EmbeddingSuccess)

Return the embedding vector(s): Vector{Float64} (single input) or Vector{Vector{Float64}} (batch). On an EmbeddingFailure or EmbeddingCallError it throws an LLMResultError; guard with issuccess.
