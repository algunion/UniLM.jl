Language models · OpenAI

Models & request rules

Models

A request names its model with model, and UniLM sends any id as given; without one, a Chat or a Respond takes the default model named at the top of the start page. The models UniLM holds request rules for are the rows of the rule table, and the models it prices are the rows of the price table. A model id takes the row of the same id, or of that id without a -YYYY-MM-DD snapshot suffix, never the row of an id it merely starts with: a request on a model no row names gets none of the per-model checks, and OpenAI's answer is the check; a result from a model with no price row is estimated at 0.0, with a warning.

list_models with service=OPENAIServiceEndpoint asks OpenAI's Models API (GET /v1/models) which models your key can use, and returns a ModelListSuccess whose models are ProviderModels. OpenAI lists each model's id, its creation time, as created, its owner and its shutdown_date, "the date when the model will shut down, or null if not announced" (List models); UniLM reads the shutdown date as retires, keeps the entry as sent in raw, and has no token limits or capabilities to fill in for OpenAI (Model Listings). An error status is a ModelListFailure, and a call that brings no listing — no key, which it names, no connection, a timeout, a reply that is not the listing — a ModelListCallError. A listing bills no tokens and is not recorded, so its output here is quoted from a live run:

r = list_models(service=OPENAIServiceEndpoint)
r isa ModelListSuccess || error("the listing failed: $r")
ids = sort!([m.id for m in r.models if startswith(m.id, "gpt-6") || startswith(m.id, "gpt-5.6")])
priced(id) = haskey(DEFAULT_PRICING, id) || haskey(DEFAULT_PRICING, replace(id, r"-\d{4}-\d{2}-\d{2}$" => ""))
ids, filter(!priced, ids)
# Listed on 25 October 2026 with UniLM's development branch after 0.26.0 (133 models in all):
# (["gpt-5.6-luna", "gpt-5.6-sol", "gpt-5.6-terra", "gpt-6-astra", "gpt-6-luna", "gpt-6-sol", "gpt-6.1-sol"], String[])

m = r.models[findfirst(m -> m.id == "gpt-6-sol", r.models)]
m.id, m.created, m.retires, m.raw["owned_by"]
# ("gpt-6-sol", DateTime("2026-09-14T17:12:17"), nothing, "system")

The listing also names models whose shutdown date has passed. Before you use a newly listed model, check that it has a price row, as the lookup above does, and whether it needs request rules UniLM does not hold yet: OpenAI's model pages give each model's reasoning efforts and the APIs it serves.

Reasoning

reasoning_effort on a Chat and reasoning=Reasoning(effort=…) on a Respond set how much a reasoning model reasons before it answers. UniLM takes the efforts "none", "minimal", "low", "medium", "high", "xhigh" and "max", and checks the request against the model's row of the table below when it is encoded, before anything is sent (Limits and refusals):

The columns:

  • Efforts on Responses and Efforts on Chat Completions: the efforts each API takes for the model. Another is refused, and the message names the next effort up that the row lists, or Respond where only the Responses API takes it. OpenAI's reference for Chat Completions lists "max" among the efforts, but the API answered "max" with HTTP 400 when these rows were written, on 22 October 2026, and again on the default model on 25 October 2026, so their Chat Completions cells end at "xhigh".
  • Sampling and log probabilities at: the efforts at which UniLM sends temperature, top_p and log probabilities, refusing them at the others; "—": at none. OpenAI's GPT-6 guide: "When reasoning effort is not none, remove temperature, top_p, and top_logprobs. For Chat Completions, also remove logprobs. For Responses, remove message.output_text.logprobs from include" (GPT-6 guide). The GPT-5.6 pages state no such rule, but OpenAI states it for the GPT-5 models before them: temperature, top_p and logprobs are "only supported" at effort none, and "Requests that include these fields will raise an error for GPT-5.4 or GPT-5.2 with any other reasoning effort setting, or for older GPT-5 models" (GPT-5.4 guide; the GPT-5.2 guide says the same). The GPT-5.6 cells follow it, and the API: on 25 October 2026 it refused temperature on one of them at an effort other than "none" and took it at "none" (the evidence below).
  • Chat Completions tools at: the efforts at which a Chat may carry tools; "—": the model takes tools only on the Responses API (Tools on Chat Completions).
  • Ultrafast tier: whether a Respond may ask for service_tier="ultrafast" (Request options).
  • prompt_cache_retention: whether a Chat or a Respond may set it (Prompt caching).
  • Default effort: the effort UniLM checks a request that sets none at (Setup), meant as the one OpenAI runs it at. OpenAI's reasoning guide: "If you omit reasoning.effort, GPT-5.6 defaults to medium", and "GPT-6.1 Sol, GPT-6 Sol, and GPT-6 Luna also default to medium reasoning effort" (reasoning); its pages name no default for GPT-6 Astra, whose response to a request that set none reported reasoning.effort "medium" on 25 October 2026 (the evidence below).
Evidence

Live requests of 25 October 2026, sent as raw HTTP. gpt-6-astra on the Responses API with no reasoning and max_output_tokens=16: HTTP 200, the response's reasoning was {"context": "all_turns", "effort": "medium", "mode": "standard", "summary": null}. gpt-5.6-luna with temperature=0.5: at reasoning_effort="low", HTTP 400 on Chat Completions, "Unsupported value: 'temperature' does not support 0.5 with this model. Only the default (1) value is supported."; with reasoning={"effort": "low"}, HTTP 400 on the Responses API, "Unsupported parameter: 'temperature' is not supported with this model."; at reasoning_effort="none", HTTP 200 on Chat Completions.

Reasoning configures the reasoning of whatever model a Respond names: UniLM checks its effort per model only for the rows above, and sends it unchecked for a model no row names, OpenAI's answer being the check. On the Responses API a summary of the reasoning comes back when the request asks for one, as the summary array of the response's reasoning items (reasoning summaries), and reasoning_summaries reads it:

result = respond("How many integers from 1 to 1000 are divisible by 3 or by 5 but not by 7? " *
                 "Answer with the number only."; service=OPENAIServiceEndpoint,
                 reasoning=Reasoning(effort="high", summary="auto"))
output_text(result)

foreach(println, reasoning_summaries(result))

u = token_usage(result)
(; u.completion_tokens, u.reasoning_tokens)

Reasoning tokens "are billed as output tokens" (reasoning): completion_tokens counts them, reasoning_tokens is their part, and estimated_cost prices them at the output rate. Chat Completions returns no reasoning text, so reasoning_text of a Chat result is nothing. A request's output cap — max_completion_tokens on a Chat, max_output_tokens on a Respond — bounds the reasoning and the visible output together: a reply that reaches it ends with finish_reason == "length", or a response with status "incomplete", possibly before any visible text.

Reasoning also takes OpenAI's persisted reasoning, context ("auto", "current_turn" or "all_turns"), and its execution mode, mode ("standard" or "pro"), and a Respond input may hold a configuration_update item, which changes the effort of later responses without rewriting the request-level effort, so the cached prompt prefix stays reusable; OpenAI supports it on "the GPT-6 model family in standard, single-agent mode" (change reasoning mid-conversation).

Prompt caching

OpenAI caches prompt prefixes by itself. On GPT-5.6 and later, prompt_cache_options chooses how: a PromptCacheOptions with a mode, "implicit" (the API's default: OpenAI places a breakpoint at the end of the latest eligible message) or "explicit" (only the breakpoints you mark), and a ttl, the minimum lifetime of what a request writes. A prefix "must meet the model's minimum cacheable token length", 1,024 tokens on GPT-5.6 and later (prompt caching). The two APIs take different options:

  • Chat Completions takes mode and ttl="30m"; another ttl, prewarm and comparison_response_id are refused (Limits and refusals). A Chat marks no breakpoint, so with mode="explicit" its request "does not use prompt caching" (Create chat completion, prompt_cache_options).
  • Responses takes ttl="30m" or "12h"; input_text(text; cache_breakpoint=true) marks a breakpoint at the end of that block, with its own cache_ttl if given; prewarm=true "Prepares the prompt cache without generating output"; and comparison_response_id asks for diagnostics against an earlier response, which come back in result.response.raw["prompt_cache_diagnostics"] (Create a model response, prompt_cache_options).

prompt_cache_key, on both APIs, is the key OpenAI uses "to cache responses for similar requests to optimize your cache hit rates". The deprecated prompt_cache_retention of a Chat or a Respond is refused on the models whose prompt_cache_retention cell in the rule table is "—", whose cache lifetime prompt_cache_options sets, and sent as given on the others. Here a generated parts list is the system prompt of a conversation, and each turn asks about one part:

parts = join(("Part $(2000 + i): $(3 + i % 7) mm washer, $(11i % 60) in stock." for i in 1:120), "\n")
chat = Chat(service=OPENAIServiceEndpoint, prompt_cache_options=PromptCacheOptions(),
            prompt_cache_key="parts-list")
push!(chat, Message(Val(:system), "Answer questions about this parts list in one short sentence.\n\n" * parts))
push!(chat, Message(Val(:user), "How many of part 2042 are in stock?"))
result = chatrequest!(chat)
text(result)

u = result.usage
(; u.prompt_tokens, u.cache_write_tokens, u.cached_tokens, cost = round(estimated_cost(result); digits=6))

push!(chat, Message(Val(:user), "And part 2077?"))
result = chatrequest!(chat)
u = result.usage
(; text = text(result), u.prompt_tokens, u.cache_write_tokens, u.cached_tokens,
   cost = round(estimated_cost(result); digits=6))

The first request wrote the system prompt and its question to the cache. The second read them back and wrote only what the conversation had added, the reply and the next question. The usage counts the cache reads as cached_tokens and the writes as cache_write_tokens, of which cache_write_extended_tokens are the writes kept for 12 hours, which only the Responses API reports; what each costs is on Cost and usage. A Respond that marks its own breakpoints sends them in its input; UniLM.encode_agentic shows the body respond sends, with no key and no request:

r = Respond(service=OPENAIServiceEndpoint,
    input=[InputMessage(role="developer",
                        content=[input_text("You answer questions about our parts catalogue."; cache_breakpoint=true,
                                            cache_ttl="12h")]),
           InputMessage(role="user", content="How many washers are in stock?")],
    prompt_cache_options=PromptCacheOptions(mode="explicit", ttl="30m"))
print(UniLM.encode_agentic(r.service, r))

Cost and usage

estimated_cost prices a result with the row of the price table below for the model that served it — result.model of a Chat result, result.response.model of a Respond result — and an id with a -YYYY-MM-DD snapshot suffix with the row of the id without it; cumulative_cost adds up the calls of a Chat. Of the usage, it bills the uncached input at the input rate, the cache reads at the cached-input rate, the cache writes at the multiples of the Cache writes column of the table just below, and all the output, the reasoning included, at the output rate. Every rate is then multiplied by the factors that apply:

  • the billed tier's multiple, for the tier the result reports as its service_tier: "flex", "fast" or "priority" (Fast mode's former name, which OpenAI reports for Fast on GPT-5.6 and earlier), and "ultrafast";
  • for a prompt over the short-context limit, the long-context multiples, on the whole request.

A "—" in the table is a price OpenAI's pricing page does not give: a write then bills at the input rate, any prompt at the row's rates, and a tier at the standard rates, with one warning per model and tier. OpenAI bills a request that Fast mode downgraded at standard rates and reports it as service_tier: "default" (Fast mode), and the estimate follows the reported tier.

Limits and refusals

A request's output stops at its cap — max_completion_tokens on a Chat, max_output_tokens on a Respond — which counts the reasoning too (Reasoning), and a model's context window and largest output are on its OpenAI model page. UniLM checks a request against neither, and leaves the size of images and files to the API. Rate limits are on When something fails.

chatrequest!, respond, the tool loops and embeddingrequest! throw these ArgumentErrors before anything is sent, and so do the constructors of the request's parts where the row names one. A rule that names a column of the rule table holds for the ids of its rows, and an id no row names meets only the other rules.
