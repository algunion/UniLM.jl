Decisions · Jev (TypeSafe)

Jev (TypeSafe)

Jev is TypeSafe's System One model: it reads a state — a text or a JSON record — and answers the questions you list about it with a probability for each answer you allowed (a box's edges, for a Box question), writing no text, and TypeSafe bills only the input tokens it reads. TYPESAFEServiceEndpoint speaks TypeSafe's API, POST /v1/systemone for decisions and GET /v1/models for the model listing, and UniLM wraps both. The endpoint serves these two alone: the verb of every capability the table below does not list, chatrequest! and respond among them, refuses it before sending anything.

Setup

Get an API key from the TypeSafe console and set it in the environment Julia starts from:

export TYPESAFE_API_KEY="..."
VariableWhen unsetMeaning
TYPESAFE_API_KEYa call sends nothing and returns a SystemOneCallError whose error reads TYPESAFE_API_KEY is not setthe key, sent as Authorization: Bearer …
TYPESAFE_BASE_URLhttps://api.typesafe.aithe API root: a proxy or a gateway in front of TypeSafe, or a server of your own in tests (Testing and recordings)
TYPESAFE_DEFAULT_MODELthe default model at the top of this pagethe model of a call that names none (Models)

UniLM reads the three when each request is sent, so a value exported after using UniLM takes effect, and a blank value counts as unset. A call goes to Jev when it names no service and no with_system_one scope around it names another provider; service = TYPESAFEServiceEndpoint names Jev explicitly, and TYPESAFEServiceEndpoint() returns that same type. A call's model is its own model = …; else, when it names no service, the model of the scope around it; else TYPESAFE_DEFAULT_MODEL, and the default model at the top of this page when that is unset. The endpoint has no options of its own, and its one request option, long_context, has a section of its own (Long context).

First decision

One request carries the state once and every question about it; each answer comes back under the name you gave its question:

const TEAM = (billing   = "payments, charges, invoices or refunds",
              technical = "the app or the website does not work as expected",
              shipping  = "a parcel that is late, lost or arrived damaged",
              other     = "anything else")
message = "I was charged twice for order #4471. Please refund the duplicate payment."

r = ask(message, "team" => choice("Which team should handle this message?", TEAM))
a = r["team"]
(a.choice, a.probabilities[a.choice], a.confidence)

a.choice is the most probable option, a.probabilities holds one probability per option, and a.confidence says how peaked they are (Confidence and tuning). A failed call has no answers: r["team"] throws a SystemOneError on it, so a decision is never read from a call that did not happen (When something fails).

r.response.model, token_usage(r).prompt_tokens

The call named no model, so it was sent with the default model at the top of this page, an alias, and r.response.model is the versioned id that answered (Models). nl_classify makes the same kind of decision in one call and returns the key whose description fits (Dispatch on Meaning):

nl_classify(message, TEAM)

Models

TypeSafe serves Jev under aliases and versioned ids, and a call sends either as its model (Models):

  • jev-latest, the most recent stable release, and jev-preview, the most recent release of any kind, are aliases. An alias moves when a new release ships, so its answers can change with no change to your code. On 25 October 2026 TypeSafe's Models page points both at jev-1.14.0 (Jev 1.14, available from 14 October 2026) and says no preview build is available.
  • A versioned id, jev-1.14.0 or jev-1.13.0, names one release. The service accepts it whether or not the listing shows it. Both releases take pictures and Box questions need Jev 1.14, by TypeSafe's Images page, though its Models and System One pages still list text input only; both take long context.

list_models returns the names the account may send, each with a description and a release date; TypeSafe's listing holds the aliases:

m = list_models()
[(card.name, card.release_date) for card in m.models]

release_date is the string the service sends, an RFC 3339 timestamp, where TypeSafe's API reference documents YYYY-MM-DD (List models); UniLM does not parse it. A live listing on 25 October 2026 returned these two cards unchanged.

r.response.model names the versioned id that answered, which TypeSafe's response reports in place of the alias (System One): log it, since an alias that moves is otherwise invisible. A threshold tuned against one version is a claim about that version, so once you have tuned one, pin the version — model = … on the call, TYPESAFE_DEFAULT_MODEL in the environment, or the model of a with_system_one scope — and move the pin on your own schedule:

pinned = ask(message, "team" => choice("Which team should handle this message?", TEAM); model = "jev-1.13.0")
pinned.response.model

TypeSafe publishes the failure modes it knows of Jev 1.13 (Jev 1.13 jaggedness); on 25 October 2026 its documentation index lists no such page for Jev 1.14. Jev 1.13 reads a question literally, does not count, compute or compare dates reliably, loses accuracy as unrelated material grows around the decision, and is not trained to generate text. Nor does it treat its state as hostile by default: text written to steer it, such as an injected instruction, can move its answer. Compute in Julia, send only what the decision needs, and leave text to a language model; Designing good questions turns these into rules for writing questions.

Questions

Jev answers four kinds of question, in any mix in one request: a choice picks one option of a set, a score places the state on levels you describe, lowest first, a noul gives the probability that a statement holds, and a box locates something in a picture (Locate with Box). A RawQuestion goes out as you wrote it, for a kind UniLM does not model. Each question is evaluated against the same state on its own: one answer is never context for another (Primitives).

r = ask("The app crashes every time I open my order history. Third time this week, and my parcel is due today!",
        "team"    => choice("Which team should handle this message?", TEAM),
        "urgency" => score("How urgent is this message?",
                           ["Can wait", "Needs attention this week", "Needs attention today"]),
        "repeat"  => noul("Has the customer had this problem before?"))
(r["team"].choice, r["urgency"].score, r["repeat"].noul)

What reaches the model:

  • Question names do not. On Jev, the names ("team", "urgency", "repeat") only key the answers: TypeSafe does not show them to the model, so write the whole question in its instructions (Primitives).
  • Option names do. A Choice's option names and their descriptions both reach the model (Choice), so a short name can pull an answer toward it; Choice, Score, Noul shows when to send the descriptions themselves as the names.
  • Guidance may be structured. Instructions, an option's description, a Score level and a Noul's yes and no may each be a string, an object or an array, and may hold a picture (Structured guidance).

A Choice takes up to 255 options and a Score up to 10 levels, and TypeSafe advises at least two levels (Score); a question over either limit is refused before the request is sent (Limits and refusals). Jev judges each Score level on its own against the state, without its number or its neighbours, so a level such as "worse than the previous level" gives it nothing to match (Score). A request may hold any number of questions as long as it fits the context. Reading the answers and the decision rules on them are on Route and Decide.

Like every decision provider, the endpoint also refuses, before anything is sent, a blank or repeated question name, criteria that are not valid, a state or guidance holding NaN or Inf (TypeSafe's request rules read "Finite numbers only. NaN, Infinity, and numbers too large to represent, such as 1e400, are rejected", Request rules and errors), and an AudioAttachment or a DocumentAttachment anywhere in the request; Reading answers covers a malformed request on every provider.

try
    ask(message, "pick" => choice("Pick one.", ["option $i" for i in 1:256]))
catch err
    println(sprint(showerror, err))
end
