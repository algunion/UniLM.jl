Capabilities by provider

Each endpoint declares what it serves as a set of capability symbols — :chat, :tools, :embeddings and so on —, and a verb checks the endpoint's set before anything is sent: on an endpoint whose declared set lacks the capability the verb needs, it throws ArgumentError, naming the feature and the endpoint and listing what the endpoint supports (Provider Capabilities says which verbs check which symbol). Read the table below to see what a provider serves before you choose it, or before you move code to it.

service, model = OPENAIServiceEndpoint, "gpt-5.4-mini"

The examples use only the names bound above. service and model are the provider and model they run on: bind your own there. The table at the end links each provider's start page.

Check a provider in code

has_capability answers for one symbol, and provider_capabilities gives the endpoint's whole set:

has_capability(service, :tools), has_capability(service, :fim)

join(sort!(collect(provider_capabilities(service))), ", ")

An endpoint of your own declares a set by adding a method to provider_capabilities; one that declares none is not checked by chatrequest!, respond, embeddingrequest! and the image verbs, and the other verbs refuse it (Write your own backend).
