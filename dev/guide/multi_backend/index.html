Language models · Across providers

One API across providers

UniLM reaches every language-model provider through one set of types and verbs. The provider is one argument: service names its endpoint and model its model, so code written for one provider runs on another once those two change. This page says what every provider shares, how to switch, and where the providers differ; each provider's own rules are on its entry, which the table at the end links.

service, model = OPENAIServiceEndpoint, "gpt-5.4-mini"

The examples use only the names bound above. service and model are the provider and model they run on: bind your own there. The table at the end links each provider's start page.

What every provider shares

A function written once takes the provider as its argument:

function explain(service, model)
    chat = Chat(service=service, model=model)
    push!(chat, Message(Val(:system), "You are a concise Julia programming tutor. Answer in plain text, without Markdown."))
    push!(chat, Message(Val(:user), "What is multiple dispatch? Answer in 2-3 sentences."))
    result = chatrequest!(chat)
    result isa LLMSuccess || error("the request failed: $result")
    result
end

result = explain(service, model)
text(result)

u = token_usage(result)
(; u.prompt_tokens, u.completion_tokens, cost = round(estimated_cost(result); digits=6))

Whatever service names:

  • The types and verbs. A Chat holds a conversation, with its tools, streaming, structured output and attachments, and chatrequest! sends it (Conversations with Chat); a Respond is one request of a provider's agentic API, which respond sends where the provider has one (Agentic respond). Embeddings, images, FIM and audio have verbs of their own, on the providers that serve them.
  • The results. A call returns a typed success, failure or call error rather than throwing for what the provider answers (Results); its usage is a TokenUsage, which estimated_cost prices (Cost Tracking).
  • Time, retries and cancellation. A RequestConfig sets a call's timeouts and retries, and a CancelToken stops it (Timeouts & Retries, Concurrency, Tasks and Cancellation); where a provider's models start from other bounds, its entry says so.
  • Recordings. with_recorded_answers records a call of the verbs it covers — chat, respond, embeddings, FIM and prefix completion, the Responses lifecycle — once and replays it with no key and no network (Testing and recordings).
  • Refusals before sending. A verb refuses an endpoint whose declared capabilities lack it, and the request's encoder refuses what the provider's rules name, each with an ArgumentError before anything is sent (Capabilities by provider).

Switch providers

  • The endpoint and its key. Bind service to the provider's endpoint, and set the variable it reads its key or host from: each provider's start page names both, and its default model. A Chat or a Respond that names no model gets that default, and throws ArgumentError on a provider that has none.
  • The model and its options. Model ids, and the options each model takes — reasoning efforts, sampling controls, service tiers, caching —, are the provider's. UniLM checks a request against the rules its provider's entry lists and throws ArgumentError before sending for what they refuse; a request those rules let through goes to the provider, whose answer is the check. After a switch, an option the new provider refuses by such a rule fails at the first call, before anything is sent. The table below links each provider's rules.
  • A conversation. Its messages move with it: Chat(service=…, model=…, messages=chat.messages) continues a conversation on another provider. What a provider adds to its own replies — thinking text, and the signatures that come with it — goes back only to that provider (ProviderContent); the next provider gets each turn's text and tool calls.
  • The price. estimated_cost prices a result at its model's row of DEFAULT_PRICING (Cost Tracking), and each provider's entry says which models its rows cover and what it prices otherwise.

Where the providers differ

  • What each serves. Capabilities by provider shows the capabilities each provider's endpoints declare — chat, tools, embeddings, images, the platform APIs —, and which requests UniLM sends to a server without knowing whether it serves them.
  • The API its endpoint speaks. Some endpoints speak their provider's native API, and others the OpenAI wire that many providers serve; the table below says which, and what UniLM's release gate tests live before every release. A server with an OpenAI-compatible API is reached with a GenericOpenAIEndpoint, and any other with an endpoint of your own (Write your own backend).

Keep up with provider models

Providers add models, deprecate them and shut them down on their own schedules. Where an endpoint declares :models, list_models lists the models it serves your key, or holds, today (Model Listings), and that provider's Models section shows what its listing gives.

UniLM checks a request against its rules for the model the request names, and prices the result at the row of DEFAULT_PRICING of the model the reply names as having served it, else of the model requested: the row of the id, else of the id without a dated snapshot suffix such as -2026-09-14 or -20251101. A model with no rule row of its own meets only the rules its provider sets for every model, and the provider's answer checks the rest; a model with no price row is estimated at 0.0 (Unpriced models cost $0). Before you adopt a newly listed model, look for its price row as the cost code does:

priced(id) = haskey(DEFAULT_PRICING, id) ||
             haskey(DEFAULT_PRICING, replace(id, r"-(\d{4}-\d{2}-\d{2}|\d{8})$" => ""))
priced(model), priced(model * "-2026-09-14"), priced("my-model")

UniLM's release gate holds its rule and price tables to three providers' listings before every release: every listed model of a family UniLM documents needs a price row, and a rule row where the table below says so; every model UniLM names — as a default, in its live tests or in the Julia code of these pages — must be listed, and listed before its shutdown date where the listing gives one.
