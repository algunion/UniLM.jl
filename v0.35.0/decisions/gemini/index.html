Decisions · Gemini Decisions API

Gemini Decisions API

Google's Decisions API reads an input — a text, a JSON value, pictures — and answers the yes/no, choice and score questions you list about it with calibrated probabilities, writing no text; Google bills the input and no output (Decisions API). The API is in Beta, on the Gemini API's v1beta only, and its one model is Gemini Decision 1. GEMINIServiceEndpoint, the endpoint of the Google Gemini language-model entry, speaks it at POST /v1beta/decisions for ask and the verbs built on it, with the same key; GEMINIOpenAIServiceEndpoint serves no decisions. Of the API, UniLM does not wrap audio, video and PDF blocks in the input, Files API and HTTPS URIs, the medium and ultra_high resolutions, or a Noul's confidence apart from its probability.

Setup

Set the API key of your Google AI Studio project in the environment Julia starts from:

export GEMINI_API_KEY="..."

A call goes to the Decisions API when it names service = GEMINIServiceEndpoint, or when it names no service and a with_system_one(GEMINIServiceEndpoint) scope encloses it; a call that names neither goes to the chapter's default provider (Decisions). A call's model is its own model = …; else, when it names no service, the scope's; else the default model at the top of this page. UniLM reads GEMINI_API_KEY when each request is sent, so a key exported after using UniLM takes effect; with none, a call sends nothing and returns a SystemOneCallError (When something fails). Requests go to https://generativelanguage.googleapis.com/v1beta/decisions, and no variable moves them; the API has no v1 route (HTTP 404 on 16 November 2026).

The API takes no request options — no caching, batch, Flex or Priority, "Repeated input across requests counts in full" (Limitations) — so a keyword of ask other than its own, and an option of a with_system_one scope, is refused before anything is sent (Limits and refusals).

First decision

One request carries the input once and every question about it; each answer comes back under the name you gave its question (How it works):

const TEAM = (billing   = "payments, charges, invoices or refunds",
              technical = "the app or the website does not work as expected",
              shipping  = "a parcel that is late, lost or arrived damaged",
              other     = "anything else")
message = "I was charged twice for order #4471. Please refund the duplicate payment."

r = ask(message, "team" => choice("Which team should handle this message?", TEAM); service = GEMINIServiceEndpoint)
a = r["team"]
(a.choice, a.probabilities[a.choice], a.confidence)

a.choice is the most probable option, a.probabilities holds one probability per option, and a.confidence says how peaked they are (Confidence and tuning). A failed call has no answers: r["team"] throws a SystemOneError on it (When something fails), and an input Google's filters block comes back as a RefusalAnswer for every question, which has no choice (Blocked inputs).

r.response.model, token_usage(r).prompt_tokens, r.response.request_id

The call named no model, so it was sent with the default model at the top of this page; Google's reply names no model, so r.response.model is the one the request named, and no header carries a request id, so r.response.request_id is nothing. nl_classify makes the same kind of decision in one call and returns the key whose description fits (Dispatch on Meaning):

nl_classify(message, TEAM; service = GEMINIServiceEndpoint)

Models

Google serves the Decisions API with one model, the default model at the top of this page: "Available on the Gemini Developer API (v1beta) with Gemini Decision 1 only" (Limitations); its model page lists text, image, video, audio and PDF inputs, an input token limit of 262,144, and calibrated probabilities with 0 output tokens. A call may name another model, which UniLM sends as written: Google answered models/gemini-decision-1 with HTTP 200, and an unknown model with HTTP 404 and the code not_found (16 November 2026). The reply names no model, so r.response.model is the name the request sent, without one leading models/: Google's SDK documents models/{model} as the same id, so both forms read as gemini-decision-1 and estimated_cost prices them alike (Cost).

list_models(service = GEMINIServiceEndpoint) lists every model Google serves the key, the language models with this one (Models); no recording holds it, so inside a replay scope it reaches Google with your key (Testing and recordings).

Questions

The API answers three kinds of question, in any mix in one request (Question types), and UniLM sends each question type as the one that fits:

You writeGoogle receivesYou get

noula noul question, yes and no as the true_description and false_description of its criteriaa NoulAnswer: the probability that the statement holds

bounding_boxnothing: refused (Limits and refusals)—

The state becomes the request's input:

StateGoogle receives
a string that is not blankthe string
a JSON value: a dictionary, an array, a tuple, a NamedTuplethe value's JSON text, a string, as the guide advises (Structured data)
an ImageAttachment, or a vector or tuple of strings and imagestext and image content blocks in their order (Images)
q = ask("The app crashes every time I open my order history. Third time this week, and my parcel is due today!",
        "team"    => choice("Which team should handle this message?", TEAM),
        "urgency" => score("How urgent is this message?",
                           ["Can wait", "Needs attention this week", "Needs attention today"]),
        "repeat"  => noul("Has the customer had this problem before?");
        service = GEMINIServiceEndpoint)
(q["team"].choice, q["urgency"].score, q["repeat"].noul)

What reaches the model:

  • Question names do not. "The model never sees question keys, so write the full question in the instructions field" (Request and response reference). A name is 1 to 64 ASCII letters, digits, _ and -; nl_dispatch names each question after its argument, so an argument named outside that set is refused.
  • Instructions are text. Every question needs instructions, and they are text only: a string, or a vector or tuple of strings, which UniLM sends as text blocks and Google joins "with no separator", so put your own spaces or newlines between them (Input). A picture belongs in the state, and a JSON object is not turned into text for you: write JSON.json(data) to send its text.
  • Option names and descriptions travel, in Google's order. "Before evaluation, the API sorts option keys alphabetically in UTF-8 byte order. Changing key order in your JSON request doesn't change option positions, and exact probability ties break to the alphabetically first key" (Pick one option). The order you pass is sent, and sets no position. Name a catch-all by what it means, not by where you expect it: the guide advises "a non-positional key like "other" rather than "noneofthe_above", since the API sorts option keys alphabetically" (Best practices).
  • Other guidance is text. An option's description, a Score level and a Noul's yes and no are strings; a level is not empty. Anything else is a refusal (Limits and refusals).

A Choice takes 2 to 255 options, a Score 2 to 255 levels (Google recommends 2 to 10), and a request 1 to 1,000 questions (Limits); a request outside these is refused before it is sent (Limits and refusals). Where each provider takes a picture is on Choosing a decision provider. Reading the answers and the decision rules on them are on Route and Decide.

Images

A picture goes in the state: an ImageAttachment alone, or a vector or tuple of strings and images, sent as image and text blocks in their order, each image its base64 bytes and its MIME type. An image's detail is the block's resolution: "low" and "high" are sent as written, and "auto", Google's default, sends none (Media resolution). The images count as input at the same rate as text (Cost): the 266-byte red circle of this manual's assets counted 1,089 tokens at the default resolution and 256 at "low" (16 November 2026).

circle = ImageAttachment(joinpath(pkgdir(UniLM), "docs", "src", "assets", "red_circle.png"); detail = "low")
p = ask(["The customer sent this picture of the sticker they received:", circle],
        "colour" => choice("What colour is the sticker?", ["red", "green", "blue"]);
        service = GEMINIServiceEndpoint)
(p["colour"].choice, token_usage(p).prompt_tokens)

A picture anywhere else — inside a JSON state, in a question's instructions, an option or a level — is refused, since instructions and descriptions are text; so are detail = "original", which has no Gemini resolution, and images of more than 100 MB in all (Limits and refusals). A text block is not empty, though one of whitespace alone, a separator, is sent.

Blocked inputs

Google answers no question of an input its filters block, and documents two shapes for it. The API reference's: a 200 whose prompt_feedback.block_reason is set, when "no decisions were evaluated, and answers is empty" (CreateDecisionResponse); UniLM returns it as a success whose every answer is a RefusalAnswer, its raw the block_reason (safety, other, blocklist, prohibited_content, image_safety) and the block_reason_message. The guide's: an HTTP 400 whose error code is safety, prohibited_content, blocklist, image_safety or content_blocked (Request and response reference); UniLM returns a SystemOneFailure whose error_type is that code. Test a isa RefusalAnswer before you read a.choice, a.score or a.noul. nl_classify, nl_dispatch and @branch take a refusal as a decline whatever their policy, which never sees it: fallback runs (the _ line, in @branch), or DecisionDeclinedError is thrown with the refusal as its answer; a failure throws a SystemOneError.

No recording can be made to hold a blocked input without sending content a filter blocks, so to test what your code does with one, declare an endpoint of your own that speaks this API's wire to a local server, through the protocol seam (Write your own decision provider); _resolve_base_url is an internal hook. Run such tests outside with_recorded_answers. This block is not run when the manual is built:

using UniLM, HTTP, JSON, Test

struct DecisionsMock <: UniLM.ServiceEndpoint end
UniLM.provider_capabilities(::Type{DecisionsMock}) = Set([:system_one])
UniLM.system_one_protocol(::Type{DecisionsMock}) = UniLM.GeminiDecisionsProtocol()
UniLM._resolve_base_url(::Type{DecisionsMock}) = "http://127.0.0.1:8125"     # internal hook
UniLM.auth_header(::Type{DecisionsMock}) = ["Content-Type" => "application/json"]

TEAM = (billing = "payments, charges, invoices or refunds", other = "anything else")
server = HTTP.serve!("127.0.0.1", 8125; verbose = false) do req
    # A blocked input, as Google's API reference shapes it: no answers, the reason in prompt_feedback.
    body = (prompt_feedback = (block_reason = "safety", block_reason_message = "Blocked."),
            usage = (total_input_tokens = 42, total_output_tokens = 0))
    HTTP.Response(200, ["Content-Type" => "application/json"], JSON.json(body))
end

@testset "a blocked input" begin
    @test nl_classify("Where is my parcel?", TEAM; service = DecisionsMock, fallback = m -> :person) === :person
    @test_throws DecisionDeclinedError nl_classify("Where is my parcel?", TEAM; service = DecisionsMock)
    r = ask("Where is my parcel?", "classify" => choice("Which team?", TEAM); service = DecisionsMock)
    @test r["classify"] isa RefusalAnswer && r["classify"].raw["block_reason"] == "safety"
end
close(server)

Confidence and tuning

A Noul's answer is the probability that its statement holds, from 0.01 to 0.99 ("a check above 0.99 never matches"); a Choice or a Score answer carries a probability distribution, and Google's own confidence is "the top outcome's probability, or max(noul, 1 - noul) for yes/no questions" (Answers, probabilities, and confidence). UniLM recomputes a Choice's and a Score's confidence with the formulas of Reading answers, so a threshold means the same on every provider, and keeps Google's value in the answer's raw:

(a.confidence, a.raw["confidence"], a.probabilities[a.choice])

The replies give every probability unrounded, so ask accepts a distribution that sums to 1 within 1e-6, and a chosen option no more than that below the most probable; a reply further off is a SystemOneCallError. The guide's own examples are rounded to two or three decimals, and two of them sum to 0.999 and 1.01: a reply like them would be a SystemOneCallError here.

Evidence

Measured on 16 November 2026 on gemini-decision-1, 13 replies with HTTP 200: every probability carried 15 or 16 decimals; the 9 distributions of 3 or 4 outcomes summed to 1 within 2.3e-16; each Choice and Score confidence equalled the top probability, and each Noul's max(noul, 1 - noul), exactly; a score equalled the expectation of its probabilities exactly. The same 4-option request sent four times gave the same probabilities each time, in another key order. Latency 0.26 s to 0.72 s, median 0.36 s. Limits: one day, one key, short English inputs.

The bar is yours: below min_confidence, a natural-language verb returns what fallback returns, and with no fallback it throws LowConfidenceError. Google advises "thresholds using labeled examples from your own traffic" and weighing "the cost of a false positive against a false negative"; where some mistakes cost more than others, price each one and let a decide policy choose the cheapest action (When mistakes have different prices). The decision rules on every provider are on Act on the answer.

Cost

Google bills a decision's input tokens, at one rate for text, images, audio and video, and no output, which is always 0 tokens: "Each request bills shared input tokens once, regardless of question count. Each question adds tokens for its own instructions, criteria, and formatting" (Pricing). The rate is the default model's row of Cost and usage.

u = token_usage(r)
(u.prompt_tokens, u.completion_tokens, estimated_cost(r))

prompt_tokens is Google's total_input_tokens — images, video frames and PDF pages count as image tokens —, completion_tokens its total_output_tokens, cached_tokens its total_cached_tokens (the API caches nothing), and prompt_audio_tokens the audio among the input. estimated_cost bills prompt_tokens at the row's input rate and no output. The free tier bills nothing, which no response shows. Totals across calls and prices of your own are on Cost Tracking.

Testing and recordings

with_recorded_answers records an exchange with the Decisions API once and replays it with no key and no network: ask, ask_each and the verbs built on them. A recording is filed under /gemini-decisions/v1beta/decisions, the request's path behind the namespace gemini-decisions, so a question asked of two providers is two recordings, and it is keyed on the exact request: its method, that path, and its body, which names the model. A picture is keyed and written as data:<mime>;sha256,<hex>, the SHA-256 of its base64 text, never its bytes.

recordings = mktempdir()      # in a package: a directory committed next to the tests
recorded = with_recorded_answers(recordings; mode = :record) do
    ask(message, "team" => choice("Which team should handle this message?", TEAM); service = GEMINIServiceEndpoint)
end
JSON.parsefile(only(readdir(recordings; join = true)))["request"]["path"]

replayed = withenv("GEMINI_API_KEY" => nothing) do
    with_recorded_answers(recordings) do
        ask(message, "team" => choice("Which team should handle this message?", TEAM); service = GEMINIServiceEndpoint)
    end
end
replayed["team"].probabilities == recorded["team"].probabilities

Recording takes GEMINI_API_KEY, and replaying takes nothing; in this manual's build the recording scope above replays the manual's own recordings, so the example reaches no service either (How this manual runs its examples). list_models on this endpoint is not recorded: inside a scope it goes to Google, with the key, as outside one. A blocked input cannot be recorded; a local server can stand in for it (Blocked inputs). Previews of what a call sends, tests of the methods and of the judgment, and an audit trail are on Test and Develop.

When something fails

A call that reaches Google returns a SystemOneSuccess; a SystemOneFailure for a status other than 200, with the status, Google's message and its error_type — the error's code when it is a string, such as "invalid_request", else its status, such as "INVALID_ARGUMENT"; or a SystemOneCallError when no usable response came. A 200 whose answers do not fit the request — a question unanswered, an option that was not offered, probabilities that are no distribution — is a SystemOneCallError too. Reading an answer of a failed call (r["name"], answer, answers) throws a SystemOneError.

UniLM sends a request again after a 408, 429, 500, 502, 503, 504, 520 to 524 or 529, up to max_attempts times within total_deadline, waiting at least what the reply's Retry-After header asks for, as the shared backoff of ask_each does; any other status comes back as it is. With no RequestConfig of your own, a call to the Decisions API is bounded by 60 s per attempt and 150 s in all, and ask_each keeps 8 requests in flight unless its ntasks says otherwise (Many requests at once); a config of your own replaces the bounds, per call or for a scope:

scoped = with_request_config(request_timeout = 20.0, max_attempts = 5) do
    ask(message, "team" => choice("Which team should handle this message?", TEAM); service = GEMINIServiceEndpoint)
end
issuccess(scoped)

Google's rate limits for Gemini Decision 1 are per project and tier (Rate limits):

The requests in flight make the rate: at the fastest reply measured, 0.26 s (16 November 2026), each keeps up to about 230 requests a minute going, so the default 8 can pass Tier 1's limit, and every tier's below it. The last column is the tier's requests a minute × 0.26 s ÷ 60 s, rounded down and at least 1: give it to ask_each as ntasks. A request of many tokens meets the tokens a minute first: use the tier's tokens a minute divided by the request's input tokens in place of its requests a minute. One request in flight can still pass the free tier's 200 when replies come fast; a 429 is retried within total_deadline, the requests of a batch backing off together.
