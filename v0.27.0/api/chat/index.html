Chat Completions API

Types and functions for the Chat Completions API.

Chat Object

UniLM.ChatType#
chat = Chat()

Creates a new Chat object with default settings:

  • model is set to gpt-6-sol (the OpenAI default)
  • messages is set to an empty Vector{Message}
  • history is set to true

On the native OpenAI endpoint, max_tokens is sent as max_completion_tokens (setting both throws ArgumentError); DeepSeekEndpoint and MistralEndpoint() send max_completion_tokens as max_tokens, the name their references give the cap, taken over a max_tokens also set, and every other endpoint sends the name the Chat sets. On the native OpenAI endpoint user throws (use safety_identifier or prompt_cache_key), and service_tier must be one of "auto", "default", "flex", "scale", "priority" or "fast". Native Gemini and GEMINIOpenAIServiceEndpoint take service_tier "standard", "flex" or "priority", and native Gemini sends seed (an int32) and store; ANTHROPICServiceEndpoint takes "auto", "standard_only" or "fast" (fast mode). Each refuses another value with ArgumentError before any request.

OpenAI options, omitted from the request when unset:

  • prompt_cache_options::Union{PromptCacheOptions,Nothing}: prompt-cache mode and ttl (PromptCacheOptions); supported for gpt-5.6 and later (gpt-5.4-mini answered HTTP 400 "promptcacheoptions is not supported on this model" on 2026-09-22). A Chat sets no cache breakpoints (the API's prompt_cache_breakpoint on a message content part), so mode="explicit" means the request does not use prompt caching.
  • prompt_cache_retention::Union{String,Nothing}: "in_memory" or "24h", the prompt cache's retention policy, which OpenAI's Chat Completions reference still lists and deprecates ("Use prompt_cache_options.ttl instead"); "for gpt-5.5, gpt-5.5-pro, and future models, only 24h is supported". OPENAIServiceEndpoint sends it, and throws ArgumentError for any value on the models whose cache lifetime prompt_cache_options sets — gpt-6-astra, gpt-6.1-sol, gpt-6-sol, gpt-6-luna, gpt-5.6 and gpt-5.6-sol/-terra/-luna (and their dated snapshots) — as a Respond does. Azure, GEMINIOpenAIServiceEndpoint, DeepSeekEndpoint and generic endpoints (Mistral among them) send it as given, the server's answer the check; native Gemini, ANTHROPICServiceEndpoint and OllamaEndpoint, whose requests have no such field, throw ArgumentError for it before any request.
  • moderation::Union{ModerationConfig,Nothing}: moderated completions (ModerationConfig).
  • stream_options::Union{AbstractDict,Nothing}: streaming options; when unset, an OPENAIServiceEndpoint, DeepSeekEndpoint or GEMINIOpenAIServiceEndpoint stream requests {"include_usage": true}, so the streamed result carries token usage.

The constructor validates ranges and throws ArgumentError on a violation; among them, n must be 1 when set — a result carries a single choice — top_logprobs must be in [0, 20], every logit_bias value (any Real) in [-100, 100], and reasoning_effort one of "none", "minimal", "low", "medium", "high", "xhigh", "max", and on a DeepSeekEndpoint also "ultra", which DeepSeek maps to max. An empty tools vector is stored as nothing.

Messages

UniLM.MessageType#
Message(; role, content=nothing, name=nothing,
          finish_reason=nothing, refusal_message=nothing,
          tool_calls=nothing, tool_call_id=nothing,
          provider_content=nothing, attachments=nothing, audio_output=nothing)

Represents a single message in a Chat Completions conversation.

Fields

  • role::String: One of RoleSystem, RoleUser, RoleAssistant, or RoleTool.
  • content::Union{String,Nothing}: The text content of the message.
  • name::Union{String,Nothing}: Optional name for the participant.
  • finish_reason::Union{String,Nothing}: Why the model stopped generating (e.g. "stop", "tool_calls"); nothing when the provider reported none. Response-only: never sent in a request.
  • refusal_message::Union{String,Nothing}: Refusal text when content is filtered; sent on the wire as refusal.
  • tool_calls::Union{Nothing,Vector{ToolCall}}: Tool calls requested by the assistant.
  • tool_call_id::Union{String,Nothing}: Required when role is "tool" — the ID of the tool call being responded to.
  • provider_content::Union{Nothing,ProviderContent}: Provider-native content blocks captured for verbatim round-trip (see ProviderContent); set by the Anthropic, Gemini, DeepSeek and Ollama decoders (tags :anthropic, :gemini, :deepseek, :ollama) and by the OpenAI-wire stream handler for the thinking chunks of a streamed Mistral reply (:mistral), nothing otherwise. Never serialized on the OpenAI wire.
  • attachments::Union{Nothing,Vector{Attachment}}: Images, sound clips and PDF documents sent with a user message (ImageAttachment, AudioAttachment, DocumentAttachment); nothing for none. See Attachment for how each endpoint sends or refuses them.
  • audio_output::Union{Nothing,AudioOutput}: The audio an OpenAI model answered with (AudioOutput), set by the OpenAI-wire decoders; nothing otherwise. Its docstring says how each encoder sends the turn back.

Validation

  • role must be one of "system", "user", "assistant", "tool".
  • At least one of content, tool_calls, refusal_message, attachments or audio_output must be given.
  • tool_call_id is required when role == "tool".
  • attachments are accepted on user messages only; an empty vector is stored as nothing.
  • audio_output is accepted on assistant messages only; with content unset or empty, the turn's content is its transcript.

Convenience Constructors

Message(Val(:system), "You are a helpful assistant")
Message(Val(:user), "Hello!")
Message(Val(:user), "What colour is the shape?",
        ImageAttachment("shape.png"))
UniLM.ProviderContentType#
ProviderContent(provider::Symbol, blocks::Vector{Any})

Provider-native assistant content captured verbatim at decode time and echoed verbatim at encode time when the SAME provider encodes the turn again.

The neutral Message carries content::String + tool_calls, but some providers attach blocks that must round-trip byte-faithfully for multi-turn flows to work: Anthropic thinking/redacted_thinking blocks (their signature must be echoed unmodified or tool round-trips on thinking models are rejected with HTTP 400), Gemini text-part thoughtSignatures, DeepSeek reasoning_content and Ollama thinking. provider tags the wire dialect (:anthropic, :gemini, :deepseek, :ollama or :mistral); blocks is the provider's content/parts array exactly as decoded (String-keyed JSON) — for :deepseek, [Dict("reasoning_content" => text)], echoed only on requests that carry tools; for :ollama, [Dict("thinking" => text)], echoed as the assistant message's thinking; for :mistral, the thinking chunks of a streamed reply joined into one Mistral ThinkChunk, [Dict("type" => "thinking", "thinking" => [Dict("type" => "text", "text" => text)])], which no encoder sends.

Encoders ignore a ProviderContent tagged for a different provider — a conversation moved across providers falls back to the neutral reconstruction (the standard "other models drop thinking" semantics). The field never serializes on the OpenAI wire (excluded from JSON.lower(::Message)).

UniLM.reasoning_textFunction#
reasoning_text(m::Message) -> Union{String,Nothing}
reasoning_text(r::LLMSuccess) -> Union{String,Nothing}

The reasoning ("thinking") text a provider returned with an assistant turn, read from its ProviderContent: Ollama's thinking, DeepSeek's reasoning_content, Anthropic thinking blocks (separate blocks joined by a blank line; redacted blocks carry no text), Gemini thought parts and the thinking chunks of a streamed Mistral reply. nothing when the turn carries none — the provider returned no reasoning, or the model did not think. Like text, it throws an LLMResultError on a failure result.

chat = Chat(service=OllamaEndpoint(), model="gemma4:e4b",
            reasoning_effort="high")
push!(chat, Message(Val(:system), "Answer briefly."))
push!(chat, Message(Val(:user), "Is 391 prime?"))
r = chatrequest!(chat)
reasoning_text(r)   # "391 = 17 × 23, so …"

Audio replies

The audio an OpenAI model answers with, on an assistant Message; see Audio replies for how to ask for it and how later turns send it.

UniLM.AudioOutputType#
AudioOutput(; id, data, expires_at, transcript)

The audio an OpenAI model answers a Chat Completions turn with, on the assistant Message's audio_output. A Chat asks for it with modalities=["text", "audio"] and audio=Dict("voice" => …, "format" => …) on a model that speaks, such as gpt-audio-1.5 (Audio in Chat Completions).

  • id::String: the service's id for the audio (OpenAI's or Azure's), by which a later turn refers to it.
  • data::Vector{UInt8}: the audio, decoded from base64, in the format the request asked for.
  • format::Union{String,Nothing}: that format as the bytes' file signature shows it — "wav", "mp3", "flac", "opus" (Ogg Opus) or "aac" (ADTS) — or nothing for bytes that begin with none, such as "pcm16"'s raw samples.
  • expires_at::Union{Int,Nothing}: the Unix time, in seconds, until which the service keeps the audio for later turns; from a minute before then on the turn goes back without its id (below): the service no longer holds the audio when the request arrives, and OpenAI answered an id it never issued with HTTP 400 audio_not_found. nothing when it is unknown: the reply names none, or a streamed reply's expiry, which comes alone in its last update after the turn's finish, was lost to a connection that closed between the two; the turn is kept either way.
  • transcript::String: what the audio says; the turn's content too, unless the turn holds other text.

The OpenAI-wire decoders read it from a reply's message.audio; a streamed reply assembles it from its delta.audio chunks, and the transcript reaches the streaming callback as text. When the conversation goes on, the OpenAI and Azure Chat encoders (OPENAIServiceEndpoint, AZUREServiceEndpoint) send the turn back as {"role": "assistant", "content": content, "audio": {"id": id}}, the turn's content beside the id, until a minute before expires_at, and always when expires_at is nothing; from then on they send the content alone. Such a follow-up's request bytes therefore depend on the clock: one recorded with with_recorded_answers while the audio was live replays only until a minute before expires_at, then throws ReplayMissError; record it after the expiry. Every other encoder — the Gemini OpenAI-compatible endpoint, DeepSeek, generic endpoints, OllamaEndpoint, native Anthropic and Gemini — sends the turn's content alone, the neutral form it also sends for another provider's ProviderContent. Throws ArgumentError for an empty id.

Attachments

Images, sound clips and PDF documents sent with a user message; see Images, audio and documents for how each endpoint sends them, and Attachments for a worked example on Ollama.

UniLM.AttachmentType#
Attachment

Abstract supertype of the media a user Message carries besides its text: ImageAttachment, AudioAttachment and DocumentAttachment. An attachment holds the media's bytes and the format read from their leading bytes (the file signature), never from a file name, so its declared format always matches its content.

Endpoints on the OpenAI Chat Completions wire (OpenAI, Azure, the Gemini OpenAI-compatible endpoint, DeepSeek, generic endpoints) send an image as an image_url part, with its detail level when it sets one, a sound clip as an input_audio part and a document as a file part, all base64: UniLM sends every kind as a content part on this wire, and the server decides what to do with it. For the Responses API, input_file turns a document into an input_file part. OllamaEndpoint sends images and clips in the message's images list and refuses a document — a chat attachment, or an input_file part for its Responses API, which documents no file inputs — and an image's detail level. The native Anthropic encoder sends an image and a document as base64 image and document blocks before the text, and refuses a sound clip and an image's detail level. Native Gemini sends every kind as an inlineData part ahead of the text, an image's detail level as its per-part media resolution ("low", "high"; "auto" sends none; "original" is refused, as is any level on the Gemini 2.5 and Gemma 4 models), and Gemini Interactions sends each as an image, audio or document part of an InputMessage's content. A System One request carries images, with a detail level on OpenAI's Decisions API alone, and refuses a document and a sound clip; an embedding input carries an image or a clip without a level. Each refusal is an ArgumentError before any network I/O.

UniLM.ImageAttachmentType#
ImageAttachment(path::AbstractString; detail=nothing)
ImageAttachment(data::AbstractVector{UInt8}; detail=nothing)

An image for a user Message: PNG, JPEG, GIF or WebP, recognised from its leading bytes. mime holds the media type ("image/png", …). detail is the level of detail an OpenAI model receives the image at — "auto", "low", "high" or "original", the image at its original dimensions, on the models that accept that level, such as GPT-5.6 (image inputs) — or nothing, which sends none and leaves the model's default. The OpenAI Chat Completions wire sends it as the part's detail; an endpoint without an equivalent refuses an image that sets one. Throws ArgumentError for empty data, bytes in any other format, or any other detail.

msg = Message(Val(:user), "What colour is the shape?",
              ImageAttachment("shape.png"))
msg = Message(Val(:user), "Read the small print.",
              ImageAttachment("label.png"; detail="original"))
UniLM.AudioAttachmentType#
AudioAttachment(path::AbstractString)
AudioAttachment(data::AbstractVector{UInt8})

A sound clip for a user Message: WAV or MP3, recognised from its leading bytes. format holds "wav" or "mp3", the names the OpenAI input_audio part uses. Throws ArgumentError for empty data or bytes in any other format.

msg = Message(Val(:user), "Transcribe this.",
              AudioAttachment("clip.wav"))
UniLM.DocumentAttachmentType#
DocumentAttachment(path::AbstractString)
DocumentAttachment(data::AbstractVector{UInt8}; filename="document.pdf")

A PDF document for a user Message, recognised from its leading bytes (%PDF-). mime is "application/pdf"; filename is the file's own name (basename(path)) or, for bytes, the keyword. Endpoints on the OpenAI Chat Completions wire send the document as a file part with its filename (file inputs); for the Responses API, input_file turns it into an input_file part with its filename. The native Anthropic encoder (a base64 document block), native Gemini (inlineData) and Gemini Interactions (a document part) send the document without it. See Attachment for the endpoints that refuse it. Throws ArgumentError for bytes that are not PDF, whatever the file is called, and for a blank filename.

msg = Message(Val(:user), "What does the report conclude?",
              DocumentAttachment("report.pdf"))

Conversation Management

Base.push!Method#
push!(chat::Chat, msg::Message)

Add a message to the conversation, refusing any mutation that would make it invalid.

Throws InvalidConversationError when the mutation would produce an invalid conversation: a non-system message pushed onto an empty conversation (it must start with a system message), or a message whose role repeats the last message's role (consecutive tool-result messages are the one exception). chat[i] = msg and direct edits to chat.messages are not validated.

A system message pushed once the conversation has started changes the instructions from that point on. Where it reaches the provider depends on the encoder:

  • the OpenAI wire (OpenAI, Azure, DeepSeek and other OpenAI-compatible endpoints) and OllamaEndpoint send it in place;
  • native Gemini joins it into systemInstruction;
  • native Anthropic places it as the Anthropic entry's Conversations section says. The system messages a conversation starts with become the top-level system prompt, joined with a blank line. Where a system message pushed later goes depends on two columns of the Claude family table (Reasoning). On a model whose Mid-conversation system messages cell is "yes", it stays in place, as a system turn, where the Messages API takes one: right after a user turn (tool results count as one), and last or right before an assistant turn. Anywhere else it joins the top-level system prompt, except, on an append-only model, one pushed after a sent assistant turn. On a model whose cell is "—", it joins the top-level system prompt. Append-only are the models whose Thinking prefix check cell is "yes", and any id that matches no row (an id with a -YYYYMMDD snapshot suffix takes the row of the id without it): once an assistant turn is sent, UniLM never edits the top-level system prompt of an append-only model, so a later system message that cannot stay in place is held back, then sent right after a later user turn, and the turns before each sent reply stay as they were in the request that got it.

On native Anthropic, a system message pushed after a reply needs a user turn after it — a user message, or the results of the reply's tool calls — except in a response prefill on a model whose Prefill cell is "yes". Until one follows, chatrequest! throws ArgumentError before sending: as it stands, the request would end with the assistant turn, a response prefill.

UniLM.issendvalidFunction#
issendvalid(chat::Chat)::Bool

Check if the conversation is valid for sending to the API.

Returns true only when the conversation has at least two messages, the first is a system message, the LAST is a user message, and no two adjacent messages share a role. Note the last two clauses are stricter than push!, which permits consecutive tool messages — this check has no such exemption, and a conversation ending in a tool result is false here.

This is a heuristic, not a proof: it cannot catch every malformed shape (a second system message in the middle passes the adjacency test). It never throws — a false is a verdict, not an error.

UniLM.update!Function#
update!(chat::Chat, msg::Message) -> Chat

Append msg to the conversation when chat.history is on; with history=false the chat is left unchanged, as documented for that setting (logged at debug level only).

UniLM.forkFunction#
fork(chat::Chat) -> Chat

Create an independent copy of a Chat: every field except service is deep-copied in one pass, so mutating a fork's messages, tools, metadata, stop or any other field never reaches its source or its siblings; service is shared (the endpoint a chat talks to, not conversation state); the cumulative-cost Ref is fresh (copied by value). The copy runs over fieldnames(Chat), so new Chat fields fork automatically. fork itself applies no normalization or rewrite — a fork is configuration-identical to its source.

fork(chat::Chat, n::Int) -> Vector{Chat}

Create n independent forks of a Chat.

UniLM.FunctionSignatureType#
FunctionSignature(; name, description=nothing, parameters=nothing, strict=nothing)

Describes a function that can be called by the model in the Chat Completions API.

Fields

  • name::String: The name of the function.
  • description::Union{String,Nothing}: A description of what the function does.
  • parameters::Union{AbstractDict,Nothing}: JSON Schema object describing the function parameters.
  • strict::Union{Bool,Nothing}: Strict schema adherence for the function's arguments. nothing (default) sends no strict, so the API's default applies: OpenAI's Chat Completions call the function non-strict, while its Responses API, which a Chat Tool reaches through Respond, "will attempt to normalize your schema into strict mode when possible" and falls back to non-strict function calling where it cannot (function calling). true asks for adherence: OpenAI's strict mode needs additionalProperties: false on every object and every property required, which UniLM does not check, and OpenAI rejects a request whose strict schema misses them "with details about the missing constraints". The native Anthropic encoder sends the flag on the tool; native Gemini and Gemini Interactions, which have no such flag, ask for validated function calling when tool_choice is unset or "auto"; OllamaEndpoint refuses strict=true.

Example

sig = FunctionSignature(
    name="get_weather",
    description="Get the current weather in a given location",
    parameters=Dict(
        "type" => "object",
        "properties" => Dict(
            "location" => Dict("type" => "string", "description" => "The city")
        ),
        "required" => ["location"],
        "additionalProperties" => false
    ),
    strict=true
)

Request Function

UniLM.chatrequest!Function#
chatrequest!(chat::Chat; config=nothing, callback=nothing, on_tool_call=nothing, cancel=nothing)

Send chat to its provider and return a typed result.

Non-streaming (chat.stream !== true): returns LLMSuccess, LLMFailure, or LLMCallError. Transient statuses (408/429/500/502–504/520–524/529) are retried with backoff and jitter under the resolved RequestConfig (max_attempts, total_deadline; retry-after-ms, else Retry-After, honored). Timeouts surface as LLMCallError with status = nothing and the UniLMTimeout in cause — no fabricated HTTP statuses. Inside a with_recorded_answers scope the request passes through the recordings, and one the scope cannot replay — no recording in :replay mode, or a recording file that cannot be read — throws ReplayMissError instead of returning: a gap in the recordings is not a service failure. A streamed call passes through them too, replayed through the same callbacks: a miss on its first request is thrown by chatrequest! itself, while its reply's lost recording (RecordingWriteError), or a miss on a later request of a turn the provider continues, is thrown inside the task, so fetch raises a TaskFailedException whose task.exception is that error.

Streaming (chat.stream === true): returns a Task whose fetch yields the same typed results. callback(chunk::Union{String,Message}, close::Ref{Bool}) receives text deltas then the final assembled Message; on_tool_call(tc::ToolCall) fires once per completed streamed tool call. Setting close[] = true — in the callback or from any other task — stops the stream at once: the call ends with LLMCallError(status=nothing, cause=UniLMCancelled(:callback, …)), unless the provider's completion marker already arrived — then the turn is committed, the final-message callback runs, and usage may be missing. The marker is the chunk that carries the finish reason; on the OpenAI wire it precedes the usage chunk and [DONE]. The turn is final at the end-of-stream sentinel ([DONE], Anthropic message_stop): the final-message callback runs then, and the result follows when the HTTP body ends, at most 0.5 s later (a body still open then has its connection closed rather than reused). An exception thrown by callback or on_tool_call ends the call with that exception in cause: never retried, nothing committed, and no callback runs after it. Time spent in these callbacks does not count toward stream_idle_timeout, which bounds only the gap between bytes off the socket. A user InterruptException is never converted into a result value: it propagates, so fetch on the streaming task throws a TaskFailedException whose task.exception is the InterruptException. So does the ReplayMissError or RecordingWriteError of a recorded call made in callback or on_tool_call, and either of them or an interrupt that a callback throws inside a wrapper, such as a fetched task's TaskFailedException: task.exception is what the callback threw.

A stream that ends without committing a turn — stopped, cancelled, timed out, cut off, or ended by an exception from callback or on_tool_call — adds the usage its provider had reported to cumulative_cost, as a lower bound of what was billed: Anthropic reports a request's input when its stream starts, Gemini the usage so far on every chunk, and OpenAI only after the finish reason, so a stopped OpenAI stream adds nothing. A request stopped before any usage arrived adds nothing, though the provider bills it; so does an attempt that was retried, and a stream the provider ended with an error event.

config::Union{Nothing,RequestConfig}: per-call timeout/retry budget; nothing resolves the ambient configuration (with_request_config scope, else the process default set via set_default_config!, else the model's own default where it has one — the 20-minute bounds of a Gemini 4 model, see set_default_config! — else the field defaults).

A long generation the provider stops at its per-request cap and returns a token to continue (Gemini 4 Argon's long decode on GEMINIServiceEndpoint) is continued inside the call: the same request is sent again with the latest token, as often as the output budget (max_completion_tokens, else max_tokens) needs at Google's per-request cap — 32,768 output tokens, 65,536 on a stream — plus one request, and at least 8 requests in all. The result is one assistant turn — the replies' parts joined, their usage summed field by field, since every reply is billed, and priced at the tier the last reply reported. Each request has the whole config budget, timeouts and retries alike; a retry sends its request again from the start: a stream that drops after one of its checkpoint tokens is not resumed from it, and what Google bills for the attempt that dropped (up to that checkpoint) is not added to cumulative_cost. A turn still unfinished after the last of those requests, or whose reply continues without having produced an output token (thinking included), is returned as it stands, with finish_reason == "continuation". A request that fails ends the call with its failure and commits nothing, and the replies already received are added to cumulative_cost. A streamed turn streams every reply into the same callback, which receives one final message. The turn's completion marker is its last reply's finish reason, not a reply's CONTINUATION: a stop or cancel before it ends the call with UniLMCancelled in cause and nothing committed, and the replies already answered — one whose CONTINUATION chunk the stop, or a throwing callback, landed on included — are added to cumulative_cost too, with what the reply in flight had reported. Continuation is exercised against a local mock; a live CONTINUATION reply was not observed.

cancel::Union{Nothing,CancelToken}: a CancelToken; nothing resolves the ambient token of with_cancel, at call entry. A cancel at any point — before connecting, during the response-header wait, mid-stream, or during a retry backoff — ends the call with LLMCallError(status=nothing, cause=UniLMCancelled(:token, …)): never retried, nothing committed to chat, no terminal callback — unless the provider's completion marker already arrived (as for close[] = true above): then the turn is committed, the final-message callback runs, and usage may be missing. A pre-cancelled token sends nothing. A TCP connect or TLS handshake already in progress cannot be interrupted (HTTP.jl 2.7.1), so a cancel during one takes effect when it completes or reaches connect_timeout.

Local validation throws before any network I/O, streaming or not: ArgumentError when callback or on_tool_call is passed without chat.stream === true (they run only on a stream, so they would be ignored), when chat.service is an endpoint type that declares its capabilities and does not list :chat (a custom endpoint declares none and is dispatched unvalidated), or when the provider's encoder rejects the request (e.g. an option the provider or model does not support); InvalidConversationError when chat.history is on and the conversation ends with an assistant message, so the reply could not be appended; and the MethodError of a seam method the endpoint type lacks — encode_request, and on a stream handle_sse_event!, whose missing method would otherwise drop every payload of the reply.

chatrequest!(; messages, config=nothing, cancel=nothing, kwargs...)

Build a Chat from keyword arguments, send it with chatrequest!(chat; config, cancel), and return that result (the reply is appended to result.self).

The conversation is EITHER messages — copied, so the caller's vector is never mutated — OR systemprompt and userprompt, each a String or a Message. Passing neither, only one prompt, or messages together with a prompt throws ArgumentError before any network I/O. Every other keyword but config and cancel is a Chat field, for example:

  • service::ServiceEndpointSpec = OPENAIServiceEndpoint: The provider endpoint type or instance.
  • model::String: The model; the service's default when omitted.
  • history::Bool = true: Whether the reply is appended to the conversation. It does not change what is sent.
  • tools::Union{Vector{Tool},Nothing} = nothing: A list of tools the model may call.
  • tool_choice::Union{String,GPTToolChoice,Nothing} = nothing: Controls which (if any) function is called by the model. e.g. "auto", "none", GPTToolChoice.
  • parallel_tool_calls::Union{Bool,Nothing} = false: Whether to enable parallel function calling.
  • temperature::Union{Float64,Nothing} = nothing: Sampling temperature (0.0-2.0). Higher values make output more random. Mutually exclusive with top_p.
  • top_p::Union{Float64,Nothing} = nothing: Nucleus sampling parameter (0.0-1.0). Mutually exclusive with temperature.
  • n::Union{Int64,Nothing} = nothing: Number of choices; must be 1 — a result carries a single choice.
  • stream::Union{Bool,Nothing} = nothing: If true, the call returns a Task and streams deltas to callback (see chatrequest!(chat)).
  • stop::Union{Vector{String},String,Nothing} = nothing: Up to 4 sequences where the API will stop generating further tokens.
  • max_tokens::Union{Int64,Nothing} = nothing: The maximum number of tokens to generate in the chat completion.
  • presence_penalty::Union{Float64,Nothing} = nothing: Number between -2.0 and 2.0. Positive values penalize new tokens based on whether they appear in the text so far.
  • response_format::Union{ResponseFormat,Nothing} = nothing: An object specifying the format that the model must output. e.g., ResponseFormat(type="json_object").
  • frequency_penalty::Union{Float64,Nothing} = nothing: Number between -2.0 and 2.0. Positive values penalize new tokens based on their existing frequency in the text so far.
  • logit_bias::Union{AbstractDict{String,<:Real},Nothing} = nothing: Modify the likelihood of specified tokens appearing in the completion.
  • user::Union{String,Nothing} = nothing: A unique identifier representing your end-user, which can help OpenAI to monitor and detect abuse.
  • seed::Union{Int64,Nothing} = nothing: This feature is in Beta. If specified, the system will make a best effort to sample deterministically.

config and cancel go to chatrequest!(chat):

  • config::Union{Nothing,RequestConfig} = nothing: Per-call timeout/retry budget; nothing resolves the ambient configuration (scoped, else process default).
  • cancel::Union{Nothing,CancelToken} = nothing: Cancellation token; nothing resolves the ambient token (see chatrequest!(chat)).

UniLM.tool_loop!Function#
tool_loop!(chat::Chat, dispatcher::Function; max_turns=10, config=nothing, callback=nothing, on_tool_call=nothing, cancel=nothing, tool_concurrency=1) -> ToolLoopResult

Run a tool-calling loop on a Chat. Repeatedly calls chatrequest!, dispatches tool calls via dispatcher(name, args), pushes tool-role messages back, and repeats until a text response, API error, or max_turns.

Tool calls run only on a turn whose finish_reason is "tool_calls". A turn that carries tool calls but finished for any other reason ("length", "content_filter", a provider-specific value) may hold partial calls: none runs, the loop stops with completed=false and an llm_error naming the reason, and that unanswered assistant turn is removed from chat, so the conversation stays sendable. A text turn completes the loop only when it finished with "stop" or reported no reason (or finished with "tool_calls" but carried no calls); "length" stops it with completed=false and llm_error = "Model output was truncated by the token limit", and any other reason ("content_filter", a provider-specific value) with an llm_error naming it — the turn stays in chat.

chat.history must be true (else ArgumentError before any request): each follow-up request carries the tool results together with the assistant turn that requested them.

Arguments

  • dispatcher: (name::String, args::Dict{String,Any}) -> String; any other return value is sent to the model JSON-encoded.
  • max_turns: Maximum API round-trips (default 10; < 1 throws ArgumentError). When they run out, the result keeps the last response, with completed=false and llm_error = "max turns (N) exhausted".
  • config: Per-request RequestConfig passed to chatrequest! — each turn gets its own attempt/deadline budget.
  • callback: Streaming callback passed to chatrequest!.
  • on_tool_call: Tool call notification callback passed to chatrequest!. Both are passed through unchanged and need chat.stream == true: otherwise the first request throws ArgumentError before any network I/O.
  • cancel: A CancelToken; nothing (default) uses the ambient token of with_cancel. Every turn — its request and its tool dispatches — runs inside with_cancel(cancel), and the token is checked before each dispatch. A cancelled loop returns promptly with completed=false and dispatches nothing further; response is the turn's typed cancellation result: the cancelled request's LLMCallError, or, when the cancel lands between dispatches, an LLMCallError whose cause is UniLMCancelled. A turn cancelled between dispatches is removed from chat (the calls it did run stay in tool_calls), so the conversation stays sendable.
  • tool_concurrency: How many of one turn's tool calls may run at once (default 1: one at a time, in the calling task; < 1 throws ArgumentError). Above 1, up to that many run concurrently on spawned tasks (Threads.@spawn), so dispatcher must be thread-safe; their results are appended in call order once all have finished, so the next request does not depend on completion order. An InterruptException from any dispatch propagates, after the interrupted turn is removed from chat (with any results already appended), so the conversation stays sendable. So does a ReplayMissError or a RecordingWriteError from a request the dispatcher made inside a with_recorded_answers scope: as a tool error, the model would read it and the loop would go on without the answer, or without its recording. Each propagates whole, also inside the TaskFailedException of a task the dispatcher fetches (a streamed call's, say); any other exception of a dispatch, so wrapped or not, is a tool error.

Example

chat = Chat(model="gpt-5.4-mini", tools=[tool])
push!(chat, Message(Val(:system), "You are a calculator"))
push!(chat, Message(Val(:user), "What is 3+5?"))
result = tool_loop!(chat, (name, args) -> string(args["a"] + args["b"]))

UniLM.tool_loopFunction#
tool_loop(r::Respond, dispatcher::Function; max_turns=10, config=nothing, cancel=nothing, tool_concurrency=1) -> ToolLoopResult

Run a tool-calling loop on a Respond request. Dispatches function calls via dispatcher(name, args) (a non-String return is sent JSON-encoded), builds function_call_output input items, and chains via previous_response_id — or, when r.conversation is set, through the conversation alone (the API rejects the two together). A call whose arguments are not a JSON object is answered with an "Error: invalid arguments: …" output, like a dispatcher error, and the loop goes on.

Function calls run only on a completed or requires_action turn. Any other status (e.g. incomplete, whose calls may be partial) stops the loop with completed=false and an llm_error naming the status and the incomplete_details reason. A turn that requests a client-side call this loop cannot execute (custom_tool_call, apply_patch_call, computer_call, a shell_call the platform did not run itself, or an mcp_approval_request) stops it the same way, with the pending call type in llm_error; none of that turn's calls run.

max_turns (default 10; < 1 throws ArgumentError) bounds the round-trips; when they run out, the result keeps the last response, with completed=false and llm_error = "max turns (N) exhausted".

cancel works as in tool_loop!: every turn runs inside with_cancel(cancel) (nothing uses the ambient token), the token is checked before each dispatch, and a cancelled loop returns promptly with completed=false and the turn's typed cancellation result — the cancelled request's ResponseCallError, or, between dispatches, a ResponseCallError whose cause is UniLMCancelled. tool_concurrency (default 1) works as in tool_loop!: above 1, up to that many of a turn's calls run at once and their outputs are sent in call order. An InterruptException, a ReplayMissError or a RecordingWriteError from a dispatch propagates, as in tool_loop!.

Per-call config::RequestConfig overrides timeouts/retry budget.

tool_loop(r::Respond; max_turns=10, config=nothing, cancel=nothing, tool_concurrency=1) -> ToolLoopResult

tool_loop(input, dispatcher::Function; tools, kwargs...) -> ToolLoopResult

Convenience form: creates a Respond and runs the tool loop.

Per-call config::RequestConfig overrides timeouts/retry budget; max_turns, cancel and tool_concurrency drive the loop as in tool_loop(::Respond, ::Function); every other keyword goes to the Respond constructor.

tool_loop(input::String; tools, max_turns=10, config=nothing, cancel=nothing, tool_concurrency=1, kwargs...) -> ToolLoopResult

No-dispatcher convenience form of the Responses-API tool loop for a plain-string prompt. Wraps input and tools in a Respond and delegates to tool_loop(::Respond), which dispatches each model-requested function call to the matching CallableTool callable.

Keyword routing is explicit: max_turns, config, cancel and tool_concurrency drive the loop (config::RequestConfig overrides timeouts/retry budget), while every other keyword is forwarded verbatim to the Respond constructor — an unknown keyword raises there rather than being silently dropped. tools is required and must hold CallableTool entries (e.g. from mcp_tools_respond).

Example

session = mcp_connect("https://mcp.example.com/mcp")
tools = mcp_tools_respond(session)
result = tool_loop("List files in /tmp"; tools=tools)
