Reference · API: OpenAI platform

Batch API

Create, retrieve, cancel, list and delete asynchronous batch jobs, poll them to completion, and read their results, on OpenAI, Anthropic and Gemini. A batch runs its requests within 24 hours at the provider's Batch rates — half its standard ones on every model each page lists, but for a cache hit on the six Gemini models whose Batch tab keeps the standard cache-hit price (gemini-3.1-pro-preview, gemini-3.1-pro-preview-customtools, gemini-3-flash-preview, gemini-2.5-pro, gemini-2.5-flash and gemini-2.5-flash-lite) — and estimated_cost prices a batch result at them.

  • create_batch(requests; service) takes the requests as custom_id => Chat pairs and sends each provider its own form of them: OpenAI a JSONL file of Chat Completions requests to one model, uploaded with purpose "batch", then the batch; Anthropic a Message Batch of Messages requests; Gemini inline generateContent requests to batchGenerateContent. It takes custom_id => Embeddings pairs too, on OpenAI (a JSONL file of /v1/embeddings requests to one model, at most 50,000 inputs across them) and Gemini (inline embedContent requests of one input each to asyncBatchEmbedContent); a batch holds one kind of request. OpenAI's own file-based form, create_batch(input_file_id, endpoint), runs any endpoint its Batch API serves.
  • batch_results reads the results of an ended batch as the results chatrequest! returns — an LLMSuccess, LLMFailure or LLMCallError per custom id —, decoded by the provider's own decoder, each success's usage at the tier "batch"; a batch of embeddings as the results embeddingrequest! returns — an EmbeddingSuccess, EmbeddingFailure or EmbeddingCallError —, billed at half the standard rate. On OpenAI it reads a /v1/chat/completions or /v1/embeddings batch: another endpoint's is a BatchCallError naming file_content(output_file_id), which reads its output file as OpenAI writes it. Given the pairs that created the batch, batch_results(id; service, requests), each result is the one chatrequest! returns for its request's Chat: a success's self is a copy of that Chat with the reply appended (the Chat passed is not changed), a failure's the Chat itself; without them, a stand-in Chat without messages. An embeddings success holds a copy of its request filled with the vectors, or, without the requests, a stand-in Embeddings holding them.
  • retrieve_batch, list_batches, cancel_batch and poll_batch run on all three; delete_batch on Anthropic and Gemini; update_batch (a batch's priority) on Gemini, a batch of embeddings included; create_batch(requests; display_name) names a Gemini batch.

Each verb first checks that its service has the :batch capability, which OPENAIServiceEndpoint, ANTHROPICServiceEndpoint and GEMINIServiceEndpoint declare.

Parsed Objects

UniLM.BatchObjectType#
BatchObject

A batch job, as create_batch, retrieve_batch, cancel_batch, update_batch and list_batches return it: id, status, request_counts (the provider's tallies of the batch's requests, as sent), and raw, the reply as sent. A reply without a string id or status is no batch: the call returns its BatchCallError.

  • OpenAI: status is the batch's status (validating, in_progress, finalizing, completed, failed, expired, cancelling, cancelled); endpoint, input_file_id, output_file_id and error_file_id are set.
  • Anthropic: status is the Message Batch's processing_status (in_progress, canceling, ended); request_counts its request_counts (processing, succeeded, errored, canceled, expired).
  • Gemini: id is the batch's name without its batches/ prefix; status its state (BATCH_STATE_PENDING, BATCH_STATE_RUNNING, BATCH_STATE_SUCCEEDED, BATCH_STATE_FAILED, BATCH_STATE_CANCELLED, BATCH_STATE_EXPIRED); request_counts its batchStats (counts as strings, as the API sends 64-bit integers); input_file_id and output_file_id the names of its input file and responses file, when it has them.
UniLM.BatchListType#
BatchList

A page of BatchObjects from list_batches; has_more signals that further pages are available, and raw holds the page as sent. The next page starts after the page's last batch id on OpenAI and Anthropic, and at its raw["nextPageToken"] on Gemini.

Result Types

UniLM.BatchSuccessType#

Successful create/retrieve/cancel/update result wrapping a BatchObject.

UniLM.BatchListSuccessType#

Successful list_batches result wrapping a BatchList.

UniLM.BatchResultsSuccessType#
BatchResultsSuccess

Successful batch_results result: results, each request's custom id paired with its result, in the order the provider returns them — for a batch of Chats an LLMSuccess, LLMFailure or LLMCallError, for a batch of Embeddings an EmbeddingSuccess, EmbeddingFailure or EmbeddingCallError.

UniLM.BatchDeleteSuccessType#

Successful delete_batch result: the provider deleted the batch id (deleted is always true).

UniLM.BatchFailureType#

Batch API error result: HTTP status, the raw response body, and the request_id the service sent (x-request-id/request-id header), if any.

UniLM.BatchCallErrorType#

Batch API call that produced no usable reply (transport failure, timeout, or a 200 that could not be decoded); cause is the underlying exception — a UniLMTimeout for a timeout. last_observed is set only when poll_batch runs out of time or is cancelled: the last BatchObject it saw, if any.

Request Functions

UniLM.create_batchFunction#
create_batch(input_file_id, endpoint; completion_window="24h", metadata=nothing, output_expires_after=nothing,
             service=OPENAIServiceEndpoint)

Create an OpenAI batch job from an uploaded file. endpoint is e.g. "/v1/chat/completions", "/v1/responses", or "/v1/embeddings". input_file_id comes from upload_file(path, "batch"). output_expires_after is the number of seconds, from 3600 (1 hour) to 2592000 (30 days), after which the batch's output and error files expire, counted from each file's creation; outside that range it throws ArgumentError before any request. This is OpenAI's form: on an Anthropic or Gemini endpoint it throws ArgumentError before any request; pass the requests themselves, create_batch(requests; service). batch_results decodes a "/v1/chat/completions" batch; another endpoint's results are its output file, which file_content(output_file_id) reads.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

create_batch(requests; service=nothing, metadata=nothing, output_expires_after=nothing, display_name=nothing)

Create a batch of chat requests: requests pairs each request's custom id with its Chat, and the batch runs on the endpoint the Chats name (service, when given, must be it). Each provider takes the Chats as its own Chat requests, encoded as chatrequest! encodes them:

  • OpenAI: a JSONL file of /v1/chat/completions requests, uploaded with purpose "batch" (one more request, which leaves the file in place should the create fail), then the batch; metadata and output_expires_after are its create's options. One model per batch: "each input file can only include requests to a single model".
  • Anthropic: a Message Batch whose requests' params are the Messages bodies. A custom id is 1 to 64 letters, digits, hyphens and underscores; fast mode (service_tier="fast") is not batched. The endpoint's betas go in the anthropic-beta header (e.g. "output-300k-2026-03-24", which raises max_tokens to 300,000 on a batch).
  • Gemini: inline requests to models/{model}:batchGenerateContent, each keyed by its custom id in its metadata; one model per batch, and no service_tier (the API answers a batched request that sets one with HTTP 400). display_name, a non-empty name, is the batch's displayName; the other providers take none.

A batch of embeddings pairs each custom id with an Embeddings request instead, encoded as embeddingrequest! encodes it, on an endpoint that has :embeddings too:

  • OpenAI: a JSONL file of /v1/embeddings requests, as above; one model per batch, and at most 50,000 inputs across its requests ("/v1/embeddings batches are also restricted to a maximum of 50,000 embedding inputs across all requests in the batch").
  • Gemini: inline requests to models/{model}:asyncBatchEmbedContent, each an embedContent request of one input (a request of several inputs is refused: give each its own custom id), keyed in its metadata.

Throws ArgumentError before any request for no request, an empty or repeated custom id, requests for different endpoints or of both kinds, a streamed Chat (stream=true), a request its provider's encoder refuses, and the provider rules above. Returns BatchSuccess (its BatchObject), BatchFailure or BatchCallError; batch_results reads the results once the batch ends.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried). The config bounds the upload and the create together on OpenAI.

UniLM.retrieve_batchFunction#
retrieve_batch(id; service=OPENAIServiceEndpoint)

The batch id on service: BatchSuccess (its BatchObject), BatchFailure or BatchCallError. On Gemini id may also be the batch's name, batches/{id}.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

UniLM.cancel_batchFunction#
cancel_batch(id; service=OPENAIServiceEndpoint)

Ask the provider to cancel the batch id; the result is the batch as the provider then reports it (OpenAI cancelling, Anthropic canceling; Gemini answers the cancel with an empty body, so the result is the batch as a GET right after it returns it). Requests already processed keep their results.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

UniLM.list_batchesFunction#
list_batches(; limit=nothing, after=nothing, service=OPENAIServiceEndpoint)

A page of the batches on service: BatchListSuccess (a BatchList), BatchFailure or BatchCallError. limit caps the page; after starts it after the batch id after on OpenAI and Anthropic (after_id), and at the page token after on Gemini (pageToken: the previous page's raw["nextPageToken"]). A 200 without the listing's required fields is a BatchCallError.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

UniLM.poll_batchFunction#
poll_batch(id; interval=10.0, timeout=86400.0, service=OPENAIServiceEndpoint, cancel=nothing)

Poll a batch until it reaches a terminal status: on OpenAI completed, failed, cancelled or expired; on Anthropic ended; on Gemini BATCH_STATE_SUCCEEDED, BATCH_STATE_FAILED, BATCH_STATE_CANCELLED or BATCH_STATE_EXPIRED. timeout bounds the wall-clock time of the whole poll (Inf waits indefinitely); interval is the pause between GETs. Both must be positive, else ArgumentError.

A transient failure — a status in the retryable set (408/429/500/502–504/520–524/529) or a GET that timed out — is polled through; any other failure is returned as it came. When the time runs out the result is a BatchCallError with cause = UniLMTimeout(:deadline, …) and last_observed set to the last BatchObject seen (nothing if no GET succeeded).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the poll cancellable: a cancel ends it at once, mid-GET or mid-pause, with a BatchCallError whose cause is a UniLMCancelled and last_observed as above; a token cancelled before the poll sends nothing.

Pass config::Union{Nothing,RequestConfig} to bound each GET (a single attempt; its total_deadline is capped at the time left).

UniLM.batch_resultsFunction#
batch_results(id; service=OPENAIServiceEndpoint, requests=nothing)

The results of the batch id, once it has ended: BatchResultsSuccess, whose results pair each request's custom id with its result, in the order the provider returns them (neither OpenAI nor Anthropic keeps the order of the requests; Gemini does), or the call's BatchFailure or BatchCallError.

Each result is what chatrequest! returns for its reply, decoded by the endpoint's decoder: an LLMSuccess whose usage names the tier "batch", so estimated_cost prices it at the provider's Batch rates; an LLMFailure for an OpenAI request answered with an HTTP error status; an LLMCallError for a request with no reply — its error holds the provider's error object as JSON (Anthropic's errored result, with its request_id; Gemini's status; an OpenAI error-file entry), or why there is none (an Anthropic request canceled or expired before it ran) — and for a reply the decoder cannot read.

Pass requests, the custom_id => Chat pairs that created the batch, and each result is the one chatrequest! returns for its request's Chat: a success's self is a copy of that Chat (fork) with the reply appended and the result's cost added to its cumulative_cost, so its conversation goes on, or runs its tool calls, from there; a failure's self is the request's Chat itself. The Chats passed are not changed. An empty or repeated custom id throws ArgumentError before any request, and a Chat whose reply could not be appended (history on, the conversation ending with an assistant message) throws InvalidConversationError, as chatrequest! does; a result whose custom id is none of the requests' is a BatchCallError. Without requests, a result's self is a stand-in Chat on service, without messages: its model is the one the provider names for the reply or the batch, else the endpoint's default model.

A batch of embeddings (OpenAI's "/v1/embeddings", Gemini's asyncBatchEmbedContent) has the results embeddingrequest! returns: an EmbeddingSuccess whose usage names the tier "batch", an EmbeddingFailure for an OpenAI request answered with an HTTP error status, and an EmbeddingCallError for a request with no reply (its error the provider's error object as JSON) or a reply that is no embedding. A success's embeddings is a stand-in Embeddings on service holding the vectors, one empty text per vector (a single one for a reply of one vector), its model the one the reply or the batch names; with requests, the custom_id => Embeddings pairs that created the batch, it is a copy of the request filled with them (the request is not changed), and a reply whose vectors do not fit its request is that request's EmbeddingCallError.

The results are read from OpenAI's output and error files (file_content: output lines, then error lines), Anthropic's results stream, and Gemini's inlined responses or its responses file. On OpenAI the batch is a "/v1/chat/completions" or "/v1/embeddings" one, as create_batch(requests) makes it: a batch of another endpoint is a BatchCallError whose ArgumentError names file_content(output_file_id), raised after the batch is read and before any file is downloaded. A batch with no results yet is a BatchFailure on Anthropic (its 404) and a BatchCallError naming the batch's status on OpenAI and Gemini; so is a batch that ended without results on either (the message holds OpenAI's errors, Gemini's error), and a Gemini response without the custom id create_batch sets in its metadata (key).

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried). The config bounds every request of the call together.

UniLM.delete_batchFunction#
delete_batch(id; service)

Delete the batch id on Anthropic or Gemini: BatchDeleteSuccess, BatchFailure or BatchCallError. Anthropic deletes a batch only once it has ended ("If you'd like to delete an in-progress batch, you must first cancel it"); Gemini answers a delete with an empty body, so the result names the batch the call deleted. OpenAI's Batch API has no delete: there delete_batch throws ArgumentError before any request.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

UniLM.update_batchFunction#
update_batch(id; priority, service)

Set the priority of the Gemini batch id (batches with a higher priority run first; negative values are allowed): BatchSuccess with the updated batch, BatchFailure or BatchCallError. Priority is the one field the API updates. A batch of embeddings is updated on updateEmbedContentBatch: the update goes there when updateGenerateContentBatch answers that the batch type does not match (HTTP 400), so it takes two requests. OpenAI's and Anthropic's Batch APIs update no batch: there update_batch throws ArgumentError before any request.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply).

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a BatchCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

Usage 

# Two requests, as Chats, on any of the three providers
ask(q) = Chat(service=ANTHROPICServiceEndpoint, model="claude-haiku-5-5", max_tokens=64,
              messages=[Message(Val(:user), q)])
batch = create_batch(["norway" => ask("Capital of Norway?"), "peru" => ask("Capital of Peru?")])
batch isa BatchSuccess || error("the batch was not created: $batch")

# Poll until it ends (Anthropic: "ended"), then read the results by custom id
done = poll_batch(batch.response.id; service=ANTHROPICServiceEndpoint, interval=60)
results = batch_results(batch.response.id; service=ANTHROPICServiceEndpoint)
if results isa BatchResultsSuccess
    for (id, r) in results.results
        r isa LLMSuccess && println(id, ": ", r.message.content, " (USD ", estimated_cost(r), ")")
    end
end

# With the requests, each result's self is its request's Chat with the reply appended: talk on
requests = ["norway" => ask("Capital of Norway?"), "peru" => ask("Capital of Peru?")]
batch = create_batch(requests)
poll_batch(batch.response.id; service=ANTHROPICServiceEndpoint, interval=60)
results = batch_results(batch.response.id; service=ANTHROPICServiceEndpoint, requests)
norway = Dict(results.results)["norway"]
if norway isa LLMSuccess
    push!(norway.self, Message(Val(:user), "And its population?"))
    chatrequest!(norway.self)
end

# A batch of embeddings (OpenAI or Gemini): one input per request on Gemini
docs = ["refunds" => Embeddings("Refunds take 5 days."; service=GEMINIServiceEndpoint, task=:document),
        "shipping" => Embeddings("Shipping is free in the EU."; service=GEMINIServiceEndpoint, task=:document)]
eb = create_batch(docs)
poll_batch(eb.response.id; service=GEMINIServiceEndpoint, interval=30)
vectors = batch_results(eb.response.id; service=GEMINIServiceEndpoint, requests=docs)
Dict(id => embedding_vectors(r) for (id, r) in vectors.results if r isa EmbeddingSuccess)

# OpenAI's file-based form: upload a JSONL request file, then create a batch from it
upload = upload_file("requests.jsonl", "batch")
openai_batch = create_batch(upload.response.id, "/v1/chat/completions"; output_expires_after=86_400)

# List jobs, cancel one, delete an ended one (Anthropic and Gemini)
list_batches(; limit=10, service=GEMINIServiceEndpoint)
cancel_batch(openai_batch.response.id)
delete_batch(batch.response.id; service=ANTHROPICServiceEndpoint)
