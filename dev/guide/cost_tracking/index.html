Language models · Concepts (every provider)

Cost Tracking

Every result of a token-billed call carries the token counts its provider reported, and UniLM turns those counts into a USD estimate. Each provider's usage is read into one shape, TokenUsage, when its reply is decoded, so the same code totals a bill on every provider; how a provider bills, and the prices UniLM holds for it, are on its entry.

Two accessors do the work: token_usage (raw counts) and estimated_cost (dollars). Chat additionally keeps a running total via cumulative_cost.

service, model = OPENAIServiceEndpoint, "gpt-5.4-mini"
own_model = "my-model"

The examples use only the names bound above. service and model are the provider and model they run on, and own_model names a model the price table does not hold, such as one of your own server: bind your own there. On an endpoint that treats its models as local, an estimate below is 0.0 unless you gave the model a price row (Local models). The table at the end links each provider's rules.

The zero-dollar footgun

estimated_cost returns 0.0 — with no error, only a warning logged once per model id — for any model that is not a key in DEFAULT_PRICING and has no fallback row, such as a model of your own server or one newer than the table. Cost tracking on it reports \$0.00 until you supply its price. See Unpriced models cost $0 below. A model its endpoint treats as local is the exception: with no row of yours, it costs 0.0 with no warning (Local models).

Reading usage and cost

token_usage returns a TokenUsage for every result of a token-billed call — chatrequest!, respond, embeddingrequest!, the image verbs, fim_complete, prefix_complete and ask — zero-filled for their failures and call errors; estimated_cost returns a Float64 in USD. Both throw ArgumentError for results of APIs that report no token usage (files, batches, audio, moderations, vector stores, …), where a zero would be indistinguishable from a free call. A real result comes back from chatrequest! / respond / embeddingrequest!, but the accessors are pure, so we build one here to keep the example deterministic and offline:

# Normally returned by chatrequest!; constructed here so the example needs no API call.
result = LLMSuccess(
    message = Message(Val(:user), "(assistant reply placeholder)"),
    self    = Chat(service=service, model=model),
    usage   = TokenUsage(prompt_tokens=1200, completion_tokens=350, cached_tokens=800),
)

u = token_usage(result)
println("prompt=$(u.prompt_tokens)  cached=$(u.cached_tokens)  completion=$(u.completion_tokens)")
println("cost USD = ", round(estimated_cost(result), digits=6))

By default the model priced is the one the result reports having served the call — result.model of a Chat result (LLMSuccess), where UniLM keeps the name the reply gives, and result.response.model of a respond, FIM or ask result — else the one requested: result.self.model for a Chat, result.embeddings.model for Embeddings. The model served can differ from the one requested: a provider that answers an alias with the dated snapshot behind it names the snapshot, which is priced at the alias's row. Each entry's first call says which model its results report. Override it explicitly when needed:

estimated_cost(result; model=model)   # priced as `model`, whatever served it

The decision providers' results — what ask returns — are priced as each one's entry says: the second table at the end links their cost sections.

How the estimate is computed

estimated_cost splits the prompt into fresh, cache-read and cache-written tokens and bills each at its own rate:

  • fresh input tokens × input
  • cache reads (cached_tokens) × cached_input, the discounted prompt-cache rate
  • cache writes (cache_write_tokens) × input
  • completion tokens × output

prompt_tokens counts every input token: cached_tokens and cache_write_tokens are subsets of it. These are the standard rates. Where UniLM models a provider's surcharges — a premium on cache writes (cache_write_extended_tokens counts the writes at the longer retention), a long-context tier, a multiplier for the service_tier or inference_geo the provider reports in TokenUsage — they apply to that provider's results, as its entry's cost section says; every other result is billed at the standard rates.

A price row holds no audio rates. A result whose usage counts audio tokens — prompt_audio_tokens and completion_audio_tokens, the audio parts of prompt_tokens and completion_tokens — is priced only where UniLM prices that model's audio, as its entry's cost section says; any other such result is estimated at 0.0, with one warning per model and endpoint, as for a model without a row, rather than its audio billed at text rates.

Reasoning tokens are already counted inside completion_tokens, so they carry no separate charge. Failures and call errors report zero usage and 0.0 cost. Image results report the usage their reply gives, but image tokens bill at rates a price row does not model: estimated_cost on an image result throws ArgumentError unless you pass model=, and a model= without a row is estimated at 0.0, with the no-row warning, so pass a pricing= row for it too.

A streamed Chat turn is priced like an unstreamed one where its provider reports the usage in the stream — on its own, or because the endpoint asks for it with stream_options = {"include_usage": true} when the Chat sets no stream_options; each entry says which, in its streaming section or the section of the endpoint it concerns. Elsewhere, set stream_options=Dict("include_usage" => true) where the server supports it, or the streamed turn reports no usage and accrues \$0. An embeddings reply that reports no usage is estimated at 0.0, with one warning per model.

The pricing table

DEFAULT_PRICING is a lock-guarded AbstractDict{String, PriceRow} (not a Dict), where a PriceRow is a NamedTuple of per-token USD rates: (input, cached_input, output). (Provider list prices are usually quoted per 1M tokens; the stored rows are those figures divided by 1,000,000.) Every Chat success prices itself against it — streaming ones on their own task — so it is safe to read and write from any task: add or replace a row with DEFAULT_PRICING[model] = row, and use get, haskey, delete!, pop!, keys and length as on a Dict. Iteration walks a snapshot, and copy, merge and filter return a plain Dict.

A model id is looked up exactly first, then without a dated snapshot suffix — -YYYY-MM-DD or -YYYYMMDD — so a snapshot is priced at its model's row. Only those date suffixes are stripped, so custom names stay unpriced rather than matching a row by accident. A provider's own fallback, where it has one, is on its entry.

priced = sort(collect(keys(DEFAULT_PRICING)))
println(length(priced), " models priced")
println(model, " row: ", DEFAULT_PRICING[model])

Unpriced models cost $0

If the model key is absent from the pricing table, estimated_cost returns 0.0 — it does not raise; it logs one warning per model id. (The dated-snapshot fallback above applies first.) This bites a model of your own server that its endpoint does not treat as local, or one newer than the table:

println(own_model, " priced? ", haskey(DEFAULT_PRICING, own_model))

unpriced = LLMSuccess(
    message = Message(Val(:user), "…"),
    self    = Chat(service=service, model=own_model),
    usage   = TokenUsage(prompt_tokens=100_000, completion_tokens=50_000),
)
println("estimated_cost with default pricing = \$", estimated_cost(unpriced))

150,000 tokens, and the estimate is still \$0.0. Always confirm your model is a key in the pricing table before trusting a cost number.

Local models

A model its endpoint treats as local bills no one, so it costs 0.0, with no warning, as that endpoint's entry says (a local model's cost), and cumulative_cost adds 0.0 for each turn — unless you price it. A row you give its exact name is used as any model's is: one in pricing= prices estimated_cost, and one you add to DEFAULT_PRICING prices both. The rows the table ships price hosted models only: a local model that bears a hosted model's name is not priced at that model's row, nor at its copy in a table such as merge(DEFAULT_PRICING, …), and a row equal to a shipped one counts as the shipped one. model= prices such a result at the row of the model it names.

Supplying custom pricing

Pass a pricing= dict (any AbstractDict{String, PriceRow}) to fix an unpriced (or mispriced) model. Build a PriceRow NamedTuple of per-token rates and merge it into the defaults — merge returns a new Dict and leaves DEFAULT_PRICING untouched:

# Fill in the provider's *current* list price (per 1M tokens); divide by 1_000_000.
pricing = merge(DEFAULT_PRICING, Dict(
    own_model => (input        = 2.00 / 1_000_000,
                  cached_input = 0.50 / 1_000_000,
                  output       = 8.00 / 1_000_000),
))

println("now priced? ", haskey(pricing, own_model))
println("cost USD = ", round(estimated_cost(unpriced; pricing), digits=6))

A row cannot price audio: a PriceRow has no audio-token rates. Whatever pricing= holds, a result whose usage counts audio tokens stays at 0.0 unless UniLM prices that model's audio, as its entry's cost section says.

Cumulative cost is Chat-only

cumulative_cost returns the running USD total that chatrequest! and prefix_complete accrue on a Chat. Accumulation happens only inside chatrequest! (both streaming and non-streaming paths, and so every turn of a tool_loop!) and prefix_complete — nothing else adds to the total:

chat = Chat(service=service, model=model)
push!(chat, Message(Val(:system), "You are helpful."))
push!(chat, Message(Val(:user), "Hello!"))
chatrequest!(chat)                     # cost accrues automatically

push!(chat, Message(Val(:user), "And again, in French."))
chatrequest!(chat)                     # accrues again

cumulative_cost(chat)                  # e.g. 0.00231  (USD, summed over both calls)

A call that ends without committing a turn adds what its provider reported billing it, as a lower bound. A stream stopped, cancelled, timed out or cut off, or ended by an exception from its callback or on_tool_call, adds the usage the provider had reported by then; where an entry knows when its provider reports usage, its streaming section says so. A request stopped before any usage arrived adds nothing, though the provider bills it; so do an attempt UniLM retried, a stream the provider ended with an error event, and an unstreamed reply UniLM could not decode.

Auto-accumulation always uses the default pricing table

chatrequest! prices each call with DEFAULT_PRICING; there is no pricing= for the running total. So a Chat on an unpriced model reports cumulative_cost == 0.0 even after successful calls — unless you add its row to the table (DEFAULT_PRICING[own_model] = row, safe while requests run), after which later calls accrue, on a model its endpoint treats as local too (Local models). Alternatively, ignore the running total and sum estimated_cost(result; pricing=…) yourself.

Totaling respond, tool-loop and embeddings costs

respond (ResponseSuccess), the respond tool loops, and Embeddings are not auto-accumulated. Sum estimated_cost over the results yourself:

# respond — one estimate per call, add them up.
r1 = respond("Summarize the Julia language in one line."; service, model)
r2 = respond("Now in French."; service, model)
responses_total = estimated_cost(r1) + estimated_cost(r2)   # USD

# Embeddings — price the batch result directly (the provider's default embedding model).
emb = Embeddings(["alpha", "beta", "gamma"]; service)
res = embeddingrequest!(emb)
embeddings_cost = estimated_cost(res)                       # USD for this batch

A respond tool loop sends a request per turn and keeps every turn's result, in order, as loop.responses (Inspecting the result): sum(estimated_cost, loop.responses) prices them all, while estimated_cost(loop.response) prices the last request alone. A tool_loop! on a Chat adds every turn to the Chat's cumulative_cost. Embedding models missing from the default table (one on your own server that its endpoint does not treat as local, for example) hit the same 0.0 behavior — supply pricing= for them too.

Prices drift

DEFAULT_PRICING is a hardcoded snapshot of the providers' list prices, and each entry with a price table says in its cost section when its rows were checked. Provider list prices change; re-verify against the provider's current pricing before relying on any number, and pass your own pricing= dict when you need authoritative figures.
