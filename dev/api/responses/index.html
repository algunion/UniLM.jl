Reference · API: language models

Responses API

Types and functions for the Responses API — the newer, more flexible alternative to Chat Completions.

Request Type

UniLM.RespondType#
Respond(; model="", input, kwargs...)

Configuration struct for an OpenAI Responses API request.

Key Fields

  • model::String: Model to use; "" (the default) resolves to the service's default model at construction ("gpt-6-sol" for OpenAI)
  • input::Any: A String or Vector{InputMessage} — the prompt input
  • instructions::String: System-level instructions
  • tools::Vector: Available tools (FunctionTool, WebSearchTool, FileSearchTool, …); a Chat Tool is converted to the equivalent FunctionTool
  • previous_response_id::String: Chain to a previous response for multi-turn; cannot be combined with conversation
  • background::Bool: Run in the background: get_response reads the response and cancel_response stops it. OpenAI takes store=false with it: "response data is temporarily stored to support asynchronous execution and polling" (background mode). Gemini Interactions (GEMINIServiceEndpoint) answers store=false with HTTP 400, so there it throws ArgumentError before any request
  • reasoning::Reasoning: Reasoning effort, summary, persisted context and mode (Reasoning)
  • text::TextConfig: Output format (text, json, json_schema)
  • temperature::Float64: Sampling temperature (0.0–2.0); OpenAI's reference recommends altering it or top_p "but not both", and a Respond that sets both sends both
  • top_p::Float64: Nucleus sampling (0.0–1.0)
  • max_output_tokens::Int64: Max tokens in the response, at least 1; a smaller value throws ArgumentError
  • top_logprobs::Int64: How many of the most likely tokens to return at each position, each with its log probability: 0 to 20, as OpenAI's reference gives; another value throws ArgumentError
  • stream::Bool: Enable streaming
  • truncation::String: "auto" or "disabled"
  • store::Bool: Whether to store the response for later retrieval
  • metadata::AbstractDict: Arbitrary metadata to attach
  • user::String: End-user identifier for other OpenAI-compatible servers; native OpenAI replaces it with safety_identifier and prompt_cache_key, so there it throws ArgumentError
  • service_tier::String: on OPENAIServiceEndpoint, "auto", "default", "flex", "scale", "fast" (or its former name "priority"), or "ultrafast", which OpenAI serves for gpt-6-astra and gpt-6.1-sol only; another value, or "ultrafast" on another OpenAI model, throws ArgumentError. On Gemini Interactions (GEMINIServiceEndpoint), "standard", "flex" or "priority", as on native Gemini Chat; another value throws ArgumentError, "deferred" among them: the API answered it with HTTP 400 on 2026-10-26, a tier "allowed on the Gemini Enterprise Agent Platform", and its reference no longer lists it. token_usage reports the tier that billed the call
  • prompt_cache_retention::String: "in_memory" or "24h"; OpenAI's reference says "for gpt-5.5, gpt-5.5-pro, and future models, only 24h is supported". UniLM sends the field unchecked on those two and on any model without a rule row. OpenAI deprecates the field: on gpt-6-astra, gpt-6.1-sol, gpt-6.1-terra, gpt-6-sol, gpt-6-luna, gpt-5.6 and gpt-5.6-sol/-terra/-luna (and their dated snapshots), whose cache lifetime prompt_cache_options sets, the native endpoint throws ArgumentError for any value
  • moderation::ModerationConfig: Moderated completions — see ModerationConfig
  • seed::Int64: decoding seed, for repeatable output. Gemini Interactions (GEMINIServiceEndpoint) sends it as generation_config.seed, an int32: a seed outside -2,147,483,648 to 2,147,483,647 throws ArgumentError before any request. A GenericOpenAIEndpoint sends it as given, as seed: vLLM's Responses API forwards a seed to its engine. OpenAI's Responses API has no seed (Chat Completions has one), so OPENAIServiceEndpoint and the other endpoints on the OpenAI Responses wire (Azure, GEMINIOpenAIServiceEndpoint) throw ArgumentError for it before any request, as does OllamaEndpoint, whose Responses API reads no seed

On OPENAIServiceEndpoint the encoder also applies OpenAI's per-model rules (reasoning efforts, sampling controls, prompt_cache_retention) to those GPT-6 and GPT-5.6 models, by exact id or a dated snapshot, before any request; other models are checked by the server. Ultrafast is served by gpt-6-astra and gpt-6.1-sol alone, so "ultrafast" throws ArgumentError on every other model, an unknown one included. See OpenAI's GPT-6 guide. Build a Respond with keywords: the positional form takes all 32 fields in declaration order.

Examples

# Simple text
Respond(input="Tell me a joke")

# With instructions
Respond(input="Translate to French: Hello", instructions="You are a translator")

# Multi-turn via chaining
Respond(input="Tell me more", previous_response_id="resp_abc123")

# With tools
Respond(
    input="What's the weather in NYC?",
    tools=ResponseTool[function_tool("get_weather", "Get weather", parameters=Dict("type"=>"object", "properties"=>Dict("location"=>Dict("type"=>"string"))))]
)

# Reasoning
Respond(input="Solve this math problem...", model="gpt-5.4-mini", reasoning=Reasoning(effort="high"))

Construction 

using UniLM
using JSON

# Simple text request
r = Respond(input="Tell me a joke")
println("Model: ", r.model)
println("Input: ", r.input)

# With instructions and tools
r2 = Respond(
    input="What's the weather in Paris?",
    instructions="You are a helpful weather assistant",
    tools=[web_search()]
)
println("Has instructions: ", !isnothing(r2.instructions))
println("Tools: ", length(r2.tools))

Response Object

UniLM.ResponseObjectType#
ResponseObject

Parsed response from the Responses API.

Accessors

  • output_text(r) — extract concatenated text output
  • function_calls(r) — extract function call outputs
  • r.id, r.status, r.model — basic metadata (through an OllamaEndpoint, a cloud model whose reply drops its tag keeps the requested name; the server's stays in r.raw)
  • r.output — full output array (raw dicts)
  • r.usage — token usage info
  • r.raw — the complete raw JSON dict

Result Types

UniLM.ResponseSuccessType#
ResponseSuccess <: LLMRequestResponse

Successful response from the Responses API. Access the parsed response via .response.

  • response: the parsed response (ResponseObject)
  • sse_dropped: undecodable SSE data: payloads dropped while assembling a streamed turn; 0 for a non-streamed call and for a clean stream
  • service: the endpoint that answered, used to price the call (a local model costs 0.0 unless you gave it a price row); nothing for a result built by hand, priced by its model name
UniLM.ResponseFailureType#
ResponseFailure <: LLMRequestResponse

A failure from the Responses API: an HTTP status other than 200, or a response whose status is "failed" (read by respond, get_response or cancel_response), whose status field is then 200. Contains the response body, status code, and optional request ID.

UniLM.ResponseCallErrorType#
ResponseCallError <: LLMRequestResponse

Exception-level error during a Responses API call (network, parsing, etc.).

Accessor Functions

UniLM.output_textFunction#
output_text(r::ResponseObject)::String
output_text(r::ResponseSuccess)::String

Extract the text of the response's answer: the output_text parts of its messages, joined by " ". A message the model labels phase: "commentary" — an intermediate update, such as a preamble before a tool call — is not part of the answer and is left out, so a turn that stops at its commentary has no text yet; a message without a phase counts. On a ResponseFailure or ResponseCallError it throws an LLMResultError — there is no model output to return; guard with issuccess.

Examples

result = respond("Hello!")
output_text(result)  # => "Hi there! How can I help?"

function_calls(r::ResponseObject)::Vector{Dict{String,Any}}

Extract function call outputs from a response.

Each dict contains: "id", "call_id", "name", "arguments" (JSON string), "status".

Examples

result = respond("What's the weather?", tools=[function_tool("get_weather", ...)])
for call in function_calls(result)

end

Request Functions

UniLM.respondFunction#
respond(r::Respond; config=nothing, callback=nothing, cancel=nothing)

Send r to the agentic API of r.service: the Responses API of OpenAI, of an OllamaEndpoint or a GenericOpenAIEndpoint server, or of an endpoint type of your own, or Gemini Interactions on GEMINIServiceEndpoint.

Returns ResponseSuccess, ResponseFailure, or ResponseCallError. Inside a with_recorded_answers scope the request passes through the recordings, streamed or not, and one the scope cannot replay throws ReplayMissError instead of returning a ResponseCallError; a streamed response whose recording cannot be written throws RecordingWriteError inside the returned task, so fetch raises a TaskFailedException whose task.exception is that error.

Per-call config::RequestConfig overrides timeouts and the retry budget (max_attempts); the process/scoped defaults apply otherwise.

For streaming, set stream=true and pass a callback:

callback(chunk::Union{String, ResponseObject}, close::Ref{Bool})

Setting close[] = true — in the callback or from any other task — stops the stream at once with ResponseCallError(status=nothing, cause=UniLMCancelled(:callback, …)), unless the provider's completion marker — the terminal event — already arrived: then the outcome it recorded stands (a response with its usage, whose final callback has already run; or the failure the event reported). An exception thrown by the callback ends the call with that exception in cause, never retried. Time spent in the callback does not count toward stream_idle_timeout. A user InterruptException during a stream is not swallowed — it rethrows inside the task and surfaces as a TaskFailedException at fetch — and neither is the ReplayMissError or RecordingWriteError of a recorded call made in the callback, nor either of them or an interrupt that the callback throws inside a wrapper (task.exception is what the callback threw).

cancel::Union{Nothing,CancelToken}: a CancelToken; nothing resolves the ambient token of with_cancel, at call entry. A cancel at any point — before connecting, during the response-header wait, mid-stream, or during a retry backoff — ends the call with ResponseCallError(status=nothing, cause=UniLMCancelled(:token, …)), never retried — unless the terminal event already arrived, as for close[] = true above. A pre-cancelled token sends nothing. A TCP connect or TLS handshake already in progress cannot be interrupted (HTTP.jl 2.7.1), so a cancel during one takes effect when it completes or reaches connect_timeout.

Local validation throws ArgumentError before any network I/O, streaming or not: when callback is passed without r.stream === true (it runs only on a stream, so it would be ignored), when r.service is an endpoint type that declares its capabilities and lists neither :responses (OpenAI wire) nor :agentic (Gemini Interactions), or when the provider's encoder rejects the request (e.g. an option the provider or model does not support). A streamed call on an endpoint type with no decode_agentic_stream method throws that function's MethodError before any network I/O too, as a streamed chatrequest! does for a missing handle_sse_event!.

Examples

r = Respond(input="Tell me a joke")
result = respond(r)
if result isa ResponseSuccess
    println(output_text(result))
end

respond(input; kwargs...)

Convenience method: create a Respond from input + keyword arguments and send it.

Examples

# Simple text
result = respond("Tell me a joke")

# With instructions and model
result = respond("Translate: Hello", instructions="You are a translator", model="gpt-5.6-sol")

# With tools
result = respond("Search for Julia news", tools=[web_search()])

# Multi-turn
r1 = respond("Tell me a joke")
r2 = respond("Tell me another", previous_response_id=r1.response.id)

# Streaming
respond("Tell me a story", stream=true) do chunk, close
    if chunk isa String
        print(chunk)  # partial text delta
    end
end

respond(callback::Function, input; kwargs...)

do-block form for streaming. Automatically sets stream=true.

Examples

respond("Tell me a story") do chunk, close
    if chunk isa String
        print(chunk)
    elseif chunk isa ResponseObject
        println("\nDone! Status: ", chunk.status)
    end
end
UniLM.get_responseFunction#
get_response(response_id::String; service=OPENAIServiceEndpoint)

Retrieve an existing response by its ID: a ResponseSuccess, or a ResponseFailure when the response's status is "failed", as respond returns it. OpenAI keeps a stored response (store=true, the default) "for at least 30 days, subject to the data retention exceptions"; the data of a background request made with store=false is "temporarily stored to support asynchronous execution and polling", and OpenAI's background guide names two exceptions: a Zero Data Retention project's "Background requests … run with store=false", their data kept "for roughly 10 minutes", and in a Modified Abuse Monitoring project "Background responses are retained after the polling period only when store=true is explicitly provided" (background mode). get_response reads a response while OpenAI holds it, and not once it is deleted. An endpoint whose Responses API stores no responses (OllamaEndpoint) throws ArgumentError before any request. Inside a with_recorded_answers scope the request passes through the recordings: one the scope cannot replay throws ReplayMissError, and an answer whose recording cannot be written throws RecordingWriteError, instead of returning a ResponseCallError.

Examples

result = get_response("resp_abc123")
if result isa ResponseSuccess
    println(output_text(result))
end
UniLM.delete_responseFunction#
delete_response(response_id::String; service=OPENAIServiceEndpoint)

Delete a stored response by its ID. Returns a Dict with "id", "object", "deleted" keys. An endpoint whose Responses API stores no responses (OllamaEndpoint) throws ArgumentError before any request. Inside a with_recorded_answers scope the request passes through the recordings: one the scope cannot replay throws ReplayMissError, and an answer whose recording cannot be written throws RecordingWriteError, instead of returning a ResponseCallError.

Examples

result = delete_response("resp_abc123")
result["deleted"]  # => true
UniLM.list_input_itemsFunction#
list_input_items(response_id::String; limit=20, order="desc", after=nothing, service=OPENAIServiceEndpoint)

List input items for a stored response. Returns a Dict with "data", "first_id", "last_id", "has_more". An endpoint whose Responses API stores no responses (OllamaEndpoint) throws ArgumentError before any request, and so does GEMINIServiceEndpoint: Google's Interactions API gets, cancels and deletes an interaction, and has no method that lists its input items. Inside a with_recorded_answers scope the request passes through the recordings, keyed with its limit, order and after: one the scope cannot replay throws ReplayMissError, and an answer whose recording cannot be written throws RecordingWriteError, instead of returning a ResponseCallError.

Examples

items = list_input_items("resp_abc123")
for item in items["data"]
    println(item["type"], ": ", item)
end
UniLM.cancel_responseFunction#
cancel_response(response_id::String; service=OPENAIServiceEndpoint)

Cancel an in-progress response by its ID. Returns ResponseSuccess with the response it read back, or a ResponseFailure when that response's status is "failed", as respond does. An endpoint whose Responses API stores no responses (OllamaEndpoint) throws ArgumentError before any request. Inside a with_recorded_answers scope the request passes through the recordings: one the scope cannot replay throws ReplayMissError, and an answer whose recording cannot be written throws RecordingWriteError, instead of returning a ResponseCallError.

Examples

# Start a background response, then cancel it
result = respond("Write a very long essay", background=true)
cancel_result = cancel_response(result.response.id)
if cancel_result isa ResponseSuccess
    println("Cancelled: ", cancel_result.response.status)
end
UniLM.compact_responseFunction#
compact_response(; model, input, kwargs...)

Compact a conversation by running a compaction pass. Returns opaque, encrypted items that can be passed as input to subsequent requests, reducing token usage in long conversations.

Fields

  • model::Union{String,Nothing}: Model to use for compaction; nothing (the default) is OpenAI's default model, "gpt-6-sol", on every service but an OllamaEndpoint, which has no default model and needs one named: a call to it without one throws ArgumentError before any request
  • input::Any: The conversation items to compact (typically the full conversation history)

Returns a Dict with "id", "object", "output", and "usage" keys. Inside a with_recorded_answers scope the request passes through the recordings: one the scope cannot replay throws ReplayMissError, and an answer whose recording cannot be written throws RecordingWriteError, instead of returning a ResponseCallError.

Examples

compacted = compact_response(model="gpt-5.6-sol", input=[
    InputMessage(role="user", content="Hello"),
    Dict("type" => "message", "role" => "assistant", "status" => "completed",
         "content" => [Dict("type" => "output_text", "text" => "Hi there!")])
])
# Use compacted["output"] as input to the next request
UniLM.count_input_tokensFunction#
count_input_tokens(; model, input, kwargs...)

Count the number of input tokens a request would use without actually generating a response. Useful for estimating costs or checking whether input fits within the context window. model defaults to OpenAI's default model, "gpt-6-sol".

Returns a Dict with "object" ("response.input_tokens") and "input_tokens" keys. Inside a with_recorded_answers scope the request passes through the recordings: one the scope cannot replay throws ReplayMissError, and an answer whose recording cannot be written throws RecordingWriteError, instead of returning a ResponseCallError.

Examples

result = count_input_tokens(model="gpt-5.6-sol", input="Tell me a joke")
println("Input tokens: ", result["input_tokens"])

Input Helpers

UniLM.InputMessageType#
InputMessage(; role, content, phase=nothing)

A structured input message for the Responses API.

Fields

  • role::String: "user", "assistant", "system", or "developer"
  • content::Any: String or a vector of content parts (see input_text, input_image, input_file). Gemini Interactions (respond on GEMINIServiceEndpoint) also takes an ImageAttachment, AudioAttachment or DocumentAttachment as a part, sent as an Interactions image, audio or document part; the OpenAI Responses wire takes no attachment (an image goes as input_image with a data URL, a document as input_file(document))
  • phase::Union{String,Nothing}: on an assistant message you replay, the phase the model gave it in r.response.output: "commentary" for an intermediate update (such as a preamble before a tool call) or "final_answer". OpenAI asks callers to "preserve and resend phase on all assistant messages"; dropping it "can degrade performance". Any other value, or a phase on another role (which the API does not read), throws ArgumentError.

Examples

InputMessage(role="user", content="What is 2+2?")
InputMessage(role="user", content=[input_text("Describe this:"), input_image("https://example.com/img.png")])
InputMessage(role="assistant", content="I'll check the logs first.", phase="commentary")
UniLM.input_textFunction#
input_text(text::String; cache_breakpoint=false, cache_ttl=nothing)

Create an input_text content part for multimodal input messages.

cache_breakpoint=true marks the end of this block as an explicit prompt-cache breakpoint (GPT-5.6 and later) by adding prompt_cache_breakpoint: {"mode": "explicit"}. OpenAI's prompt-caching guide: "mark each desired breakpoint by adding prompt_cache_breakpoint: { "mode": "explicit" } to a supported content block inside an input message." Pair it with PromptCacheOptions(mode="explicit") to cache only the prefixes you mark.

cache_ttl gives this breakpoint its own cache lifetime, "30m" or "12h" (the Responses API's), in place of the request's prompt_cache_options ttl: "Set prompt_cache_breakpoint.ttl to override it for an individual explicit breakpoint." It needs cache_breakpoint=true; another value, or a ttl without a breakpoint, throws ArgumentError. See OpenAI prompt caching.

UniLM.input_imageFunction#
input_image(url=nothing; detail=nothing, file_id=nothing)

Create an input_image content part. Provide either an image url or a file_id. detail can be "auto" (the API's default), "low", "high" or "original".

UniLM.input_fileFunction#
input_file(; url=nothing, id=nothing, file_data=nothing, filename=nothing)

Create an input_file content part. Provide a url, a file id, or inline file_data (base64). filename is recommended when passing file_data.

input_file(document::DocumentAttachment)

The input_file content part of a DocumentAttachment: file_data is the PDF as a base64 data URL ("data:application/pdf;base64,…", the form OpenAI's file inputs guide sends) and filename the document's name — the same Dict as input_file(; file_data=…, filename=document.filename). OllamaEndpoint's Responses API documents no file inputs and refuses an input_file part before any request.

UniLM.configuration_updateFunction#
configuration_update(; effort::String)

Build a configuration_update input item, {"type": "configuration_update", "reasoning": {"effort": effort}}, that changes the reasoning effort of this and later responses without rewriting the request-level reasoning.effort, so the cached prompt prefix stays reusable. Place it in input before the next user message. Supported by the GPT-6 model family in standard, single-agent requests; the API rejects two adjacent updates. effort must be one of "none", "minimal", "low", "medium", "high", "xhigh", "max". See Change reasoning mid-conversation.

Multimodal Input 

# Text-only input
msg = InputMessage(role="user", content="What is Julia?")
println("Role: ", msg.role)

# Multimodal input
parts = [
    input_text("Describe this image:"),
    input_image("https://example.com/photo.jpg", detail="high")
]
println("Parts: ", length(parts))
println("Part types: ", [p[:type] for p in parts])

UniLM.ResponseToolType#
ResponseTool

Abstract supertype for Responses API tools. Subtypes: FunctionTool, WebSearchTool, FileSearchTool, MCPTool, ComputerTool, ImageGenerationTool, CodeInterpreterTool, ShellTool, ApplyPatchTool and CustomTool.

UniLM.FunctionToolType#
FunctionTool(; name, description=nothing, parameters=nothing, strict=nothing,
             async=nothing, allowed_callers=nothing, defer_loading=nothing, output_schema=nothing)

A function tool for the Responses API.

  • async: true lets the model keep working while your application runs the tool; return its result later with the original call_id (GPT-6 models).
  • allowed_callers: invocation contexts, "direct" and/or "programmatic"; any other value throws ArgumentError.
  • defer_loading: true defers the definition until the model loads it via tool search.
  • output_schema: JSON Schema of the JSON value encoded in the tool's string output.

Unset fields are omitted from the request.

Examples

FunctionTool(
    name="get_weather",
    description="Get current weather for a location",
    parameters=Dict(
        "type" => "object",
        "properties" => Dict(
            "location" => Dict("type" => "string", "description" => "City name")
        ),
        "required" => ["location"]
    )
)

WebSearchTool(; type="web_search", search_context_size="medium", user_location=nothing, filters=nothing)

A web search tool for the Responses API. Allows the model to search the web.

UniLM.MCPToolType#
MCPTool(; server_label, server_url=nothing, connector_id=nothing, authorization=nothing,
        server_description=nothing, require_approval="never", allowed_tools=nothing,
        headers=nothing, tunnel_id=nothing)

A Model Context Protocol (MCP) tool for the Responses API. Connect the model to a remote MCP server (server_url), an OpenAI connector (connector_id, e.g. "connector_googledrive", "connector_gmail", "connector_dropbox"), or a Secure MCP Tunnel (tunnel_id). Connectors are OpenAI's legacy connectors: connector_id "is deprecated for models released after September 1, 2026", which take server_url or tunnel_id, and "Existing models retain connector support" (connectors and MCP). UniLM.ImageGenerationToolType#
ImageGenerationTool(; background=nothing, output_format=nothing, output_compression=nothing,
                    quality=nothing, size=nothing, model=nothing, action=nothing,
                    moderation=nothing, partial_images=nothing, input_fidelity=nothing,
                    input_image_mask=nothing)

An image generation tool for the Responses API. Allows the model to generate images inline during a response.

  • model: image model, e.g. "gpt-image-2", "gpt-image-2.5-flare", "gpt-image-2.5-sunburst"
  • action: "generate", "edit", or "auto"
  • moderation: "auto" or "low"
  • partial_images: partial images to stream before the final image, 0–3
  • input_fidelity: "high" or "low" — how closely edits preserve input images (omit it for gpt-image-2, which always uses high fidelity)
  • input_image_mask: inpainting mask, Dict("file_id" => …) or Dict("image_url" => …)
  • quality: "low", "medium", "high", "auto"; the 2.5 models add "xhigh" and "max"

action, moderation, partial_images, and input_fidelity are validated at construction (ArgumentError). quality, background, and output_format are passed through unchecked (the accepted quality values depend on the model). Unset fields are omitted from the request.

UniLM.CodeInterpreterToolType#
CodeInterpreterTool(; container=Dict("type" => "auto"), file_ids=nothing)

A code interpreter tool for the Responses API. Allows the model to execute code in a sandboxed environment: the container OpenAI's tool requires. By default it is an auto container ({"type": "auto"}), which OpenAI creates or reuses; a Dict is sent as given (e.g. Dict("type" => "auto", "memory_limit" => "4g")), and a String is the id of a container created beforehand (create_container). file_ids are sent inside the auto container; with a container id, or beside a container Dict that names file_ids already, they are an ArgumentError.

Reasoning, Prompt Caching & Moderation

UniLM.ReasoningType#
Reasoning(; effort=nothing, summary=nothing, generate_summary=nothing, context=nothing, mode=nothing)

Reasoning configuration for OpenAI and Gemini Interactions models.

  • effort: OpenAI accepts "none", "minimal", "low", "medium", "high", "xhigh", and "max" — any other value throws ArgumentError at construction; each model supports a subset (gpt-5.4-mini stops at "xhigh"). For gpt-6-astra, gpt-6.1-sol, gpt-6.1-terra, gpt-6-sol, gpt-6-luna, gpt-5.6 and gpt-5.6-sol/-terra/-luna (and their dated snapshots) the native OpenAI endpoint checks the effort before the request: the Responses API takes "low" to "max" on GPT-6 Astra and GPT-6.1 Sol and "none" to "max" on the others, so "minimal" (and "none" on Astra and 6.1 Sol) throws ArgumentError pointing to "low". Other models are checked by the server. Gemini 3.8 supports "low", "medium", and "high".
  • summary: "auto", "concise", or "detailed" — request a reasoning summary in the output.
  • generate_summary: deprecated alias serialized as summary; prefer summary. Gemini Interactions accepts summary="auto" for thought summaries.
  • context: OpenAI persisted reasoning: "auto", "current_turn", or "all_turns".
  • mode: OpenAI "standard" or "pro" execution; pro can consume more tokens.
UniLM.PromptCacheOptionsType#
PromptCacheOptions(; mode=nothing, ttl=nothing, prewarm=nothing, comparison_response_id=nothing)

Prompt-cache controls (OpenAI: GPT-5.6 and later; Anthropic). mode is "implicit" or "explicit"; ttl, how long a cached prefix is kept, is one of "5m" or "1h" (Anthropic's lifetimes), "30m" or "12h" (OpenAI's) — any other value throws ArgumentError. Each native endpoint takes its own subset and throws ArgumentError naming it, before any request:

  • OPENAIServiceEndpoint: Chat Completions takes "30m" (the API answers HTTP 400 for any other ttl); the Responses API (Respond) and OpenAI Decisions take "30m" and "12h".
  • ANTHROPICServiceEndpoint: a top-level cache_control (automatic caching) with ttl "5m" or "1h" and mode "implicit" or unset; prewarm=true and comparison_response_id throw.
  • Native Gemini (Chat and Interactions) and OllamaEndpoint refuse prompt_cache_options.
  • Azure, the Gemini OpenAI-compatible endpoint, DeepSeek and other OpenAI-compatible endpoints send the object unchanged: the server's answer is the check.

Explicit mode caches only prefixes marked with prompt_cache_breakpoint in input content blocks (see input_text with cache_breakpoint=true).

Responses API only:

  • prewarm=true prepares the prompt cache without generating output; send the real request afterwards with the same prefix and prewarm unset.
  • comparison_response_id requests prompt-cache diagnostics against an earlier response; they come back in r.response.raw["prompt_cache_diagnostics"].

Chat Completions accepts only mode and ttl: a Chat for OPENAIServiceEndpoint with prewarm or comparison_response_id set throws ArgumentError when encoded. Message content is a plain string, so a Chat cannot mark cache breakpoints, and per the Chat Completions reference an explicit-mode request without one "does not use prompt caching": a Chat with mode="explicit" throws ArgumentError when it is built, whatever its endpoint. Unset fields are omitted from the request. See OpenAI prompt caching.

UniLM.ModerationConfigType#
ModerationConfig(; model, input_mode=nothing, output_mode=nothing)

OpenAI moderated completions for Chat and Respond: the required moderation model (e.g. "omni-moderation-latest") checks the request input and the generated output. The optional input_mode / output_mode set the policy per side: "score" or "block". Serialized as {"model": …, "policy": {"input": {"mode": …}, "output": {"mode": …}}} with unset policy parts omitted. A respond result carries the outcome in r.response.raw["moderation"] ("input" and "output" moderation results), and a chatrequest! result in its moderation (LLMSuccess). See the moderation parameter of Create a model response.

reasoning = UniLM.Reasoning(effort="high")
println("Effort: ", reasoning.effort)
