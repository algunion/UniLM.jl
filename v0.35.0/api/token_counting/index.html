Token Counting

count_tokens asks a provider how many input tokens a request would bill, without running it: the request object the generation verb takes, encoded as that verb encodes it.

ProviderRequestRouteTotal
OpenAIa RespondPOST /v1/responses/input_tokensinput_tokens
Anthropica ChatPOST /v1/messages/count_tokensinput_tokens
Geminia Chat on GEMINIServiceEndpointPOST /v1beta/models/{model}:countTokenstotalTokens
chat = Chat(service=ANTHROPICServiceEndpoint, model="claude-haiku-5-5", messages=[Message(Val(:user), "Hello")])
r = count_tokens(chat)
r isa TokenCountSuccess && r.input_tokens
# Counted on 16 November 2026: 11

Each count sends the generation body without the fields the counting route does not take, which bound or deliver the output, name the end user, or pick a tier, a region or a stored copy, and so change no input token. On Anthropic those are max_tokens, stop_sequences, stream, metadata, service_tier and inference_geo; an endpoint with betas counts on the beta route, its betas and token-counting-2024-11-01 in the anthropic-beta header. On Gemini the count takes the whole generateContent body, tools, system instruction and generation config included. On OpenAI it takes the input, the instructions, the tools and the tool choice, the previous response or conversation, the reasoning, the text format and the truncation; a Respond that sets context_management or image_context_compression, each of which changes the input the model reads, throws ArgumentError. OpenAI counts no Chat, and Gemini's Interactions API (a Respond on Gemini) has no count: either throws ArgumentError before any request, as an endpoint without the :token_count capability does.

Anthropic's token counting "is free to use" (Token counting); OpenAI and Google publish no price for theirs, and no count reports a usage. A count is not recorded by with_recorded_answers: inside a scope it goes to the provider. Gemini's reply also gives the tokens per modality (promptTokensDetails), which stay in raw. count_input_tokens counts on OpenAI's route by keyword and returns the reply as a Dict.

UniLM.count_tokensFunction#
count_tokens(request::Union{Chat,Respond}; config=nothing, cancel=nothing)

How many input tokens request would bill, counted by its provider without generating:

  • a Chat on ANTHROPICServiceEndpoint (POST /v1/messages/count_tokens): the body chatrequest! sends, without max_tokens, stop_sequences, stream, metadata (the user id), service_tier and the endpoint's inference_geo, which the count does not take and which do not change the input. An endpoint with betas counts on the beta route: its betas and token-counting-2024-11-01 in the anthropic-beta header, as Anthropic's SDK sends them; one without sends no beta header.
  • a Chat on GEMINIServiceEndpoint (models.countTokens): the whole generateContent body, system instruction, tools and generation config included, as its generateContentRequest.
  • a Respond on OPENAIServiceEndpoint (POST /v1/responses/input_tokens): the body respond sends, without its output, delivery, storage, tier, caching, end-user and moderation fields, which the count does not take. A Respond with context_management or image_context_compression throws ArgumentError: each changes the input the model reads, and the count takes neither. count_input_tokens counts on the same route by keyword, and sends personality, which a Respond does not hold.

The encoder's own refusals hold, as in the generation verb. Any other pairing throws ArgumentError before any request, naming what the provider counts: OpenAI counts no Chat, and Gemini's Interactions API (a Respond on Gemini) has no count; so does an endpoint without the :token_count capability.

Returns a TokenCountSuccess (input_tokens, and raw, the reply), a TokenCountFailure for an error status, or a TokenCountCallError, which is also what a missing key gives (it names the variable) and what a reply without its count gives. config (a RequestConfig) bounds the call and its retries of the retryable statuses; cancel (default: the ambient with_cancel token) ends it with a UniLMCancelled in cause. A count is not recorded by with_recorded_answers: inside a scope it goes to the provider, as outside one.

chat = Chat(service=ANTHROPICServiceEndpoint, model="claude-haiku-5-5", messages=[Message(Val(:user), "Hello")])
r = count_tokens(chat)
issuccess(r) && r.input_tokens   # 11
UniLM.TokenCountSuccessType#
TokenCountSuccess

Successful count_tokens result:

  • input_tokens::Int: the input tokens the request would bill — OpenAI's and Anthropic's input_tokens, Gemini's totalTokens;
  • raw::Dict{String,Any}: the reply as the provider sent it, with what one provider adds: Gemini's per-modality promptTokensDetails.
UniLM.TokenCountFailureType#

count_tokens error result: HTTP status, the raw response body, and the request_id the provider sent (x-request-id/request-id header), if any.

UniLM.TokenCountCallErrorType#

count_tokens call that produced no count (a missing key, no connection, a timeout, a cancel, or a reply that is not the documented count); cause is the underlying exception — a UniLMTimeout for a timeout, a UniLMCancelled for a cancel.
