Mistral & OpenAI-compatible services

Mistral makes the Mistral models — Mistral Large, Codestral, Mistral Embed, the Voxtral audio models and others — and serves them through its own API. MistralEndpoint() is a GenericOpenAIEndpoint on Mistral's host, https://api.mistral.ai: UniLM speaks Mistral's chat, embeddings, FIM and transcription routes as OpenAI-compatible ones, and a hosted service of another vendor with an OpenAI-compatible API is reached the same way, with GenericOpenAIEndpoint(base_url, key). The rules on this page are that endpoint's; the facts marked as Mistral's are Mistral's alone. UniLM holds no rule of Mistral's or of any other service: it sends every field a request sets as it is, under its own name but for those First call lists, and sends the requests of the capabilities the table below lists without knowing whether the service serves them. A verb that needs a capability the table lists as not available refuses the endpoint, and so does ask; respond, which takes responses or agentic, and transcribe, which takes transcription or audio, are sent. Of Mistral's API, UniLM does not use the Agents and Conversations APIs, OCR or the classifiers either. Servers of your own have their entry: vLLM, LM Studio & llama.cpp. No Mistral key was at hand for this page: its examples are not run, and their code stands without output.

Setup

Set your Mistral API key in the environment Julia starts from:

export MISTRAL_API_KEY="..."

MistralEndpoint() is GenericOpenAIEndpoint("https://api.mistral.ai", "", "MISTRAL_API_KEY"), and prints as that call. It reads the variable each time a request is built, so the endpoint can be made before the key is set, and a call without it returns a call-error result whose cause is the KeyError naming it; MistralEndpoint(api_key="…") sends the key it is given instead. The key goes as Authorization: Bearer, the header Mistral documents (chat completions). MistralEndpoint is a constructor with no type of its own: an error names GenericOpenAIEndpoint, and code cannot dispatch on Mistral.

Another service's endpoint takes the root of its API and a key, given or read from a variable:

mistral = MistralEndpoint()
service = GenericOpenAIEndpoint("https://api.example.com", "", "EXAMPLE_API_KEY")

Under the root, without /v1, UniLM sends a Chat to /v1/chat/completions, an Embeddings request to /v1/embeddings, transcribe to /v1/audio/transcriptions and respond to /v1/responses, and drops a trailing /; fim_complete goes to Mistral's /v1/fim/completions on Mistral's host, and to /v1/completions on any other. A service whose routes are not those cannot be reached through this endpoint; a backend of your own can reach it (Write your own backend). A key given as "", or a variable holding "", sends no Authorization header. The endpoint has no default model: every request names the model the service serves under that name (Models), or is refused (Limits and refusals).

First call

A Chat starts with its system message; chatrequest! sends it and returns a typed result, and text reads the reply — or throws, on a failure:

chat = Chat(service=MistralEndpoint(), model="mistral-large-latest")
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "In one sentence: what is a prime number?"))
result = chatrequest!(chat)
text(result)
result.model, result.message.finish_reason, result.usage

The reply is read as a Chat Completions reply: result.model is the model the service reports, and finish_reason and usage are read as the OpenAI-compatible API defines them. No Mistral model has a price row, so the first chatrequest! logs a warning and the call costs 0.0 (Cost and usage).

An unstreamed reply's reasoning is not kept. A content that is a list of chunks, the shape Mistral's reasoning models answer in with reasoning_effort="high" — a thinking chunk, then the answer's text chunks (reasoning) — is read as its text chunks joined, and its thinking chunks are dropped: reasoning_text gives nothing. A streamed reply keeps them (Streaming).

Fields go out under the names of the Chat, but on Mistral's host a max_completion_tokens goes out as max_tokens, taken over a max_tokens also set, the name Mistral's chat reference gives the cap (chat completions), and a seed as random_seed, "The seed to use for random sampling", the name it gives the seed; any other service gets both as the Chat names them. Mistral's safe_prompt, min_tokens, prompt_mode and guardrails are not Chat fields (chat completions). What Mistral does with a field its reference does not list is untested.

Conversations

A Chat keeps the conversation: each reply is appended to it, and the next chatrequest! sends the whole conversation again; a system message pushed after the conversation started is sent in place.

push!(chat, Message(Val(:user), "And a composite number?"))
text(chatrequest!(chat))

A reply's reasoning never goes back with a later turn: an unstreamed reply keeps none (First call), and the reasoning a streamed one keeps is not sent. What push! refuses is the same on every provider (Chat Completions).

Streaming

With stream=true, chatrequest! returns a Task at once, and fetch gives the same typed result as an unstreamed call; the callback receives the text as it arrives, then the assembled Message:

chat = Chat(service=MistralEndpoint(), model="mistral-large-latest", stream=true)
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "List the planets of the solar system in order, one per line."))
task = chatrequest!(chat; callback=(chunk, close) -> chunk isa String && print(chunk))
text(fetch(task))

A Chat on this endpoint sends no stream_options unless it sets them, a field Mistral's chat reference does not list; whether Mistral's stream reports its usage unasked is untested, and a stream without usage adds 0.0 to cumulative_cost. The stream is the Chat Completions one: the turn is final at data: [DONE], or, without one, when the HTTP body ends after the finish reason; on_tool_call(tc) runs once per call whose arguments decode, as the next call begins or at the end of the stream; and setting close[] = true stops it (Stopping a Stream Early).

A delta whose content is a list of chunks is read chunk by chunk. Mistral streams a reasoning reply's thinking in such lists, then "a single list containing both a closing ThinkChunk and the first TextChunk", then the answer as strings (reasoning): the text chunks reach the callback and the final Message in order, and the thinking chunks are kept apart as the turn's reasoning, which reasoning_text reads once the finish reason or data: [DONE] has arrived; a stream cut before then keeps none. No thinking reaches the callback. The concepts every provider shares are on Streaming.

Tools

Each Tool in tools goes out as a function tool, and tool_choice, parallel_tool_calls and a tool's strict go as they are set; a Chat with tools sends parallel_tool_calls: false unless it sets another value, where Mistral's own default is true. Mistral's tool_choice takes "auto", "none", "any", "required" or a function: "any or required means the model must call one or more tools" (chat completions). tool_loop! runs the calls and sends their results back until the model answers in text:

weather = UniLM.CallableTool(
    Tool(func=FunctionSignature(name="get_weather", description="Current weather in a city",
        parameters=Dict("type" => "object", "required" => ["city"],
                        "properties" => Dict("city" => Dict("type" => "string"))))),
    (name, args) -> "18°C and sunny in $(args["city"])")
chat = Chat(service=MistralEndpoint(), model="mistral-large-latest", tools=[weather])
push!(chat, Message(Val(:system), "You are concise."))
push!(chat, Message(Val(:user), "What is the weather in Lyon? Use the tool, then answer in one sentence."))
loop = tool_loop!(chat; tools=[weather])
text(loop.response)

The loop every provider shares is on Tool Calling.

Structured output

A JSON Schema response_format goes out as {"type": "json_schema", "json_schema": {"name": …, "schema": …}}, and UniLM.json_object() as {"type": "json_object"}; the service constrains the reply. On Mistral, json_schema "guarantees the message the model generates is in JSON and follows the schema you provide", and with json_object "you MUST also instruct the model to produce JSON yourself with a system or a user message" (chat completions):

using JSON
schema = Dict("type" => "object", "additionalProperties" => false, "required" => ["name", "year"],
              "properties" => Dict("name" => Dict("type" => "string"), "year" => Dict("type" => "integer")))
chat = Chat(service=MistralEndpoint(), model="mistral-large-latest",
            response_format=UniLM.json_schema("person", "A person", schema))
push!(chat, Message(Val(:system), "You extract facts."))
push!(chat, Message(Val(:user), "Extract the person: Ada Lovelace, born 1815."))
JSON.parse(text(chatrequest!(chat)))

The formats every provider shares are on Structured Output.

Attachments

A user message's attachments go out as content parts: an image as an image_url part, with its detail when one is set, a sound clip as an input_audio part, and a document as a file part holding its name and a data URL. The service decides what it reads, and UniLM checks none of it before sending. The attachments every provider shares are on Attachments.

Embeddings

An Embeddings request goes to /v1/embeddings with the texts, the model and the fields it sets:

emb = Embeddings(["first text", "second text"]; service=MistralEndpoint(), model="mistral-embed")
r = embeddingrequest!(emb)
length(embedding_vectors(r)), length(first(embedding_vectors(r)))

Mistral's embeddings route takes input, model, output_dimension, output_dtype, encoding_format and metadata (embeddings). On Mistral's host an Embeddings request's dimensions goes out as output_dimension, "The dimension of the output embeddings when feature available", and on any other service as dimensions; its effect on Mistral is untested. Each item is text: an image or a sound clip is refused before the request (Limits and refusals). The concepts every provider shares are on Embeddings.

Audio

transcribe sends the recording and the fields a request sets to /v1/audio/transcriptions, as a multipart form, and reads a JSON reply's text:

heard = transcribe("memo.wav"; service=MistralEndpoint(), model="voxtral-mini-latest", language="en")
transcript_text(heard)

Mistral's route takes the file, a model it marks required, a language ("Providing the language can boost accuracy"), temperature, timestamp_granularities, context_bias and diarize (transcriptions); a request's prompt and response_format, which that reference does not list, go out as set, untested. The endpoint has no default transcription model, so a call names one (Limits and refusals). transcribe is sent again after a transient status, as a Chat is, whole each time (When something fails).

FIM completion

On Mistral's host, fim_complete goes to /v1/fim/completions, Mistral's fill-in-the-middle route, and reads each choice's message.content, the chat shape Mistral answers in; on another host it goes to /v1/completions and reads each choice's text. A request names a model with FIM, Codestral on Mistral:

fim = fim_complete("def fib(n):"; suffix="    return fib(n - 1) + fib(n - 2)",
                   service=MistralEndpoint(), model="codestral-latest", max_tokens=64)
fim_text(fim)

Mistral's FIM route takes model, prompt, suffix, max_tokens, min_tokens, stop, temperature, top_p, random_seed, stream, prompt_cache_key and metadata (FIM). A FIMCompletion sends max_tokens 128 unless it sets another value, has no streaming path (Limits and refusals), and sends its echo, logprobs, frequency_penalty and presence_penalty only when it sets them, fields that reference does not list. The concepts every provider shares are on FIM & Prefix Completion.

Limits and refusals

UniLM checks no limit of a service: a request longer than the model's context, or one the service cannot serve, is the service's error (When something fails). Every field goes out as it is set; the checks every request gets still hold, such as a temperature from 0 to 2, though Mistral's error glossary gives "temperature outside 0 to 1 range" as a cause of HTTP 400 (error glossary). respond sends a Respond to /v1/responses, its seed among its fields, while Mistral's API reference lists no Responses route. It refuses before anything is sent what the table below lists; the verbs of the capabilities the table at the top of this page lists as not available refuse the endpoint too.

Cost and usage

A result is priced by the model id it reports, whatever the service. No Mistral model has a row in DEFAULT_PRICING: its estimated_cost is 0.0, with one warning per model id, its embeddings' too, and cumulative_cost adds 0.0. A model another service reports is priced at its id's row where DEFAULT_PRICING has one, as a priced provider's model served through another service is, and at 0.0 otherwise. Give the model's rates, USD per token, as pricing, or add the row to DEFAULT_PRICING; Mistral lists Mistral Large 3, mistral-large-2512, at "Input $0.5 /M Tokens" and "Output $1.5 /M Tokens" (API pricing), and "Cached tokens are billed at 10% of the standard input token price" (chat completions):

large = (input=0.5e-6, cached_input=0.05e-6, output=1.5e-6)
estimated_cost(result; pricing=Dict(result.model => large))
DEFAULT_PRICING[result.model] = large                  # cumulative_cost prices with it from now on

The row prices the model the reply reports. A row holds no audio rates, so a result whose usage counts audio tokens is estimated at 0.0, with a warning, even then. A transcription, which Mistral prices per minute of audio, carries no token usage: estimated_cost throws ArgumentError for it. How a call is priced on every provider is on Cost Tracking.

When something fails

chatrequest!, embeddingrequest!, fim_complete and transcribe return what the service or the network did as a typed result, and do not throw it (Results). A failure holds the service's HTTP status and, as response, the body that came with it; a call error holds the text of an exception as error and the exception as cause. UniLM sends a request again after a transient status — 408, 429, 500, 502 to 504, 520 to 524 and 529 — or a failed connection, as often as the call's RequestConfig allows, and then returns the last answer (Timeouts & Retries); a streamed request is sent again only while none of its callbacks has run. Models

The endpoint has no default model: a request names one by the name the service serves it under. On Mistral, many API names are dated, such as mistral-large-2512 (Mistral Large 3), codestral-2508 or mistral-embed-2312, while some of the newest are not, such as mistral-medium-3-5 and mistral-large-4, and "A deprecated model still answers requests until its retirement date. A retired model no longer does: use its replacement" (models); the examples of Mistral's API reference name aliases, such as mistral-large-latest, codestral-latest, mistral-embed and voxtral-mini-latest. Mistral lists its models at GET /v1/models (models API).
