Reference · API: language models

Audio API

Synthesize speech from text, transcribe audio to text, and translate speech into another language. speak runs on OpenAI's Realtime API, on Gemini TTS or on a local Ollama speech model, and returns 24 kHz, 16-bit mono audio, as a WAV file or as raw PCM. transcribe uploads an audio file to OpenAI, to Gemini Transcribe and, with a local model that hears audio, to Ollama (Audio), and can stream the transcript from OpenAI. translate streams a WAV file through an OpenAI Realtime translation session, or uploads an audio file to Ollama, and returns the translated text.

Request Types

UniLM.SpeechRequestType#
SpeechRequest(; input, service=OPENAIServiceEndpoint, model=nothing, voice=nothing,
              response_format="wav", speed=nothing, instructions=nothing, speakers=nothing, language=nothing)

A text-to-speech request; pass it to speak. input is the text to read aloud, or on Gemini a dialogue: a vector of SpeechTurns, read in the voices speakers gives each speaker (below). model and voice left nothing are the service's defaults:

servicespeaks throughdefault modeldefault voicevoicespeed
OPENAIServiceEndpointa Realtime API sessiongpt-realtime-2.1-minimarinalloy, ash, ballad, coral, echo, sage, shimmer, verse, marin, cedar, or a custom voice's voice_… id, sent as {"id": …}0.25 to 1.5
GEMINIServiceEndpointGemini TTSgemini-3.8-flash-ttsKorea prebuilt voice (the 30 studio voices or one of the Extended Voice Library), a designed or replicated voice's voice_… id, or a replicated voice's voicekey_… keynone
OllamaEndpointOllama's speech route (Ollama 0.40.9 or later)none: name an installed speech model, such as phononthe model's own (voice not sent)one of the model's voices, which model_info lists (voices), sent as given1 only

Every service produces 16-bit mono PCM at 24 kHz: response_format "wav" returns it as a WAV file, "pcm" as the raw samples. instructions direct the delivery (tone, pace, accent): on OpenAI they follow the session's instruction to read input word for word, on Gemini they are the text's speech style (speechMetadata.style). Gemini TTS has no speed parameter: describe the pace in instructions ("speaking slowly"). Ollama takes neither: it answers non-empty instructions and any speed but 1 with HTTP 400.

On Gemini, language is the BCP-47 tag the text is read in (speechConfig.languageCode, such as "fr-FR"; Gemini answers an unknown one with HTTP 400), and a dialogue reads several voices in one request (speech generation):

speak([SpeechTurn("Joe", "How's it going today, Jane?"), SpeechTurn("Jane", "Not too bad!"; style="cheerful")];
      service=GEMINIServiceEndpoint, speakers=["Joe" => "Puck", "Jane" => "Kore"])

Each turn is a part of its own with its speaker (speechMetadata.speaker) and style, and speakers becomes multiSpeakerVoiceConfig, each voice a prebuilt one or any other, as voice is; the request's input field holds the turns' texts, joined by line breaks, and its voice is "". Every turn's speaker must be one of speakers; a dialogue takes no voice (the speakers have theirs) and no instructions (each turn has its style). Google's guide says multi-speaker speech "supports up to 2 speakers using prebuilt voices"; three speakers, and a designed voice beside a prebuilt one, were each spoken on 17 November 2026, so neither is refused. Other services read one voice and take no language: a dialogue, speakers or language there throws ArgumentError.

Throws ArgumentError, before any request, for an empty input, a voice the Realtime session does not have or a blank Gemini or Ollama voice, a response_format other than "wav" or "pcm", a speed out of range, and any speed on Gemini; on Ollama, for a request without a model, an input of more than 4,096 characters and non-empty instructions; and for GEMINIOpenAIServiceEndpoint, which has no speech route, naming GEMINIServiceEndpoint. The Extended Voice Library's names are listed by Gemini's GET /v1beta/voices, which list_voices reads (a Voice's id is a voice speak takes; create_voice makes one), so a Gemini voice is sent as given, and Gemini answers a name it does not have; an Ollama voice is sent as given too, and Ollama answers one the model does not have with HTTP 400 naming those it has. Voices: OpenAI Realtime, Gemini TTS, Ollama.

UniLM.SpeechTurnType#
SpeechTurn(speaker, text; style=nothing)

One turn of a dialogue that Gemini TTS reads in several voices: the speaker, a name the request's speakers gives a voice, the text the speaker reads, and the turn's delivery style (its speechMetadata.style, such as "whispered urgently"). A blank speaker or text throws ArgumentError. Give the turns to speak or SpeechRequest as input.

UniLM.TranscriptionRequestType#
TranscriptionRequest(; file, model=nothing, service=OPENAIServiceEndpoint, …)

An audio transcription request. file is a path on disk. model left nothing is the service's default: gpt-transcribe for OpenAI, gemini-3.5-transcribe for GEMINIServiceEndpoint; Ollama has none, so a request to it names an installed model that hears audio (e.g. model="gemma4:e4b") or throws ArgumentError before any request, and so does a GenericOpenAIEndpoint, whose request names the model its server serves. Optional languages, keywords, prompt, response_format, and temperature refine decoding. For gpt-transcribe, a legacy singular language is translated to languages. Other models retain their singular language field. Never set both forms. response_format is one of json, text, srt, verbose_json, vtt, diarized_json, and temperature lies in 0 … 1 (on Ollama, any finite number); anything else is an ArgumentError. On OpenAI, srt, vtt and verbose_json (subtitles and timestamps) are documented only for whisper-1, and diarized_json (speaker labels) only for gpt-4o-transcribe-diarize: deprecated models that shut down on February 26, 2027 (speech to text).

OpenAI's further options (create transcription):

  • include: ["logprobs"] adds the tokens' log probabilities to the reply (raw["logprobs"]).
  • timestamp_granularities: "word" and/or "segment", with response_format = "verbose_json" only (OpenAI's rule: with json it answers without them); the reply's segments and words are the result's TranscriptSegments and TranscriptWords.
  • chunking_strategy: "auto", or a TranscriptionVAD with server VAD settings.
  • known_speaker_names and known_speaker_references: up to 4 speakers for a diarization model, one reference each — an audio sample of 2 to 10 seconds, as a data URL (data:audio/wav;base64,…) or a path to an audio file, which UniLM sends as one.
  • stream = true: transcribe streams the transcript (see there); whisper-1 does not stream ("Streaming is not supported for the whisper-1 model and will be ignored"), so a stream on it throws ArgumentError.

On GEMINIServiceEndpoint (gemini-3.5-transcribe, audio transcription): languages (or one language) are BCP-47 codes such as "en-US"; keywords are its custom vocabulary (up to 1,000 terms); diarization = true labels the speakers; timestamp_granularities = ["word"] adds word timestamps; mode is "verbatim" (the default) or "smart", which removes disfluencies and formats the text, and source_text, in smart mode, is a text the audio edits. Gemini rejects custom vocabulary beside diarization or word timestamps, and smart mode beside either, so those combinations throw ArgumentError, as do the options Gemini's transcription does not take (prompt, temperature, response_format, include, chunking_strategy, known speakers, stream, segment timestamps). diarization, mode and source_text are Gemini's: any other service throws ArgumentError for them (on OpenAI, speaker labels come from gpt-4o-transcribe-diarize with response_format = "diarized_json").

Ollama's /v1/audio/transcriptions (Ollama 0.40.12 or later) reads one language, the prompt, temperature (any finite number; its default 0), stream and a response_format of json, text or verbose_json: a request to it that sets languages, keywords, another format or any of OpenAI's further options but stream throws ArgumentError before any request. Pass to transcribe.

UniLM.TranscriptionVADType#
TranscriptionVAD(; threshold=nothing, prefix_padding_ms=nothing, silence_duration_ms=nothing)

Server-side voice activity detection that cuts a transcription's audio into chunks: OpenAI's chunking_strategy {"type": "server_vad", …}, given to TranscriptionRequest as chunking_strategy (the string "auto" lets the server choose the chunking). A field left nothing is the API's default: threshold (sensitivity, 0 to 1; 0.5), prefix_padding_ms (audio kept before detected speech; 300) and silence_duration_ms (the silence that ends speech; 200). A threshold outside 0 … 1 or a negative duration throws ArgumentError.

Result Types

UniLM.SpeechSuccessType#

Successful speak result: audio holds a WAV file (content_type "audio/wav") or the raw 16-bit little-endian mono samples at 24 kHz ("audio/pcm"). Save it with save_audio.

UniLM.TranscriptionSuccessType#
TranscriptionSuccess

Successful transcribe/translate result. text holds the transcript or translation (via transcript_text); raw the parsed JSON a transcription or Ollama translation reply carried — for a streamed transcription its transcript.text.done event, for Gemini its generateContent reply — and nothing for a text reply and for an OpenAI Realtime translation. segments and words are the reply's TranscriptSegments and TranscriptWords, empty when it has none. The reply's usage (raw["usage"], Gemini's raw["usageMetadata"]) is not priced: token_usage and estimated_cost throw for a TranscriptionSuccess, streamed or not.

UniLM.TranscriptSegmentType#
TranscriptSegment(; text, start_time=nothing, end_time=nothing, speaker=nothing, id=nothing)

A stretch of a transcript: its text, its start and end in seconds from the start of the audio (nothing where the reply gives none), the speaker it is attributed to, and the provider's id for it. From OpenAI, a verbose_json reply's segments (id an integer index; no speaker), a diarized_json reply's and a streamed diarization's transcript.text.segment events (id such as "seg_0", speaker such as "A", or a name from known_speaker_names); from Gemini, each part of its transcription, one per speaker turn with diarization (speaker such as "spk:0"), whose start and end are those of its first and last word when word timestamps were asked for.

UniLM.TranscriptWordType#
TranscriptWord(; text, start_time=nothing, end_time=nothing, speaker=nothing)

One recognized word and its start and end in seconds from the start of the audio: OpenAI's verbose_json words (timestamp_granularities including "word"), Gemini's word timestamps (timestamp_granularities = ["word"]), which carry the speaker of their turn with diarization.

UniLM.AudioFailureType#

Audio error result: the HTTP status (nothing when a Realtime session reported the failure as an event, which carries no HTTP status), the raw response (the reply body, the Realtime event's JSON, or for a refused WebSocket upgrade HTTP.jl's report of its status) and the request_id the service sent (x-request-id/request-id header), if any.

UniLM.AudioCallErrorType#

Audio call that produced no usable reply (transport failure, timeout, cancel, a session that closed before its result, or a reply that could not be decoded); cause is the underlying exception — a UniLMTimeout for a timeout, a UniLMCancelled for a cancel, and, when the server closed a Realtime session, the HTTP.WebSockets.WebSocketError that carries its status and reason, which error names too.

Functions

UniLM.speakFunction#
speak(s::SpeechRequest; config=nothing, cancel=nothing) -> SpeechSuccess | AudioFailure | AudioCallError
speak(input; service=OPENAIServiceEndpoint, model=nothing, voice=nothing, response_format="wav",
      speed=nothing, instructions=nothing, speakers=nothing, language=nothing, config=nothing, cancel=nothing)

Synthesize speech from text, or on Gemini from a dialogue of SpeechTurns read in the voices speakers names; the keywords build a SpeechRequest.

On OPENAIServiceEndpoint the speech comes from a Realtime API session (wss://api.openai.com/v1/realtime, gpt-realtime-2.1-mini unless model names another), the replacement OpenAI names for its retiring text-to-speech models (text to speech): UniLM sets the voice, 24 kHz PCM output and instructions to read the text word for word, adds the text as a user message, asks for a response and collects its audio. Realtime models are conversational, and OpenAI notes that instructions are not guaranteed to be followed. On GEMINIServiceEndpoint it comes from Gemini TTS (generateContent on gemini-3.8-flash-tts unless model names another, speech generation), which reads the text verbatim. On OllamaEndpoint it comes from Ollama's OpenAI-compatible speech route (Ollama 0.40.9 or later, speech), one request carrying the model, the text, the format, and the voice and speed when set; there is no default model, so name an installed speech model, such as phonon:

r = speak("Hello from UniLM."; service=OllamaEndpoint(), model="phonon", voice="Zoey")
r isa SpeechSuccess && save_audio(r, "hello.wav")

Returns SpeechSuccess: a WAV file (response_format = "wav") or the raw samples ("pcm"). Ollama's bytes come back as it streamed them: its WAV header, written before the length is known, holds the maximum size in its size fields. A failure the provider reports is an AudioFailure: an HTTP error status, a WebSocket upgrade the server refuses included (a bad key is a 401; response is then HTTP.jl's report of the status, since it does not keep the reply); a Gemini reply whose candidate did not finish (a finishReason other than STOP, such as MAX_TOKENS or SAFETY) or that has no candidate (a blocked prompt, its reason in promptFeedback), with status 200 and the reply as response; or on a Realtime session the error event, read even when the server closes the session while UniLM is still sending, or a response.done that did not complete (status is then nothing and response the event's JSON). A session that closes before its response is done (error names the close's status and reason, and cause is the close), a timeout, a cancel and a reply without usable audio are an AudioCallError. Audio received before a failure is never returned.

Pass config::Union{Nothing,RequestConfig} to bound the call. On OpenAI the session is a single attempt, which max_attempts does not change: a retry after the session's response.create may bill a second response, and a session's audio cannot be resumed. There total_deadline bounds the whole call whatever the socket does, connect_timeout the WebSocket open, and stream_idle_timeout every send and every wait for the next event. On Gemini and Ollama, transient statuses (408/429/500/502–504/520–524/529) and transport failures are retried with backoff under the config's max_attempts and total_deadline (retry-after-ms, else Retry-After, honored), as chatrequest! retries them, each attempt on Gemini a billed generateContent request; a 429 that no retry can serve is returned at once. Speech is not priced: token_usage and estimated_cost throw for a SpeechSuccess.

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns an AudioCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

UniLM.transcribeFunction#
transcribe(t::TranscriptionRequest) / transcribe(path; model=nothing, kwargs...)

Transcribe audio to text in the source language. Returns TranscriptionSuccess (.text, via transcript_text), AudioFailure, or AudioCallError. model left nothing is the service's default (gpt-transcribe on OpenAI).

On Ollama (0.40.12 or later), an installed model that hears audio transcribes through Ollama's OpenAI-compatible /v1/audio/transcriptions route, which takes language, prompt, temperature and a response_format of json, text or verbose_json; the reply is read by its Content-Type, JSON or, for "text", the bare text. There is no default model, and what that route cannot carry — languages, keywords, another format — throws ArgumentError before any request:

r = transcribe("memo.wav"; service=OllamaEndpoint(), model="gemma4:e4b", language="en",
               temperature=0.0, response_format="text")
r isa TranscriptionSuccess && println(transcript_text(r))

A GenericOpenAIEndpoint sends the request to its server's /v1/audio/transcriptions with every field it sets, as given — vLLM serves OpenAI's Transcriptions API there — and has no default model either.

Transient statuses (408/429/500/502–504/520–524/529) and transport failures are retried with backoff and jitter under the resolved RequestConfig (max_attempts, total_deadline; retry-after-ms, else Retry-After, honored), as chatrequest! retries them, and each attempt sends the whole file again; a 429 that no retry can serve is returned at once. Pass config::Union{Nothing,RequestConfig} to override the timeout and retry budget for this call.

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns an AudioCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

Streaming (stream = true, on OpenAI and the OpenAI-wire routes): the call returns a Task whose fetch yields the result, and the transcript arrives as OpenAI's server-sent events. Pass a callback:

callback(chunk::Union{String,TranscriptSegment}, close::Ref{Bool})

Each transcript.text.delta is a String (the text added), and each transcript.text.segment (a streamed diarization, gpt-4o-transcribe-diarize with response_format = "diarized_json") a TranscriptSegment. The result is the same TranscriptionSuccess as unstreamed: text is the transcript.text.done event's, raw that event (its usage, logprobs and languages), segments the streamed segments. Setting close[] = true stops the stream at once with an AudioCallError whose cause is a UniLMCancelled; an exception the callback throws ends the call with that exception as cause. A status before the stream is an AudioFailure, retried as unstreamed while no callback has run; an error the stream itself carries ({"error": …}) is an AudioFailure with status = nothing; a stream that ends before transcript.text.done, a gap longer than stream_idle_timeout, a timeout and a cancel are an AudioCallError. A callback without stream = true throws ArgumentError.

UniLM.translateFunction#
translate(path; language="en", source_language=nothing, model=nothing, service=OPENAIServiceEndpoint,
          config=nothing, cancel=nothing) -> TranscriptionSuccess | AudioFailure | AudioCallError

Translate the speech in the audio file at path into language and return the translation as text: a TranscriptionSuccess, read with transcript_text. model left nothing is the service's default: gpt-realtime-translate on OpenAI; Ollama has none.

On OpenAI the audio goes to an OpenAI Realtime translation session (wss://api.openai.com/v1/realtime/translations, Realtime translation): UniLM sets the target language (the session's audio.output.language, such as "fr" or "es"; English unless named), streams the audio in 200 ms frames, closes the session and joins the translated transcript. The session also returns translated speech, which translate does not keep. Speech already in the target language can come back as empty text: an English clip translated into English did. A short clip's translation also varies from call to call: of ten translations into English of a two-second French sentence made with speak, one came back empty and six named words the sentence does not have (October 2026).

There path must be a 16-bit PCM WAV file, at any sample rate and channel count: a translation session takes 24 kHz mono PCM16 only, so UniLM mixes the channels down and resamples by linear interpolation (speech-grade: there is no anti-aliasing filter). Any other file throws ArgumentError before any I/O, naming the conversion; so do an empty file, a blank language and a service that has neither OpenAI's Realtime API nor Ollama's translation route, and so does a source_language: the session sets only the target language and has no field for the spoken one (translation client events).

On OllamaEndpoint (Ollama 0.40.12 or later) the file goes as it is to Ollama's OpenAI-compatible translation route, one multipart request carrying the model, the target language as to_language, the "ISO 639-1 code of the output language", and source_language, when given, as Ollama's own language, "the spoken language, if known" (OpenAI compatibility); the translation is the reply's text, and raw holds the reply. Ollama decodes a WAV file itself and passes any other container to the model whole. There is no default model: name an installed model that hears audio, such as gemma4:e4b; a call without one, a blank language or source_language, and a missing or empty file throw ArgumentError before any request:

r = translate("memo.wav"; language="fr", service=OllamaEndpoint(), model="gemma4:e4b")
r isa TranscriptionSuccess && println(transcript_text(r))

A status Ollama answers is an AudioFailure (a language it does not translate into or from is a 400); transient statuses and transport failures are retried as transcribe retries them, the whole file sent each time.

On OpenAI, a failure the provider reports is an AudioFailure: a Realtime error event, for example for a language it does not translate into (status = nothing, the event's JSON as response), read even when the server closes the session during the upload, or a WebSocket upgrade the server refuses (a bad key is a 401). A session that closes before session.closed (error names the close's status and reason), a timeout and a cancel are an AudioCallError. config::Union{Nothing,RequestConfig} bounds the call as for speak: total_deadline the whole call whatever the socket does, connect_timeout the open, stream_idle_timeout every send and every wait for the next event. On OpenAI it is a single attempt, which max_attempts does not change: a retry after the session's audio was sent may bill a second translation, and a session's audio cannot be resumed.

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns an AudioCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).

Accessors

UniLM.transcript_textFunction#
transcript_text(r::TranscriptionSuccess) -> String

The transcript text from a transcribe or translate result.

UniLM.save_audioFunction#
save_audio(r::SpeechSuccess, path) -> path

Write the synthesized audio bytes to path, atomically: the bytes go to a temporary file in the same directory, which is then renamed over path, so a failed write leaves any existing file intact. An existing file keeps its permission bits. A symlink is written through — a dangling one creates its target; a directory throws ArgumentError.

Usage 

# Speech from OpenAI (gpt-realtime-2.1-mini, voice "marin"), saved as a WAV file
r = speak("Hello from UniLM.")
r isa SpeechSuccess && save_audio(r, "hello.wav")

# Speech from Gemini TTS (gemini-3.8-flash-tts), another voice and a delivery, as raw PCM
r = speak("Hello from UniLM."; service=GEMINIServiceEndpoint, voice="Puck",
          instructions="warm and enthusiastic", response_format="pcm")

# Transcribe audio to text in its source language
t = transcribe("hello.wav"; languages=["en"], keywords=["UniLM", "Julia"])
t isa TranscriptionSuccess && println(transcript_text(t))

# Stream the transcript as it is made (a Task, as a streamed Chat)
t = fetch(transcribe("hello.wav"; stream=true, callback=(chunk, _) -> chunk isa String && print(chunk)))

# Transcribe with Gemini (gemini-3.5-transcribe), its speakers labelled
t = transcribe("call.wav"; service=GEMINIServiceEndpoint, diarization=true)
t isa TranscriptionSuccess && foreach(s -> println(s.speaker, ": ", s.text), t.segments)

# Translate speech into French text (into English when no language is named)
t = translate("bonjour.wav"; language="fr")

# On your own machine: Ollama, with installed models (ollama pull gemma4:e4b phonon)
t = transcribe("memo.wav"; service=OllamaEndpoint(), model="gemma4:e4b", response_format="text")
r = speak("Hello from UniLM."; service=OllamaEndpoint(), model="phonon", voice="Zoey")
t = translate("memo.wav"; language="fr", service=OllamaEndpoint(), model="gemma4:e4b")

Every service produces 16-bit mono PCM at 24 kHz: response_format = "wav" (the default) returns it as a WAV file — on OpenAI and Gemini UniLM writes a 44-byte header, and Ollama's header, streamed before the length is known, holds the maximum size — and "pcm" returns the samples (content_type "audio/pcm"). Any other format, a voice the Realtime session does not have (nova, onyx and fable are not Realtime voices), a blank Gemini or Ollama voice, a speed out of range, any speed on Gemini, and an empty input throw ArgumentError before any request, as does GEMINIOpenAIServiceEndpoint: Google's OpenAI-compatible API has no speech route, so the error points to GEMINIServiceEndpoint.

On OpenAI, speak opens a Realtime WebSocket session, sets the voice, PCM output and instructions to read the text word for word, adds the text as a user message and collects the response's audio. Realtime models are conversational, and OpenAI notes that a model is not guaranteed to follow its instructions. instructions add delivery directions (tone, pace, accent) after UniLM's own. OpenAI's tts-1, tts-1-hd and gpt-4o-mini-tts shut down on January 6, 2027, and gpt-realtime-2.1-mini on the Realtime API is the replacement OpenAI names (text to speech, Realtime voices).

On Gemini, speak sends one generateContent request with responseModalities ["AUDIO"], the voice in speechConfig and 24 kHz L16 output requested. Gemini 3.8 TTS reads the text verbatim; instructions become the text's speech style, which is also where the pace goes ("speaking slowly"): Gemini TTS has no speed parameter (speech generation). language sets the BCP-47 tag it reads in (speechConfig.languageCode, such as "fr-FR"; Gemini answered "xx-ZZ" with HTTP 400 "Invalid language_code", an AudioFailure).

A dialogue reads several voices in one request: input is a vector of SpeechTurns and speakers gives each speaker a voice, a prebuilt one or any other, as voice takes them:

r = speak([SpeechTurn("Joe", "How's it going today, Jane?"),
           SpeechTurn("Jane", "Not too bad, ready to test these voices?"; style="cheerful")];
          service=GEMINIServiceEndpoint, speakers=["Joe" => "Puck", "Jane" => "Kore"])

Each turn goes as a part of its own, its speaker and style in speechMetadata, and the speakers as multiSpeakerVoiceConfig. Every turn's speaker must be among speakers; a dialogue takes no voice (its speakers have theirs) and no instructions (each turn has its style), and a speaker named twice or a blank one is refused before the request. Google's guide says this "supports up to 2 speakers using prebuilt voices"; three speakers, and a designed voice beside a prebuilt one, were each spoken on 17 November 2026, so UniLM refuses neither. OpenAI's Realtime session and Ollama read one voice and take no language: a dialogue, speakers or a language there throws ArgumentError. The speech's format stays UniLM's: 24 kHz 16-bit mono, as WAV or PCM, whichever response_format asks; Gemini's other output formats (MP3, Opus, A-law, μ-law, URI delivery) are not requested.

On Ollama, speak sends one POST to /v1/audio/speech with the model, the text, the format, and the voice and speed when set (speech); there is no default model, so name an installed speech model such as phonon. Ollama answers with HTTP 400 what its model does not support, so UniLM refuses, before sending it, a request without a model, an input of more than 4,096 characters, a speed other than 1, non-empty instructions and a format other than "wav" and "pcm". A voice is each model's own and is sent as given: Ollama answers one the model does not have with a 400 AudioFailure that names the voices it has. The reply's bytes come back as Ollama streamed them, and a reply under another Content-Type is an AudioCallError; transient statuses are retried as on Gemini.

An error the provider reports is an AudioFailure: an HTTP error status (a WebSocket upgrade the server refuses included: a bad key is a 401), a Gemini reply whose candidate did not finish (a finishReason other than STOP, such as MAX_TOKENS or SAFETY) or that has no candidate (a blocked prompt), with status 200 and the reply as response, or, on a Realtime session, the error event or a response.done that did not complete, with status = nothing and the event's JSON as response. An error event the server sends before it closes the session is that failure even when the close interrupts UniLM's sending. A session that closes before its response is done (its close status and reason in error, the close itself in cause), a timeout, a cancel and a reply without usable audio are an AudioCallError. Audio received before a failure is never returned. On OpenAI, total_deadline bounds the whole call whatever the socket does, connect_timeout the WebSocket open, and stream_idle_timeout every send and every wait for the next event. Every service takes cancel, a CancelToken, the ambient one unless given: a token already cancelled sends nothing, and a cancel ends the call at once, with an AudioCallError whose cause is a UniLMCancelled. Speech is not priced: token_usage and estimated_cost throw for a SpeechSuccess.

Translation

translate(path; language="en") on OpenAI (model gpt-realtime-translate unless named) opens a Realtime translation session (wss://api.openai.com/v1/realtime/translations), sets the target language (audio.output.language), streams the audio in 200 ms frames, closes the session and joins the translated transcript into the text of a TranscriptionSuccess. The session also returns translated speech, which translate does not keep. Speech already in the target language can come back as empty text: an English clip translated into English did. A short clip's translation also varies from call to call: of ten translations into English of a two-second French sentence made with speak, one came back empty and six named words the sentence does not have (October 2026). A translation session takes 24 kHz mono 16-bit PCM only, so path must be a 16-bit PCM WAV file, at any sample rate and channel count: UniLM mixes the channels down and resamples by linear interpolation, which suits speech (there is no anti-aliasing filter). Any other file throws ArgumentError before any I/O, naming the conversion; convert it first, for example with ffmpeg -i in.m4a -c:a pcm_s16le out.wav. A source_language throws ArgumentError before any I/O too: the session sets only the target language and has no field for the spoken one (translation client events). A language the session does not translate into is an AudioFailure carrying the provider's error event; the bounds and the cancellation are those of speech on OpenAI. Translation replaces OpenAI's file-upload translation endpoint, which shuts down on February 26, 2027 (Realtime translation).

On OllamaEndpoint (Ollama 0.40.12 or later), translate uploads the file as it is to Ollama's /v1/audio/translations, with the model, the target language as to_language, the "ISO 639-1 code of the output language", and source_language, when given, as Ollama's own language, "the spoken language, if known" (OpenAI compatibility), and returns the reply's text, its JSON in raw. Ollama decodes a WAV file itself and passes any other container to the model whole. There is no default model: name an installed model that hears audio, such as gemma4:e4b; a call without one, a blank language or source_language and a missing or empty file throw ArgumentError before the request. A language Ollama does not translate into or from is its 400, an AudioFailure, and transient statuses are retried as a transcription's are.

Transcription

Transcription takes the service's default model when model is left nothing: gpt-transcribe on OpenAI, gemini-3.5-transcribe on GEMINIServiceEndpoint. Its languages and keywords options are vectors of strings sent as repeated multipart fields. A singular language is translated to a one-element languages list for this model; older models keep their singular field. Setting both forms raises ArgumentError.

OpenAI's further options (create transcription) are typed fields of TranscriptionRequest, each sent as OpenAI reads it:

optionvaluessent as
include["logprobs"]include[]; the reply's logprobs stay in raw
timestamp_granularities"word", "segment", with response_format = "verbose_json"timestamp_granularities[]
chunking_strategy"auto" or a TranscriptionVADone field: auto, or the server VAD settings as JSON
known_speaker_names, known_speaker_referencesup to 4 pairs; a reference is a data URL or a path to a 2–10 s clipknown_speaker_names[], known_speaker_references[] (data URLs)
streamtruestream; the call streams (below)

OpenAI reads chunking_strategy as one field: the VAD settings as JSON with a bogus type were answered with HTTP 400, the bracketed fields a form gives other objects (chunking_strategy[type]) were ignored with a 200 (17 November 2026). A request that asks for what OpenAI would refuse or ignore throws ArgumentError before it is sent: an include item other than "logprobs", timestamps without verbose_json (with json, gpt-transcribe answered without them), a stream on whisper-1 (OpenAI: "Streaming is not supported for the whisper-1 model and will be ignored"), names without a reference each, more than four speakers, a VAD threshold outside 0 … 1. Known speakers are for the diarization model: gpt-transcribe answered them with HTTP 400 "Known speaker references are only supported for diarization models", an AudioFailure.

A reply's segments and words are typed: a verbose_json reply's segments (id an index) and words, a diarized_json reply's segments, each with its speaker, become the result's TranscriptSegments and TranscriptWords; everything else the reply holds stays in raw. Transcription is not priced: token_usage and estimated_cost throw for a TranscriptionSuccess, and the usage the reply reports stays in raw["usage"].

Streaming

With stream = true, transcribe returns a Task, as a streamed Chat does, and hands the transcript to callback(chunk, close) as OpenAI's events arrive: each transcript.text.delta as a String, each transcript.text.segment of a streamed diarization as a TranscriptSegment. The task's result is the same TranscriptionSuccess as unstreamed, built from the transcript.text.done event (its text, and in raw its usage, logprobs and languages), its usage as unpriced as the unstreamed reply's.

task = transcribe("memo.wav"; stream=true, callback=(chunk, close) -> chunk isa String && print(chunk))
r = fetch(task)
r isa TranscriptionSuccess && println("\n", r.raw["usage"])

close[] = true stops the stream at once (an AudioCallError whose cause is a UniLMCancelled); an exception in the callback ends the call with it as cause. A status before the stream is an AudioFailure and a transient one is sent again while no callback has run; an error inside the stream ({"error": …}, Ollama's form) is an AudioFailure with status = nothing; a stream that ends before transcript.text.done, a byte gap longer than stream_idle_timeout, a timeout and a cancel are an AudioCallError. Ollama streams the same events.

Gemini

On GEMINIServiceEndpoint, transcribe sends the file inline to gemini-3.5-transcribe in one generateContent request, its options in generationConfig.audioTranscriptionConfig (audio transcription):

optionGemini field
languages (or one language), BCP-47 codes such as "en-US"languageCodes
keywords, up to 1,000 termscustomVocabulary
diarization = truediarization
timestamp_granularities = ["word"]wordTimestamp
mode, "verbatim" (default) or "smart"mode
source_text, with mode = "smart"sourceText
r = transcribe("call.wav"; service=GEMINIServiceEndpoint, diarization=true, timestamp_granularities=["word"])
for s in r.segments
    println(s.speaker, " (", s.start_time, "–", s.end_time, " s): ", s.text)
end

Each part of the reply is a speaker turn: a TranscriptSegment with its speaker ("spk:0", "spk:1", …), its start and end those of its first and last word; the words, with their speaker, are the result's TranscriptWords, and the text is the turns joined with spaces. Google's Interactions API takes the same options as transcription_config and gave the same transcript (17 November 2026); UniLM uses generateContent, which stores nothing and answers a turn per part. Gemini rejects custom vocabulary beside diarization or word timestamps — it answered HTTP 400 "customvocabulary is incompatible with diarization." — and smart mode beside either, so those throw ArgumentError, as do the options Gemini takes none of (prompt, temperature, `responseformat,include,chunkingstrategy, known speakers,stream, segment timestamps). A reply whose candidate did not finish is an [AudioFailure](@ref) withstatus200; transient statuses are retried as speech's are.diarization,modeandsourcetextare Gemini's: an OpenAI-wire service throwsArgumentError` for them.

Ollama, and OpenAI's deprecated models

Ollama has no default: name a model that hears audio, such as gemma4:e4b. Its /v1/audio/transcriptions (Ollama 0.40.12 or later) reads one language, a prompt, temperature (any finite number; its default 0) and a response_format of json, text or verbose_json (OpenAI compatibility), and UniLM reads the reply by its Content-Type: JSON, or the bare text for "text". A reply labelled otherwise is an AudioCallError naming the label: Ollama before 0.40.12 labelled its JSON application/x-ndjson. languages, keywords and any other format (srt, vtt, diarized_json) throw ArgumentError before the request, in Ollama's words, as do OpenAI's further options but stream, which Ollama lists. The live suite test/integration_ollama.jl, whose 109 tests include a transcription, passed on Ollama 0.40.16 (16 November 2026, gemma4:e4b-it-q4_K_M). An endpoint declares transcription with the capability :transcription, which :audio implies.

OpenAI deprecated gpt-4o-transcribe, gpt-4o-mini-transcribe, gpt-4o-transcribe-diarize, and whisper-1 on August 26, 2026, with shutdown scheduled for February 26, 2027. The srt, vtt and verbose_json formats (subtitles and timestamps) are documented only for whisper-1, and diarized_json (speaker labels) only for gpt-4o-transcribe-diarize. OpenAI transcription guide, deprecation schedule.

Custom voices

One family of verbs makes, lists and removes the voices speak can use, on OpenAI and on Gemini, each returning a Voice whose id is what speak takes as voice on that service; an endpoint declares them with the capability :voices.

verbOpenAI (/v1/audio/voices)Gemini (/v1beta/voices)
create_voicea prompt voice (prompt), or one from a recording (audio_sample and consent)a designed voice (prompt), or a replicated one (audio_sample and consent_audio)
list_voicesnone: ArgumentErrorthe project's voices, then the prebuilt catalog, filtered
retrieve_voicenone: ArgumentErrora stored voice
delete_voiceyesa stored voice
create_voice_consent, list_voice_consents, retrieve_voice_consent, update_voice_consent, delete_voice_consentthe speaker's consent recordingsnone: the consent recording goes with the replicated voice
# Gemini: design a voice, read with it, delete it
v = create_voice(; service=GEMINIServiceEndpoint, name="Narrator", prompt="A calm, clear adult narrator.")
if v isa VoiceSuccess
    s = speak("The bridge reopens on Monday."; service=GEMINIServiceEndpoint, voice=v.response.id)
    delete_voice(v.response.id; service=GEMINIServiceEndpoint)
end

# The catalog: prebuilt voices in a language, a page at a time
page = list_voices(; service=GEMINIServiceEndpoint, type="prebuilt", language="en-GB", limit=20)

On Gemini a designed voice is stored under an id voice_… (200 per project, one year) and its reply carries a WAV preview (raw["sample_audio"]) and its token usage, which UniLM does not price; a replicated voice made with store = false is not stored and comes back as a key (voicekey_…, seven days), which speak takes as its voice. The catalog's prebuilt voices list by their ids ("achernar", "am-et-assistant-1", …), and speak took both kinds by id on 17 November 2026; retrieve_voice reads stored voices only (a prebuilt id is a 404). A designed voice was read in a dialogue beside a prebuilt one. Untested: no live run has replicated a voice (audio_sample with consent_audio), made one with store = false or edited a base_voice; those requests are built from Gemini's voice replication and voice design guides, and tested offline only, against scripted replies.

On OpenAI a voice made from a prompt is supported "only in Live, not in Realtime or the speech endpoint": the Realtime session speak runs refused one with "Prompt-based voices are not supported by the Realtime API" (17 November 2026), so a prompt voice cannot be read by speak. A voice from a recording needs the speaker's consent (create_voice_consent, then consent = "cons_…"), an access OpenAI limits "to eligible customers": an organization without it gets HTTP 404 "Your organization does not have access to this endpoint" from both, a VoiceFailure. Untested: the organization the live tests run under gets that 404, so no live run has made a voice from a recording or seen a consent verb succeed; those success paths are built from OpenAI's reference and tested offline only, against scripted replies. OpenAI's API lists and looks up no voices, so list_voices and retrieve_voice default to GEMINIServiceEndpoint, and on OpenAI throw ArgumentError naming it. The Realtime API takes a custom voice as an object, {"id": "voice_…"} (a plain string answered "Supported values are: 'alloy', …"), and so speak on OpenAI sends a voice_… id (custom voices).

Each verb is one bounded attempt, never retried (a create that timed out may still have made the voice), and takes config and cancel as the other platform verbs do; a status the service answers is a VoiceFailure, a reply that is not the documented object (a voice without its type, a deletion record of another kind, a page without has_more) a VoiceCallError, as are a missing API key and a recording that cannot be read; a call whose token was already cancelled reads no file.

UniLM.VoiceType#
Voice

A voice speak can use, as create_voice, retrieve_voice and list_voices return it:

  • id: the voice's id, which speak takes as voice on the service that made it — OpenAI's voice_…; Gemini's voice_… for a stored custom voice, and a prebuilt voice's catalog id (such as "achernar"). nothing for a Gemini voice replicated with store = false, which has a key.
  • name: OpenAI's name; Gemini's display_name (nothing when it has none).
  • type: how it was made: OpenAI's "audio_sample" or "prompt"; Gemini's "replicated", "prompted" or "prebuilt".
  • created_at: OpenAI's creation time, in Unix seconds; Gemini reports none (nothing).
  • key: a Gemini stateless replication key (voicekey_…), which speak takes as voice; else nothing.
  • raw: the voice as the provider sent it — OpenAI's prompt; Gemini's expire_time, model, language_code, prompted, sample_audio (a base64 WAV preview of a prompted voice) and usage.

A page of Voices from list_voices: Gemini's custom voices, newest first, then its prebuilt catalog. has_more signals a further page, whose cursor is raw["next_page_token"] (pass it as after); raw holds the page as Gemini sent it.

UniLM.create_voiceFunction#
create_voice(; name=nothing, prompt=nothing, audio_sample=nothing, service=OPENAIServiceEndpoint, …)
    -> VoiceSuccess | VoiceFailure | VoiceCallError

Create a custom voice, from a description (prompt) or from a recording of the speaker (audio_sample, a path), one of the two, and return it as a Voice whose id (or Gemini's stateless key) is what speak takes as voice on that service.

On OPENAIServiceEndpoint (custom voices): name (1 to 256 characters) is required. A prompt (at most 2,000 characters) with an optional script_hint (the text the voice speaks while it is made) and model ("auto" unless named) makes a prompt voice, which OpenAI supports "only in Live, not in Realtime or the speech endpoint": a Realtime session refused one with "Prompt-based voices are not supported by the Realtime API" (2026-11-17), so speak cannot use it. An audio_sample (at most 10 MiB) with consent, the id of the speaker's VoiceConsent, makes a voice from the recording; that access is "limited to eligible customers", and an organization without it gets HTTP 404 "Your organization does not have access to this endpoint" as a VoiceFailure. Untested: no live run has made a voice from a recording (the live tests' organization gets that 404); the request is built from OpenAI's reference and tested offline only.

On GEMINIServiceEndpoint (voice design, voice replication): a prompt designs a voice (base_voice names a voice it edits); an audio_sample with consent_audio, a recording of the speaker reading the consent phrase, replicates one. store (default true) keeps the voice in the project, under an id voice_… (200 per project, one year); store = false replicates a voice without storing it and returns its key (voicekey_…, seven days). name is its display name; model, language (a BCP-47 tag), region, accent, persona, context, gender, pitch ("low", "medium" or "high") and description describe it. A designed voice's reply carries a WAV preview (raw["sample_audio"]) and its token usage (raw["usage"]), which UniLM does not price. Untested: no live run has replicated a voice, made one with store = false or edited a base_voice; those requests are built from Gemini's guides and tested offline only.

An option the service does not take, a missing name on OpenAI, both or neither of prompt and audio_sample, a missing consent and a missing file throw ArgumentError before any request; a file that cannot be read and a missing API key are a VoiceCallError, and a call whose token was already cancelled reads no file. A create is a single attempt, never retried: one that timed out may still have made the voice. Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a VoiceCallError whose cause is a UniLMCancelled — without sending anything when the token was already cancelled, at once when mid-request (never retried).
