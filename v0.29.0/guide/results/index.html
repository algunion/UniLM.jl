Language models · Concepts (every provider)

Results

A request to a model returns what the service or the network did as a typed result instead of throwing it: a success holding the reply, a failure holding what the provider answered with, or a call error holding what ended the call. Branch on the type, or ask issuccess, before you read the reply.

service, model = OPENAIServiceEndpoint, "gpt-5.4-mini"

The examples use only the names bound above. service and model are the provider and model they run on: bind your own there. The table at the end links each provider's rules.

Three outcomes

VerbSuccessFailureCall error
chatrequest!, prefix_completeLLMSuccessLLMFailureLLMCallError
respondResponseSuccessResponseFailureResponseCallError
embeddingrequest!EmbeddingSuccessEmbeddingFailureEmbeddingCallError
fim_completeFIMSuccessFIMFailureFIMCallError

Each is an LLMRequestResponse:

  • A success holds the reply: an LLMSuccess its message, the conversation as self and the usage; a ResponseSuccess the response as a ResponseObject, with its id, status, model, output items, usage and the whole body as raw.
  • A failure holds the HTTP status and, as response, the body the provider answered with. From respond, a ResponseFailure also stands for a response that ended failed, and a response with any other status — incomplete, in_progress, cancelled, … — is a ResponseSuccess, read with response_status.
  • A call error holds, as error, the text of what ended the call without a reply it could use, its HTTP status when there was one, and the exception, when there was one, as cause: a UniLMTimeout for a bound that ran out, a UniLMCancelled for a stop or a cancel, the connection's exception, or the error of a reply it could not read.

A failure or call error of chatrequest!, respond or fim_complete also keeps the provider's request id header, when one came, as request_id. A tool loop returns a ToolLoopResult whose response is the last result it received, and responses every one, in order (Inspecting the result). Of the lifecycle verbs of stored responses, delete_response, list_input_items, compact_response and count_input_tokens return the provider's answer as a Dict on success, and a ResponseFailure or ResponseCallError otherwise.

result = chatrequest!(
    systemprompt="You are a calculator. Respond only with the number.",
    userprompt="What is 42 * 17?",
    service=service,
    model=model,
    temperature=0.0
)
result isa LLMSuccess, issuccess(result)

Reading a success

text is the reply of an LLMSuccess, and output_text the answer of a ResponseSuccess; result.message holds the whole reply, its finish_reason, tool_calls and refusal_message among it. An LLMSuccess's model is the model the provider reports having served the turn where UniLM keeps the name its reply gives, and nothing otherwise (each entry's first call says which); a ResponseSuccess's is result.response.model. Its logprobs and moderation are the reply's log probabilities and moderation results, when the request asked for them and the reply carries them, and nothing otherwise (LLMSuccess). token_usage reads the usage in one shape for every provider, a TokenUsage — prompt_tokens counts all the input, cache reads and writes included, and completion_tokens all the output, reasoning included — and estimated_cost prices it in USD (Cost Tracking):

u = token_usage(result)
(; reply = text(result), result.message.finish_reason, u.prompt_tokens, u.completion_tokens,
   cost = round(estimated_cost(result); digits=6))

A streamed result also counts, as sse_dropped, the stream payloads that could not be read and were dropped while it was assembled, 0 for a clean stream and for an unstreamed call (Dropped SSE payloads).

Handling a failure

A failure holds no reply: text, output_text, reasoning_text, embedding_vectors and fim_text throw LLMResultError for one, which names its status and the start of its body, and its usage is zero. This failure is built by hand, as a 429 would arrive:

chat = Chat(service=service, model=model)
failure = LLMFailure(status=429, response="{\"error\": {\"message\": \"Rate limit reached\"}}", self=chat)
issuccess(failure), token_usage(failure).prompt_tokens, estimated_cost(failure)

err = try text(failure); nothing catch e; e end
err isa LLMResultError || error("expected text to refuse a failure")
print(sprint(showerror, err))

What a call throws instead of returning is what UniLM refuses before sending — an ArgumentError for a request that breaks a rule it checks, an InvalidConversationError for a conversation the reply could not be appended to —, a user InterruptException, and, in a recorded call, a ReplayMissError or RecordingWriteError (Recorded answers). In a stream, the last three can come from its task, at fetch, wrapped in a TaskFailedException. Which statuses and errors a provider returns, and what to do about each, is in its entry's failure section.
