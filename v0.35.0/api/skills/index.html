Reference · API: OpenAI platform

Skills API

Upload a skill — a folder whose root holds a SKILL.md, or a .zip of that folder — version it, read it back, download it and delete it, on each provider's own Skills API: OpenAI's (OPENAIServiceEndpoint, the default) and Anthropic's (ANTHROPICServiceEndpoint), each declaring :skills. The verbs and their results are the same on both; what differs is below. An OpenAI skill loads into a container through a SkillReference, and a zip goes into one directly as an InlineSkill (Containers API). An Anthropic skill loads into the code-execution container of a Messages request (container.skills), which a Chat does not send yet.

A skill's SKILL.md starts with front matter naming it and saying what it does — the model reads the description to decide when to use it — and goes on with its instructions:

---
name: csv-sum
description: Sums a column of a CSV file. Use it when asked for a column's total.
---
Read the file with pandas and print the column's sum.

A folder goes as one multipart part per file — every file in it, its subfolders' too — each named by its path under the folder's name (csv-sum/SKILL.md), the layout both providers document: "All files must be in the same top-level directory and must include a SKILL.md file at the root of that directory" (Anthropic); "Each part's filename includes the path inside a single top-level folder" (OpenAI). A .zip goes as one part. Hidden entries under the folder — each name starting with ., such as .env, .git/ or .DS_Store, at any depth and with all they hold — are never sent, and OpenAI's 500 counts only the files sent.

Each refusal in the table is an ArgumentError before anything is sent, and so are a path that is no folder or .zip file, a folder without a SKILL.md at its root, and an empty skill id or version. An Anthropic Skills request sends the key, anthropic-version and the endpoint's workspace_id, and neither its betas nor its user_profile_id: the API "is out of beta and needs no beta header", and skills-2025-10-02 would select the beta's response shapes, whose versions are timestamps (Skills guide). A reply without a field the provider's reference requires, or naming another kind of record, is a SkillCallError, never a result with the field made up.

Objects

UniLM.SkillObjectType#
SkillObject

A skill stored by a provider's Skills API, as create_skill, retrieve_skill, update_skill and list_skills return it; raw holds it as the provider sent it.

  • id::String: the id the other Skills verbs take, and SkillReference on OpenAI.
  • name::String: OpenAI's name; Anthropic's display_name, from the SKILL.md's name unless create_skill set one.
  • description::Union{String,Nothing}: OpenAI's description; nothing on Anthropic, whose versions carry theirs.
  • default_version::Union{String,Nothing}: OpenAI's default_version, the version a reference without one loads; nothing on Anthropic, which has none.
  • latest_version::String: the newest version — OpenAI's latest_version, Anthropic's latest_version_id.
  • created_at::Int: the creation time in Unix seconds — OpenAI's created_at; Anthropic's, an RFC 3339 time, to the second.

The rest is in raw: Anthropic's source ({"type": "custom"} for a skill of yours) and updated_at. A reply without a field the provider requires, or naming another kind of record, is no skill: the call returns a SkillCallError.

UniLM.SkillVersionObjectType#
SkillVersionObject

One version of a skill, as create_skill_version, retrieve_skill_version and list_skill_versions return it; raw holds it as the provider sent it.

  • id::String: the version's id.
  • skill_id::String: the skill's id.
  • version::String: what the version verbs, skill_content and a reference take — OpenAI's version number ("1", "2", …), Anthropic's id.
  • name::String, description::String: from the version's SKILL.md.
  • created_at::Int: the creation time in Unix seconds.
UniLM.SkillListType#
SkillList

A page of SkillObjects from list_skills. has_more signals that further pages are available, and after is the cursor to pass as after for the next page — OpenAI's last_id, Anthropic's next_page —, nothing on the last page; raw holds the page as sent.

UniLM.SkillVersionListType#
SkillVersionList

A page of SkillVersionObjects from list_skill_versions, read as a SkillList is.

Result Types

UniLM.SkillSuccessType#

Successful create_skill, retrieve_skill or update_skill result wrapping a SkillObject.

UniLM.SkillListSuccessType#

Successful list_skills result wrapping a SkillList.

UniLM.SkillVersionSuccessType#

Successful create_skill_version or retrieve_skill_version result wrapping a SkillVersionObject.

UniLM.SkillVersionListSuccessType#

Successful list_skill_versions result wrapping a SkillVersionList.

UniLM.SkillDeleteSuccessType#

Successful delete_skill or delete_skill_version result: the service confirmed (deleted is always true) the removal of id, the id its reply names.

UniLM.SkillFailureType#

Skills API error result: HTTP status, the raw response body, and the request_id the service sent (x-request-id/request-id header), if any.

UniLM.SkillCallErrorType#

Skills API call that produced no usable reply (transport failure, timeout, cancel, or a 200 that could not be decoded); cause is the underlying exception — a UniLMTimeout for a timeout, a UniLMCancelled for a cancel.

skill_content returns the zip's bytes as a FileContentSuccess, which save_file_content writes to disk.

Request Functions

UniLM.create_skillFunction#
create_skill(path; display_name=nothing, service=OPENAIServiceEndpoint)

Upload a skill: path is its folder, whose root holds its SKILL.md (the skill's name and description in its front matter, then its instructions), or a .zip of that folder. A folder goes as one part per file — every file in it, its subfolders' too — each named by its path under the folder's name; a zip as one part. Hidden entries under the folder, each name starting with . (.env, .git/, .DS_Store), at any depth and with all they hold, are never sent. Returns SkillSuccess, SkillFailure or SkillCallError.

  • display_name (Anthropic only): the skill's label, up to 255 characters on one line; Anthropic takes the SKILL.md's name without one.

Refused with ArgumentError before anything is sent: a path that is no folder or .zip file, a folder without a SKILL.md at its root, more than 500 files to send on OpenAI, display_name on OpenAI, and a display_name longer than 255 characters or of more than one line.

Pass config::Union{Nothing,RequestConfig} to override the timeout budget for this call (a single bounded attempt; max_attempts does not apply): like every create, an upload is never sent again.

Pass cancel::Union{Nothing,CancelToken} (default: the ambient with_cancel token) to make the call cancellable: once the token is cancelled it returns a SkillCallError whose cause is a UniLMCancelled — without reading a file or sending anything when the token was already cancelled, at once when mid-request.

UniLM.list_skillsFunction#
list_skills(; limit=nothing, after=nothing, order=nothing, source=nothing, service=OPENAIServiceEndpoint)

List the skills, a page at a time: a SkillListSuccess whose SkillList holds the page's skills and the after of the next one.

  • limit: the page's size (OpenAI 0 to 100; Anthropic 1 to 1000, default 20).
  • after: where the page starts, the previous page's after.
  • order (OpenAI only): "asc" or "desc" by creation time.
  • source (Anthropic only): "custom" for your skills, "anthropic" for Anthropic's.

An order outside the two, order on Anthropic or source on OpenAI is an ArgumentError before anything is sent. config and cancel work as for create_skill.

UniLM.retrieve_skillFunction#
retrieve_skill(skill_id; service=OPENAIServiceEndpoint)

The skill skill_id: SkillSuccess, SkillFailure (a 404 for an unknown id) or SkillCallError. An empty id is an ArgumentError before anything is sent, as in every Skills verb. config and cancel work as for create_skill.

UniLM.update_skillFunction#
update_skill(skill_id; default_version, service=OPENAIServiceEndpoint)

Set the version of skill skill_id that a reference without one loads (OpenAI only): default_version is a version number, 2 or "2", sent as a string. Returns the skill as a SkillSuccess. Anthropic has no default version — a request names a version or "latest" —, so on ANTHROPICServiceEndpoint the call is an ArgumentError before anything is sent.

UniLM.delete_skillFunction#
delete_skill(skill_id; service=OPENAIServiceEndpoint)

Delete skill skill_id and every version of it: a SkillDeleteSuccess when the provider's deletion record names it — OpenAI's a "skill.deleted" object saying "deleted": true, Anthropic's a "skill_deleted" —, the SkillCallError otherwise.

UniLM.skill_contentFunction#
skill_content(skill_id; version=nothing, service=OPENAIServiceEndpoint)

Download a skill as the zip of its files: a FileContentSuccess of its bytes, which save_file_content writes to disk, else SkillFailure or SkillCallError. version is the version to download (a SkillVersionObject's version); without one, OpenAI serves the skill's default version. Anthropic serves a version only: there, a call without version is an ArgumentError before anything is sent.

UniLM.create_skill_versionFunction#
create_skill_version(skill_id, path; default=nothing, service=OPENAIServiceEndpoint)

Upload a new version of skill skill_id, from path as create_skill takes it: the whole skill, whose SKILL.md names the skill's name, its hidden entries (a name starting with .) never sent. Returns a SkillVersionSuccess.

  • default (OpenAI only): true makes the new version the skill's default.

default on Anthropic, whose newest version is the skill's latest_version, is an ArgumentError before anything is sent, as are the paths create_skill refuses.

UniLM.list_skill_versionsFunction#
list_skill_versions(skill_id; limit=nothing, after=nothing, order=nothing, service=OPENAIServiceEndpoint)

List the versions of skill skill_id, a page at a time, as list_skills lists skills (order on OpenAI only, by version number; Anthropic lists the newest first): a SkillVersionListSuccess.

UniLM.retrieve_skill_versionFunction#
retrieve_skill_version(skill_id, version; service=OPENAIServiceEndpoint)

The version version of skill skill_id (a SkillVersionObject's version; Anthropic takes "latest" too): a SkillVersionSuccess. OpenAI may answer a version just made with a 404 for a moment ("A newly uploaded version can briefly return 404").

UniLM.delete_skill_versionFunction#
delete_skill_version(skill_id, version; service=OPENAIServiceEndpoint)

Delete one version of skill skill_id: a SkillDeleteSuccess when the deletion record names it, read as delete_skill reads one. OpenAI refuses to delete the default version while others remain, and deleting the last deletes the skill; Anthropic refuses to delete a skill's only version.

Usage 

# OpenAI: upload the folder, add a version, make it the default
s = create_skill("skills/csv-sum")
s isa SkillSuccess || error("upload failed: $s")
id = s.response.id
v = create_skill_version(id, "skills/csv-sum"; default=true)
retrieve_skill(id).response.default_version          # "2"

# Load it into a container by reference, and its version 1 inline, from its zip: an inline skill is
# named and described as its SKILL.md names and describes it
zip = skill_content(id; version="1")
zip isa FileContentSuccess && save_file_content(zip, "csv-sum-1.zip")
c = create_container(name="sandbox", skills=[SkillReference(s.response),
                     InlineSkill("csv-sum-1.zip"; name=s.response.name, description=s.response.description)])

# Anthropic: a label, versions by id, the zip of one version
a = create_skill("skills/csv-sum"; display_name="CSV sum", service=ANTHROPICServiceEndpoint)
versions = list_skill_versions(a.response.id; service=ANTHROPICServiceEndpoint)
skill_content(a.response.id; version=a.response.latest_version, service=ANTHROPICServiceEndpoint)
delete_skill(a.response.id; service=ANTHROPICServiceEndpoint)   # its versions with it
