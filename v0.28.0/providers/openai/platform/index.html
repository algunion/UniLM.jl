Language models · OpenAI

Platform APIs

Besides its model APIs, OpenAI serves APIs that hold what a request works with — files, conversations, code-interpreter containers — and that run work beside it: batches, fine-tuning jobs, moderation, and the webhooks that report on them. UniLM wraps each with verbs of its own, on OPENAIServiceEndpoint unless a call names another service; OPENAIServiceEndpoint() returns that same type. The vector stores of file search are on Retrieval & file search, and images, speech and the Realtime API on Images, audio & realtime; which of these APIs other providers serve is on Capabilities by provider. Every verb, type and keyword is in the API reference: Files, Uploads, Conversations, Containers, Batch, Fine-tuning, Moderations and Webhooks. UniLM does not wrap OpenAI's Agents API, which "gives your application access to the Codex harness through an OpenAI-managed API" (Agents API).

These calls are not recorded, so their output on this page is quoted from dated runs.

What the platform verbs share

  • Results. A verb returns a typed result, and throws only for what it refuses before sending (Limits and refusals): a *Success; a *Failure for an error status, holding the status, the body as response and the x-request-id header as request_id; or a *CallError when no usable reply came — a transport failure, a timeout, a cancel, a reply that does not decode —, holding the text as error and the exception as cause. FileSuccess, FileFailure and FileCallError are the Files family, and the others are named alike (Results).
  • One attempt. Each call makes a single attempt, bounded by the call's config, a RequestConfig; max_attempts does not change it. A create is never sent again: a POST that timed out, or drew a gateway 5xx after OpenAI stored its object, may still have made it, so a failed upload_file does not prove that no file was made.
  • The key is read when the call is made: without OPENAI_API_KEY the result is the family's call error, whose cause is the KeyError naming it (Setup).
  • Cancellation. With the key set, the ambient CancelToken of with_cancel ends a call: a token already cancelled sends nothing, and a cancel during the call aborts it, either way with the call error, whose cause is a UniLMCancelled (Cancellation).
  • Cost. The results carry no usage: token_usage and estimated_cost throw for them. What OpenAI charges for storage, containers and batches is on its pricing page.
  • Deletes. A delete that OpenAI answers with a deletion record — of a file, a vector store, a container or a conversation — counts only when the record says "deleted": true: a reply without it, or with false, is the call error, the object being in place as far as UniLM can tell. delete_conversation_item is answered with the conversation, which UniLM returns as it came.
  • Capabilities. Each verb first checks that its service has the capability it needs — :files, :uploads, :vector_stores, :conversations, :containers, :batch, :fine_tuning, :moderation, :transcription (which :audio implies) or :realtime —, all of which OPENAIServiceEndpoint declares (realtime_connect, which throws rather than returning a result and does not observe the token, is on Realtime sessions), and refuses an endpoint that declares its capabilities without it, or declares none (Limits and refusals; Capabilities by provider).

Files and uploads

upload_file(path, purpose) sends a file to POST /v1/files as multipart/form-data, with the purpose "assistants", "batch", "fine-tune", "vision" or "user_data"; the Evals API's "evals" is refused (Limits and refusals), since OpenAI's Evals "become read-only" on 31 October 2026 and "are scheduled to shut down" on 30 November 2026 (deprecations). "Individual files can be up to 512 MB, and each project can store up to 2.5 TB of files in total"; the Batch API "only supports .jsonl files up to 200 MB in size", and fine-tuning .jsonl files (Upload file). list_files takes a purpose, a limit — "between 1 and 10,000, and the default is 10,000" — and after, the id of the last file of the page before (its has_more says whether one follows); retrieve_file reads one file's record, file_content its bytes, and delete_file removes it, which also is to "remove it from all vector stores" (Files).

write("questions.jsonl", """{"custom_id": "q1", "method": "POST", "url": "/v1/responses", "body": {"model": "gpt-6-sol", "input": "Name a prime number."}}\n""")
up = upload_file("questions.jsonl", "batch")
up isa FileSuccess || error("upload failed: $up")
f = up.response
f.filename, f.purpose, f.bytes
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# ("questions.jsonl", "batch", 127)

listed = list_files(purpose="batch", limit=5)
listed isa FileListSuccess || error("listing failed: $listed")
any(x -> x.id == f.id, listed.response.data)
# true

content = file_content(f.id)
content isa FileContentSuccess || error("the download failed: $content")
save_file_content(content, "questions_copy.jsonl")
# "questions_copy.jsonl"

delete_file(f.id)
# FileDeleteSuccess("file-UYtK7VGBUPApXVa8Uz7epn", true)
Evidence

Runs of 25 October 2026, 16:29–16:47 UTC, with UniLM's development branch after 0.26.0: OpenAI answered file_content of a file uploaded with the purpose "user_data" with HTTP 502 or 503 on each of three tries, while files with the purpose "batch" downloaded; four of ten delete_file calls drew HTTP 503 and succeeded when sent again; one upload_file drew HTTP 502, and a listing afterwards showed that no file had been made.

save_file_content writes the bytes atomically: to a temporary file beside the target, then renamed over it, so a failed write leaves an existing file whole; the file keeps its permission bits, a symbolic link is written through, and a directory is refused. An uploaded file goes to a Respond as input by its id, input_file(; id=…) for a document and input_image(; file_id=…) for an image (Input).

The Uploads API takes a large file in parts: "an Upload can accept at most 8 GB in total and expires after an hour after you create it", "Each Part can be at most 64 MB", and "The number of bytes uploaded upon completion must match the number of bytes initially specified when creating the Upload object" (Uploads). create_upload takes the Files purposes, "evals" refused as above (Limits and refusals); add_upload_part sends one part, the bytes you give it; complete_upload joins the parts in the order the list gives their ids, checking an md5 of the whole file when given one, and returns the upload with its file; cancel_upload ends one. UniLM does not split a file: a file larger than a part is sent a slice at a time, as the second block below does.

data = read("requests.jsonl")
up = create_upload(filename="requests.jsonl", purpose="batch", bytes=length(data), mime_type="text/jsonl")
up isa UploadSuccess || error("create_upload failed: $up")
up.response.status, up.response.bytes
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# ("pending", 456)

half = length(data) ÷ 2
p1 = add_upload_part(up.response.id, data[1:half])
p2 = add_upload_part(up.response.id, data[half+1:end])
(p1 isa UploadPartSuccess && p2 isa UploadPartSuccess) || error("a part failed: $p1, $p2")
done = complete_upload(up.response.id, [p1.response.id, p2.response.id])
done isa UploadSuccess || error("complete_upload failed: $done")
done.response.status, done.response.file.filename, done.response.file.bytes, done.response.file.purpose
# ("completed", "requests.jsonl", 456, "batch")

A file larger than a part goes up a slice at a time, each slice a part:

parts = String[]
for slice in Iterators.partition(data, 50_000_000)
    part = add_upload_part(up.response.id, collect(slice))
    part isa UploadPartSuccess || error("a part failed: $part")
    push!(parts, part.response.id)
end
done = complete_upload(up.response.id, parts)

Conversations

A conversation of OpenAI's Conversations API holds a conversation's items on OpenAI's side, with "its own durable identifier", and works with the Responses API (conversation state). create_conversation(; items, metadata) makes one — "You may add up to 20 items at a time" — and conversation_id reads its id, which a Respond's conversation takes: "Items from this conversation are prepended to input_items for this response request. Input items and output items from this response are automatically added to this conversation after this response completes" (Create a model response, conversation).

c = create_conversation(metadata=Dict("topic" => "ferries"))
c isa ConversationSuccess || error("create failed: $c")
conv = conversation_id(c.response)
r1 = respond("Which planet of the solar system is the largest?"; conversation=conv,
             instructions="You are a concise assistant: answer in one short sentence.")
r1 isa ResponseSuccess || error("respond failed: $r1")
output_text(r1)
# Run on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-6-sol:
# "Jupiter is the largest planet in the solar system."

r2 = respond("And the smallest?"; conversation=conv,
             instructions="You are a concise assistant: answer in one short sentence.")
r2 isa ResponseSuccess || error("respond failed: $r2")
output_text(r2), r2.response.raw["conversation"]["id"] == conv, token_usage(r2).prompt_tokens
# ("Mercury is the smallest planet in the solar system.", true, 57)

items = list_conversation_items(conv; order="asc")
items isa ConversationItemListSuccess || error("listing failed: $items")
[(item.type, item.raw["role"]) for item in items.response.data]
# 4-element Vector{Tuple{String, String}}:
#  ("message", "user")
#  ("message", "assistant")
#  ("message", "user")
#  ("message", "assistant")

delete_conversation(conv)
# ConversationDeleteSuccess("conv_6ade313d1634819582bab2425f6f512a0c45c1ed494760a4", true)

conversation is sent as given, the id or a Dict("id" => …), and a Respond refuses it together with previous_response_id (Limits and refusals); the conversation's turns come back from OpenAI, so the second request sends only its question, and tool_loop chains through the conversation when the Respond sets one (Tools). "Conversation objects and items in them are not subject to the 30 day TTL" of a stored response (conversation state). retrieve_conversation and update_conversation(id, metadata) read and change the conversation's record, add_conversation_items appends items without a response, list_conversation_items pages through them (limit, order, after), retrieve_conversation_item(id, item_id; include) reads one, "a single item from a conversation", as a ConversationItemSuccess, and delete_conversation_item removes one, returning the conversation.

Code interpreter and containers

The code interpreter, a hosted tool of the Responses API, runs Python that the model writes, and "requires a container object", "a fully sandboxed virtual machine that the model can run Python code in" (Code Interpreter). code_interpreter() sends an auto container, {"type": "auto"}, which "automatically creates a new container, or reuses an active container that was used by a previous code_interpreter_call item in the model's context"; container takes OpenAI's other forms:

  • a Dict, sent as given: an auto container with a memory_limit, "1g" (the default), "4g", "16g" or "64g", which "applies for the entire life of that container";
  • a String, the id of a container made with create_container, sent as "container": "cntr_…".

file_ids, the ids of uploaded files, go inside the container Dict, the auto one unless you give another. With a container id, or beside a Dict that names file_ids itself, they are refused (Limits and refusals): a container made beforehand takes its files through create_container(; file_ids) and add_container_file.

UniLM.encode_agentic shows the tool each form sends, with no key and no request:

sent(tool) = UniLM.encode_agentic(OPENAIServiceEndpoint, Respond(input="Total the prices.", tools=[tool]))
println(sent(code_interpreter()))
println(sent(code_interpreter(container=Dict("type" => "auto", "memory_limit" => "4g"),
                              file_ids=["file-abc123"])))
println(sent(code_interpreter(container="cntr_abc123")))

refusal = try code_interpreter(container="cntr_abc123", file_ids=["file-abc123"]); nothing catch err; err end
refusal isa ArgumentError || error("expected the request to be refused")
print(refusal.msg)

A run in a container made beforehand, with tool_choice="required" so that the model runs the tool, and include=["code_interpreter_call.outputs"] for what the code printed:

code_interpreter_outputs returns the response's code_interpreter_call items as OpenAI sent them, each with the code the model ran, the container_id it ran in and, with the include, its outputs. "A container expires if it is not used for 20 minutes. When this happens, using the container in v1/responses will fail", and its data is discarded: "You should download any files you may need from the container while it is active" (Code Interpreter). create_container(; name, file_ids, expires_after) sends no memory_limit, so a container it makes has OpenAI's default, "1g"; retrieve_container, list_containers and delete_container read, list and delete containers, and add_container_file(id, path) uploads a file into one, returning a ContainerSuccess whose response is the file's record, its path where the code sees it; a path that is no file is refused before anything is sent (Limits and refusals). It does not wrap the endpoints that list, read or delete the files in a container. A container bills "1 GB $0.03, 4 GB $0.12, 16 GB $0.48, 64 GB $1.92 per 20-minute session per container" (pricing), which estimated_cost leaves out (Cost and usage).

Batches

The Batch API runs requests "with 50% lower costs, a separate pool of significantly higher rate limits, and a clear 24-hour turnaround time" (Batch API). Its input is a .jsonl file, uploaded with the purpose "batch", each of whose lines is one request: a unique custom_id, the method, the url — /v1/responses, /v1/chat/completions, /v1/embeddings, /v1/completions, /v1/moderations, /v1/images/generations or /v1/images/edits — and the body, "the same as the parameters for the underlying endpoint"; "each input file can only include requests to a single model", and "A single batch may include up to 50,000 requests". The bodies can be the ones UniLM would send, so its request rules hold for them: UniLM.encode_agentic of a Respond, or UniLM.encode_request of a Chat.

using JSON
questions = ["What is the capital of Norway?", "What is the capital of Peru?"]
lines = [JSON.json(Dict("custom_id" => "capital-$i", "method" => "POST", "url" => "/v1/responses",
                        "body" => JSON.parse(UniLM.encode_agentic(OPENAIServiceEndpoint,
                                      Respond(input=q, instructions="Answer with the city's name only.")))))
         for (i, q) in enumerate(questions)]
write("capitals.jsonl", join(lines, "\n") * "\n")
lines[1]
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# "{\"body\":{\"input\":\"What is the capital of Norway?\",\"instructions\":\"Answer with the city's name only.\",\"model\":\"gpt-6-sol\"},\"custom_id\":\"capital-1\",\"method\":\"POST\",\"url\":\"/v1/responses\"}"

input = upload_file("capitals.jsonl", "batch")
input isa FileSuccess || error("upload failed: $input")
batch = create_batch(input.response.id, "/v1/responses"; metadata=Dict("job" => "capitals"))
batch isa BatchSuccess || error("the batch was not created: $batch")
batch.response.status, get(batch.response.raw, "completion_window", nothing)
# ("validating", "24h")

seen = retrieve_batch(batch.response.id)   # one read
seen isa BatchSuccess || error("the read failed: $seen")
seen.response.status
# "validating"

stopped = cancel_batch(batch.response.id)
stopped isa BatchSuccess || error("the cancel failed: $stopped")
stopped.response.status
# "cancelling"

Read back once the cancel had settled:

settled = retrieve_batch(batch.response.id)
settled isa BatchSuccess || error("the read failed: $settled")
settled.response.status, settled.response.request_counts, settled.response.output_file_id
# Read on 25 October 2026, eleven minutes after the cancel:
# ("cancelled", Dict{String, Any}("completed" => 0, "failed" => 0, "total" => 0), nothing)

create_batch(input_file_id, endpoint; completion_window="24h", metadata) sends the endpoint as given — "the completion window can only be set to 24h" —, and retrieve_batch, list_batches and cancel_batch read, list and cancel batches. A batch moves through OpenAI's statuses: validating, in_progress, finalizing and completed; failed when "the input file has failed the validation process"; expired when it "was not able to be completed within the 24-hour time window"; and cancelling, which "may take up to 10 minutes", then cancelled. poll_batch reads a batch until it is completed, failed, cancelled or expired (Long-running jobs).

The results are files: output_file_id names the output, which "will have one response line for every successful request line in the input file", and error_file_id the errors; "the output line order may not match the input line order", so match lines by custom_id. Either id is nothing while the batch has no such file, as for the batch cancelled above, so read it before calling file_content:

done = poll_batch(batch.response.id)
done isa BatchSuccess || error("the batch did not finish: $done")
out = done.response.output_file_id
if !isnothing(out)
    content = file_content(out)
    content isa FileContentSuccess || error("the download failed: $content")
    save_file_content(content, "capitals_out.jsonl")
end

An expired batch's "unfinished requests within that batch are cancelled, and any responses to completed requests are made available via the batch's output file. You will be charged for tokens consumed from any completed requests." The batch.completed, batch.cancelled, batch.expired and batch.failed webhooks report the end without a poll (Webhooks).

Fine-tuning

"OpenAI is winding down the fine-tuning platform. The platform is no longer accessible to new users. Eligible existing customers can create training jobs until January 6, 2027, unless the base model shuts down earlier", and "Fine-tuned models remain available for inference until their base model shuts down" (supervised fine-tuning). The default model takes no fine-tuning: its model page lists v1/fine-tuning as "Not supported" (GPT-6 Sol). No job was run for this page, so this block has no output:

train = upload_file("train.jsonl", "fine-tune")
train isa FileSuccess || error("upload failed: $train")
job = create_fine_tuning_job(model=base_model, training_file=train.response.id,
                             method=Dict("type" => "supervised",
                                         "supervised" => Dict("hyperparameters" => Dict("n_epochs" => 2))))
job isa FineTuningSuccess || error("the job was not created: $job")
r = retrieve_fine_tuning_job(job.response.id)
r isa FineTuningSuccess || error("the read failed: $r")
r.response.status, r.response.fine_tuned_model

base_model is a model your organization may still fine-tune. create_fine_tuning_job sends model, training_file and, when set, validation_file, method — a Dict that names the "supervised", "dpo" or "reinforcement" method with its hyperparameters —, suffix and metadata. A job's status is one of "validating_files, queued, running, pausing, paused, succeeded, failed, or cancelled" (Fine-tuning), and fine_tuned_model names the model it made, which a Chat or a Respond takes as its model. No verb waits for a job: read it with retrieve_fine_tuning_job, page through list_fine_tuning_events and list_fine_tuning_checkpoints (limit, after), or take the fine_tuning.job.succeeded, fine_tuning.job.failed and fine_tuning.job.cancelled webhooks (Webhooks). cancel_fine_tuning_job and list_fine_tuning_jobs cancel and list jobs; OpenAI's pause, resume and checkpoint permissions are not wrapped.

Moderation

moderate(input; model="omni-moderation-latest") classifies text and images with OpenAI's Moderations API, POST /v1/moderations. "The omni-moderation-latest model accepts text and image inputs. It doesn't classify audio. The moderation endpoint is free to use, and image files can be up to 20 MB" (moderation). input is a string, a vector of strings, or a vector of content parts, text and image_url ones, which are one input together:

m = moderate("I will find where you live and hurt you.")
m isa ModerationSuccess || error("moderation failed: $m")
is_flagged(m), m.response.model
# Run on 25 October 2026 with UniLM's development branch after 0.26.0:
# (true, "omni-moderation-latest")

row = m.response.results[1]
sort!([k for (k, v) in row.categories if v === true])
# 3-element Vector{String}:
#  "harassment"
#  "harassment/threatening"
#  "violence"

first(sort!(collect(row.category_scores); by=last, rev=true), 3)
# 3-element Vector{Pair{String, Any}}:
#                "violence" => 0.8667556675090715
#  "harassment/threatening" => 0.5270943475735724
#              "harassment" => 0.48830641686805554

two = moderate(["The ferry leaves at nine.", "I will find where you live and hurt you."])
two isa ModerationSuccess || error("moderation failed: $two")
[r.flagged for r in two.response.results], is_flagged(two)
# (Bool[0, 1], true)

A ModerationResponse holds one ModerationResult per input — its flagged, its categories, each true or false, and its category_scores — and the model; each result keeps its row as raw. A reply whose rows do not match the inputs one for one, or a row without flagged, is a ModerationCallError: a verdict that cannot be matched to its input is no verdict. is_flagged is true when any row is flagged, and throws an ArgumentError for a ModerationFailure or a ModerationCallError rather than answering false, which would let unmoderated content through: check issuccess first, and decide what a missing verdict means. A Chat or a Respond can also moderate its own input and output with a ModerationConfig, whose results a Chat's result keeps as its moderation and a Respond's in result.response.raw["moderation"] (Chat Completions, Request options): ModerationConfig(; model, input_mode, output_mode) needs its model, and sends each mode set, "score" or "block", as the policy of its side. The moderation of an image request is another setting, the filtering level of the image models (Image generation).

Webhooks

OpenAI's webhooks "allow you to receive real-time notifications about events in the API, such as when a batch completes, a background response is generated, or a fine-tuning job finishes. Webhooks are delivered to an HTTP endpoint you control, following the Standard Webhooks specification", and each endpoint, made on OpenAI's dashboard, comes with "a signing secret to use for server-side verification of incoming webhook requests" (webhooks). verify_webhook(payload, headers, secret) checks a delivery against it, with no request: payload is the raw body, headers the request's headers, which hold webhook-id, webhook-timestamp and webhook-signature, and secret the signing secret, with or without its whsec_ prefix. It returns true when a fresh v1 signature of the delivery is valid, false otherwise. A stored delivery, here with a made-up secret, verifies with tolerance_seconds=Inf, which skips the time check:

secret = "whsec_dW5pbG0tZG9jcy1leGFtcGxlLXNlY3JldC0zMmJ5dGU="
payload = """{"object": "event", "id": "evt_6ade2f3c7a3881908e0a6a1f2c3b4d5e", "type": "batch.completed", "created_at": 1792946400, "data": {"id": "batch_6ade2f3a1b2c8190a7d6e5f4c3b2a190"}}"""
headers = Dict("webhook-id" => "wh_6ade2f3c90f48190b5e1c2a7d4f61b0e", "webhook-timestamp" => "1792946400",
               "webhook-signature" => "v1,KuH1/bBMozlJfbeUhblkBOne1gUNyD41q48+86kVGAQ=")
verify_webhook(payload, headers, secret; tolerance_seconds=Inf), verify_webhook(payload, headers, secret)

The second call keeps the default window, 300 seconds either side of now, and the delivery is older, so it fails, as a replayed delivery does. parse_webhook reads a verified payload into a WebhookEvent:

event = parse_webhook(payload)
event.type, event.data["id"], event.type in WEBHOOK_EVENTS

WEBHOOK_EVENTS lists the event types: responses, batches and fine-tuning jobs that end, incoming calls of the Realtime and Live APIs, and safety notices. It leaves out the eval.run.* events, which OpenAI sends until the Evals API shuts down on 30 November 2026, so a filter on it drops them. On a server, the payload is the request's body as it arrived, before any JSON parsing, here in an HTTP.serve handler, with handle_batch your own function:

using HTTP
HTTP.serve("0.0.0.0", 8000) do req
    payload = String(req.body)
    verify_webhook(payload, req.headers, ENV["OPENAI_WEBHOOK_SECRET"]) || return HTTP.Response(400)
    event = parse_webhook(payload)
    event.type == "batch.completed" && Threads.@spawn handle_batch(event.data["id"])
    return HTTP.Response(200)
end

OpenAI asks for a quick 2xx: "If the endpoint doesn't return a successful (2xx) status code, or doesn't respond within a few seconds, the webhook request will be retried. OpenAI will continue to attempt delivery for up to 72 hours with exponential backoff", and it "may deliver duplicate copies of the same webhook event. You can use the webhook-id header as an idempotency key to deduplicate" (webhooks). A negative or NaN tolerance is refused, and so is a secret that is not base64 after its whsec_ prefix, such as a placeholder like whsec_*** or misplaced padding; whitespace around the secret is ignored. An empty secret — "", as an unset variable read with a default gives, or whsec_ alone — is refused whatever the delivery, since anyone can sign with an empty key (Limits and refusals).

poll_batch and poll_file_batch read their job every interval seconds until it reaches a final status, which they return, for at most timeout seconds of wall-clock time (Inf waits indefinitely). A failure worth another read — a status UniLM sends a request again after (When something fails), or a GET that timed out — is polled through; any other failure is returned as it came. When the time runs out, the result is the family's call error, BatchCallError or VectorStoreCallError, with a UniLMTimeout(:deadline, …) as cause and the last batch it read as last_observed (nothing if no read succeeded). cancel (the ambient token unless given) ends a poll at once, mid-read or mid-pause, with the call error and a UniLMCancelled as cause; config bounds each read.

A background response is read back with get_response and stopped with cancel_response (Stored responses), here with one read between them:

started = respond("Write a detailed history of lighthouses, century by century.";
                  background=true, max_output_tokens=4000)
started isa ResponseSuccess || error("the background request failed: $started")
id = started.response.id
response_status(started)
# Run on 25 October 2026 with UniLM's development branch after 0.26.0 on gpt-6-sol:
# "queued"

sleep(3)
response_status(get_response(id))
# "in_progress"

response_status(cancel_response(id)), response_status(cancel_response(id))
# ("cancelled", "cancelled")

"Keep polling while the request is in the queued or inprogress state. When it leaves these states, it has reached a final (terminal) state", and "Cancelling twice is idempotent - subsequent calls simply return the final Response object" (background mode). A background response that failed comes back from `getresponseandcancelresponseas aResponseFailure, asrespondreturns a failed response: itsstatusis 200, itsresponsethe response's JSON with OpenAI'serror, and [responsestatus](@ref) reads"failed"`.

A background request may set store=false: "Background requests can use store=false, but response data is temporarily stored to support asynchronous execution and polling", and get_response reads such a response while OpenAI holds it. A stored response (store=true, the default) is kept "for at least 30 days, subject to the data retention exceptions" (Create a model response), and the background guide names two for background requests: in a Zero Data Retention project they "run with store=false", their data kept "for roughly 10 minutes"; in a Modified Abuse Monitoring project, "Background responses are retained after the polling period only when store=true is explicitly provided. If store is omitted or set to false for a background request, the response is deleted after roughly 10 minutes" (background mode).
