Service Endpoints

Types for configuring multi-backend service endpoints, and the extension API a new backend implements.

Abstract Types

UniLM.ServiceEndpointType#
ServiceEndpoint

Abstract supertype for LLM service backends. Subtypes control URL routing and authentication.

OpenAI-compatible backends subtype OpenAIWireEndpoint (itself a subtype of ServiceEndpoint) to inherit the chat request/response encoding and SSE handling; backends with a native wire (Anthropic, Gemini) subtype ServiceEndpoint directly and implement the wire seam (encode_request/decode_response/handle_sse_event!) themselves.

Built-in subtypes:

  • OPENAIServiceEndpoint — OpenAI API (default)
  • AZUREServiceEndpoint — Azure OpenAI Service
  • GEMINIOpenAIServiceEndpoint — Google Gemini via OpenAI-compatible endpoint
  • GEMINIServiceEndpoint — Google Gemini native generateContent API
  • ANTHROPICServiceEndpoint — Anthropic (Claude) native Messages API
  • OllamaEndpoint — a local Ollama server (native chat and embeddings API)
  • DeepSeekEndpoint — DeepSeek API (chat, FIM and prefix completion)
  • GenericOpenAIEndpoint — any OpenAI-compatible provider (Mistral, vLLM, LM Studio, etc.)
  • TYPESAFEServiceEndpoint — TypeSafe's System One (decisions only)
UniLM.OpenAIWireEndpointType#
OpenAIWireEndpoint <: ServiceEndpoint

Abstract supertype for backends that speak the OpenAI-compatible chat wire. Subtypes inherit the OpenAI Chat Completions request/response encoding (encode_request/decode_response) and the default SSE stream handling (handle_sse_event!) for free, so a new OpenAI-compatible provider defines only get_url and auth_header (plus, optionally, the _api_base_url pattern that routes the Responses/agentic surface).

Backends that speak a genuinely different wire (Anthropic's Messages API, Gemini's native generateContent) subtype ServiceEndpoint directly and additionally implement encode_request, decode_response, and handle_sse_event!. A bare ServiceEndpoint subtype that omits those methods fails with a MethodError at call time rather than silently emitting OpenAI-shaped requests to a foreign API.

Built-in OpenAI-wire subtypes: OPENAIServiceEndpoint, AZUREServiceEndpoint, GEMINIOpenAIServiceEndpoint, GenericOpenAIEndpoint, DeepSeekEndpoint, and OllamaEndpoint, which overrides the chat seam with Ollama's native wire and keeps the OpenAI-wire Responses and completions routes.

UniLM.ANTHROPICServiceEndpointType#
ANTHROPICServiceEndpoint
ANTHROPICServiceEndpoint(; betas=String[], user_profile_id=nothing, workspace_id=nothing,
                         inference_geo=nothing)

Anthropic (Claude) native Messages API endpoint. Requires the ANTHROPIC_API_KEY env variable. Native wire format (content blocks, top-level system, user/assistant roles) — NOT OpenAI-compatible.

The type itself (service=ANTHROPICServiceEndpoint) is the endpoint with no options set. An instance adds options that every request through it carries (Messages API):

  • betas: beta feature names, sent comma-joined in the anthropic-beta header (beta headers). UniLM sends the names and models no beta's request fields or response blocks; the one it reads is "fast-mode-2026-02-01", which service_tier="fast" needs on Claude Opus 5 and Opus 4.8. list_models sends no anthropic-beta header: Anthropic's Models API reference marks it deprecated on GET /v1/models.
  • user_profile_id: the anthropic-user-profile-id header, the uprof_ id of the end customer the requests are made for (user profiles). list_models does not send it: Anthropic's Models API reference names no such header for GET /v1/models.
  • workspace_id: the anthropic-workspace-id header, the workspace of a credential that can act on more than one.
  • inference_geo: "global" or "us", the request's inference_geo, where inference runs (data residency); nothing leaves the workspace default. The Claude 4.5 models (Opus 4.5, Sonnet 4.5, Haiku 4.5) and earlier answer it with HTTP 400, so a request for one of them throws ArgumentError.

estimated_cost bills US-only inference (a usage that reports inference_geo "us") at 1.1× every rate on Claude 4.6 and later; an earlier model is billed at the standard rates, whatever region its usage reports (data residency pricing). A reply at Priority Tier (a usage that reports service_tier "priority") is estimated at the list rates, as at the standard tier: Priority Tier draws down an organization's contracted capacity commitment (service tiers).

The constructor throws ArgumentError for a blank value, a value that holds a control character (CR, LF, …), a beta name that holds a comma, and an inference_geo other than "global" or "us". Instances with the same options are equal (==, hash).

The fields are read-only: to change an option, build a new endpoint. betas is copied at construction but is a Vector, so it can still be changed in place; that changes the endpoint's hash (a Dict or Set holding it no longer finds it), and the beta names are checked again by the same rule when the header is built, so a name changed in place that breaks it is refused before anything is sent (the verb returns the ArgumentError as the cause of its call-error result).

claude = ANTHROPICServiceEndpoint(user_profile_id="uprof_011CZkZCu8hGbp5mYRQgUmz9", inference_geo="us")
chat = Chat(service=claude, model="claude-haiku-5-5")
UniLM.TYPESAFEServiceEndpointType#
TYPESAFEServiceEndpoint <: ServiceEndpoint

TypeSafe System One API endpoint (model family Jev). Requires the TYPESAFE_API_KEY environment variable; TYPESAFE_BASE_URL overrides the API root and TYPESAFE_DEFAULT_MODEL the default model name. It speaks TypeSafeProtocol, and it is the System One backend a call uses when it names none and no with_system_one scope sets another.

This endpoint speaks neither the OpenAI chat wire nor any other chat wire: it declares only :system_one and :models, so ask and list_models accept it while the verbs — chatrequest!, respond, embeddingrequest!, moderate and the other OpenAI platform verbs — reject it up front with an ArgumentError rather than posting a request no server here would answer. A Chat or an Embeddings that names this endpoint can be built only with an explicit model= (without one the constructor throws ArgumentError, since there is no default model to resolve); sending it is refused. TYPESAFEServiceEndpoint() returns the type.

TYPESAFEServiceEndpoint is not a chat backend: it serves TypeSafe's System One model, Jev (System One API), and declares only :system_one and :models, so the chat, Responses and embedding verbs reject it up front. OPENAIServiceEndpoint answers System One requests too, through OpenAI's Decisions API, and so does an OllamaEndpoint, from a local decision model.

Generic Endpoint

UniLM.GenericOpenAIEndpointType#
GenericOpenAIEndpoint <: OpenAIWireEndpoint
GenericOpenAIEndpoint(base_url, api_key, key_env="")

Configurable endpoint for any OpenAI-compatible API provider. Supports Chat Completions, Embeddings, FIM, transcription and (where the provider implements it) the Responses API.

Fields

  • base_url::String: Base URL without trailing slash (e.g., "http://localhost:11434")
  • api_key::String: API key for Bearer auth, sent as is when not empty.
  • key_env::String: The environment variable that holds the key when api_key is empty, read each time a request is built, so a missing variable fails that request, naming it; "" reads none.

An empty key, given or read, sends no Authorization header: use "" for local servers with no auth.

A request goes out with its fields as set and under their own names, except on Mistral's host, as MistralEndpoint() is: there a Chat's max_completion_tokens goes out as max_tokens (taken over a max_tokens also set), its seed as random_seed, and an Embeddings request's dimensions as output_dimension, the names Mistral's references give them.

Example

# vLLM (local)
chat = Chat(service=GenericOpenAIEndpoint("http://localhost:8000", ""),
            model="Qwen/Qwen3-8B")

# Mistral: GenericOpenAIEndpoint("https://api.mistral.ai", "", "MISTRAL_API_KEY")
chat = Chat(service=MistralEndpoint(), model="mistral-large-latest")
UniLM.ServiceEndpointSpecType#
ServiceEndpointSpec

Type alias accepting both marker types (OPENAIServiceEndpoint) and instances (GenericOpenAIEndpoint(...)). Used as the type of service fields. The field-less built-in endpoints — OPENAIServiceEndpoint, AZUREServiceEndpoint, GEMINIServiceEndpoint, GEMINIOpenAIServiceEndpoint, TYPESAFEServiceEndpoint — are passed as types: calling one, OPENAIServiceEndpoint(), returns the type.

UniLM.MistralEndpointFunction#
MistralEndpoint(; api_key=nothing) -> GenericOpenAIEndpoint

Pre-configured endpoint for Mistral AI API. A given api_key is sent as is; without one the key is read from MISTRAL_API_KEY each time a request is built (GenericOpenAIEndpoint("https://api.mistral.ai", "", "MISTRAL_API_KEY")), so building the endpoint needs no key and a missing variable fails the request, naming it. Requests go out under Mistral's names: a Chat's max_completion_tokens as max_tokens, its seed as random_seed, an Embeddings request's dimensions as output_dimension (GenericOpenAIEndpoint).

UniLM.DeepSeekEndpointType#
DeepSeekEndpoint <: OpenAIWireEndpoint
DeepSeekEndpoint(; api_key=nothing)

Pre-configured endpoint for DeepSeek API. Supports chat completions, tool calling, FIM completion, and prefix completion.

api_key::Union{String,Nothing}: a given key is sent as is; nothing (the default) reads DEEPSEEK_API_KEY each time a request is built, so building the endpoint needs no key and a missing variable fails the request, naming it.

FIM and prefix completion use the beta base URL (https://api.deepseek.com/beta).

OllamaEndpoint and its options are on the Ollama page.

Azure Deployment Mapping

Azure requires model-to-deployment name mappings. Use add_azure_deploy_name! to register custom mappings:

UniLM.add_azure_deploy_name!Function#
add_azure_deploy_name!(model::String, deploy_name::String)

Register an Azure OpenAI deployment for a given model name. Without a registration the deployment is read from AZURE_OPENAI_DEPLOY_NAME_<MODEL> (model id upper-cased, other characters mapped to _) when a request is built.

Example

add_azure_deploy_name!("gpt-5.2", "my-gpt52-deployment")

using UniLM

# Register a custom deployment for a specific model
UniLM.add_azure_deploy_name!("gpt-5.2", "my-gpt52-deploy")
println("Registered deployment: ", UniLM._MODEL_ENDPOINTS_AZURE_OPENAI["gpt-5.2"])
delete!(UniLM._MODEL_ENDPOINTS_AZURE_OPENAI, "gpt-5.2")  # cleanup

Selecting a Backend

Pass the service keyword to any request constructor:

chat = Chat(service=UniLM.AZUREServiceEndpoint, model="gpt-5.2")
println("Service: ", chat.service)
println("Model: ", chat.model)

Extension API

The functions a new backend adds methods to, and the stream-state types its handlers mutate. They are declared public but not exported: qualify them (UniLM.get_url) when adding methods. Write your own backend walks through both cases — an OpenAI-compatible provider (routing and authentication only) and a provider with its own wire (the chat and agentic seams). Pre-1.0, this contract can still change in a minor release, under the CHANGELOG's Breaking heading.

Routing, authentication and defaults

UniLM.get_urlFunction#
get_url(request) -> String
get_url(service, request) -> String

The URL a request is sent to. get_url(chat), get_url(emb) and get_url(r::Respond) dispatch on the request's service, so a backend adds get_url(::MyEndpoint, ::Chat) (and, for the surfaces it serves, ::Embeddings or ::Respond): dispatch on the instance for an endpoint with fields, on ::Type{MyEndpoint} for a singleton. The built-in methods return the provider's documented URLs.

Public extension API (not exported); see the Custom Backends guide.

UniLM.auth_headerFunction#
auth_header(service) -> Vector{Pair{String,String}}

The headers sent with every request to service: its credentials, where it takes any, and the Content-Type. A backend adds auth_header(::MyEndpoint) (or auth_header(::Type{MyEndpoint}) for a singleton endpoint). A built-in endpoint that takes a key sends the key it was given, or else reads its key variable from the environment when a request is built, so a missing variable surfaces in the verb's call-error result, naming it: as a KeyError, or for TYPESAFEServiceEndpoint as an ArgumentError naming the variable, which a blank value gets too. An OllamaEndpoint sends no credentials (a local server takes none), except to Ollama's cloud, https://ollama.com, which gets OLLAMA_API_KEY as a Bearer token, read here, a missing or blank one an ArgumentError naming the variable (these are the headers of its inference requests; its model verbs go without the key when it is unset); and a GenericOpenAIEndpoint whose key is empty sends no Authorization header.

Public extension API (not exported); see the Custom Backends guide.

UniLM.default_modelFunction#
default_model(service) -> Union{String, Nothing}

Return the default chat/completions model for the given service endpoint. Returns nothing for generic and user-defined endpoints (model must be specified explicitly; Chat then throws an ArgumentError when it is not). A backend adds default_model(::MyEndpoint) to make model= optional for it.

Public extension API (not exported); see the Custom Backends guide.

provider_capabilities (exported) is the capability hook: an endpoint that defines it opts into validation against that set.

Chat wire seam

UniLM.encode_requestFunction#
encode_request(service, chat::Chat) -> String

Serialize chat into the provider's request body. The OpenAIWireEndpoint default emits OpenAI Chat Completions JSON. An ArgumentError thrown here — an option the provider or model cannot express — is local validation: chatrequest! calls the encoder before any network I/O and lets it propagate.

Public extension API (not exported); see the Custom Backends guide.

UniLM.decode_responseFunction#
decode_response(service, resp::HTTP.Response)

Parse a provider's 200 response into (; message::Message, usage::Union{TokenUsage,Nothing}, model::Union{String,Nothing}): the reply, its token usage, and the model id the provider reports having served it (nothing when it reports none), which becomes the result's model and prices the call. model is optional: a decoder that returns (; message, usage) reports no model. So are logprobs and moderation, the reply's log probabilities and moderation results (Dict{String,Any} or nothing), which become the result's fields of those names. The OpenAIWireEndpoint default reads OpenAI Chat Completions (extract_message). A body that is not a valid reply should throw: chatrequest! reports the exception as an LLMCallError carrying it in cause, never as an empty success.

Public extension API (not exported); see the Custom Backends guide.

UniLM.handle_sse_event!Function#
handle_sse_event!(service, event::AbstractString, payload::AbstractString,
                  state::StreamState) -> Symbol

Per-provider chat-streaming event handler — the seam that replaces decode_stream_chunk (removed in 0.11.3). Called by the stream driver once per complete data: payload, with the current SSE event name. Mutates state and returns

  • :continue — keep reading;
  • :done — sentinel end-of-stream ([DONE], Anthropic message_stop);
  • :error — terminal in-band error; the handler MUST store the decoded payload in state.error (the driver then returns a non-success result).

Text deltas are appended to BOTH state.content and state.pending_delta (the driver forwards the latter to the streaming callback). Throwing on an undecodable payload is safe: the dispatcher logs the payload, counts it in the result's sse_dropped and drops it, the rest of the stream is read, and a stream that ends without its turn is an LLMFailure. The OpenAIWireEndpoint default reads OpenAI Chat Completions chunks and ends at [DONE]; a provider without a sentinel (native Gemini) never returns :done, and its stream ends at EOF with state.finish_reason recorded.

Public extension API (not exported): a backend adds a method for its own service type (dispatch is on the first argument); see the Custom Backends guide. A streamed chatrequest! on an endpoint with no method throws the MethodError for this function before anything is sent, as a missing encode_request does, and so does a streamed respond on one with no decode_agentic_stream.

UniLM.StreamStateType#
StreamState()

Mutable accumulator for one streamed chat attempt, filled by handle_sse_event! and read by the stream driver. A handler appends text to both content and pending_delta (the driver forwards the latter to the streaming callback), refusal text to refusal, and records finish_reason, usage (a TokenUsage), the model the provider reports having served (the result's model; nothing when it reports none) and, for an in-band error, the decoded payload in error. service_tier holds the billed tier a chunk (or the response head) reported, for a handler whose provider reports it apart from the usage, and continuation_token the token a provider returns for continuing a long generation in another request. audio is filled by the OpenAI-wire handler only, from a streamed audio reply's delta.audio updates, and becomes the message's AudioOutput; a handler of another wire leaves it nothing. logprobs and moderation become the result's fields of those names: each token list a chunk gives extends the list of its name ("content", …), and each moderation object's results are merged in. Tool calls live in tool_calls by index as Dict("id" => …, "type" => "function", "function" => Dict("name" => …, "arguments" => …)); "complete" => true on an entry tells the driver the call has finished streaming. The raw_* fields capture provider-native content blocks for verbatim round-trip, and sse_dropped counts undecodable payloads. A retried attempt starts from a fresh state.

Public extension API (not exported); see the Custom Backends guide.

Agentic wire seam

UniLM.encode_agenticFunction#
encode_agentic(service, r::Respond) -> String

Serialize r into the request body of service's agentic surface. The OpenAIWireEndpoint default emits OpenAI Responses JSON; a backend with its own agentic wire overrides it (the Gemini Interactions backend is the in-repo reference). An ArgumentError thrown here — a field the wire cannot express — is local validation: respond calls the encoder before any network I/O and lets it propagate.

Public extension API (not exported); see the Custom Backends guide.

UniLM.decode_agenticFunction#
decode_agentic(service, resp::HTTP.Response) -> ResponseObject

Parse service's 200 response into the neutral ResponseObject, whose output uses the OpenAI Responses item shapes the accessors read. A body that is not a valid response should throw: respond and the lifecycle operations report the exception as a ResponseCallError carrying it in cause.

Public extension API (not exported); see the Custom Backends guide.

UniLM.decode_agentic_streamFunction#
decode_agentic_stream(service, chunk::String, state::AgenticStreamState)

Streaming half of the agentic wire seam: consume one raw read's bytes, mutate state (an AgenticStreamState; text deltas go to both textbuff and pending_delta), and return (; done, event, data, terminal): done is true at a terminal event, terminal is :completed, :failed, :incomplete or :error, and data holds that event's decoded payload. Default: OpenAI Responses SSE via _parse_response_stream_chunk.

A raw read can hold several payloads, so the method drops an undecodable payload itself and counts it in state.sse_dropped, as the built-in methods do; an exception it throws ends the streamed respond as a ResponseCallError with the exception in cause.

Public extension API (not exported); see the Custom Backends guide. A streamed respond on an endpoint with no method throws the MethodError for this function before anything is sent, as a streamed chatrequest! does for a missing handle_sse_event!.

UniLM.AgenticStreamStateType#
AgenticStreamState()

Public extension API (not exported); see the Custom Backends guide.

Mutable per-stream assembly state for the agentic streaming seam (decode_agentic_stream). Carries the layer-1/2 SSE machinery state (carry partial-line buffer, last_event sticky event name), the accumulated output text (textbuff), the not-yet-forwarded text deltas (pending_delta), the per-stream drop count (sse_dropped), and — for providers whose terminal event omits the step list (Gemini Interactions) — a per-index registry of assembled steps: steps maps a step index to its (mutable) step dict, and order records first-seen index order for deterministic output rebuilding. text_by_step holds each step's streamed string (answer text, function-call argument JSON, or thought signature, depending on the step type), read once when the interaction completes.

System One protocols

A System One backend is reached through a protocol, a Holy trait of its endpoint: UniLM.system_one_protocol maps the endpoint to a UniLM.SystemOneProtocol, whose UniLM.encode_system_one turns a request into a UniLM.SystemOneWire — what is sent, and the record_body a recording is keyed on — refusing before any I/O what the backend cannot carry — and whose UniLM.decode_system_one turns the reply into a typed result. Three protocols ship: UniLM.TypeSafeProtocol (TypeSafe's POST /v1/systemone), UniLM.OpenAIDecisionsProtocol (OpenAI's POST /v1/decisions, for OPENAIServiceEndpoint) and UniLM.OllamaSystemOneProtocol (Ollama's POST /v1/systemone, for OllamaEndpoint). They are documented with the System One API.

A server that speaks TypeSafe's wire — a gateway, a proxy, a mock — needs no protocol code. To send TYPESAFEServiceEndpoint's requests there, set TYPESAFE_BASE_URL. To give it an endpoint of its own, declare :system_one, its base URL and its credentials; an endpoint without a system_one_protocol method speaks TypeSafeProtocol:

struct JevGateway <: UniLM.ServiceEndpoint end
UniLM.provider_capabilities(::Type{JevGateway}) = Set([:system_one])
UniLM._api_base_url(::Type{JevGateway}) = "https://jev-gateway.example.com"   # internal hook
UniLM.auth_header(::Type{JevGateway}) =
    ["Authorization" => "Bearer $(ENV["JEV_GATEWAY_KEY"])", "Content-Type" => "application/json"]

ask("My parcel never arrived.", "team" => choice(["billing", "shipping"]); service = JevGateway)

Its requests are TypeSafe's, byte for byte, and its recordings are keyed as TypeSafe's — on the request's path and body, never its host — so an answer recorded through one replays for the other.
