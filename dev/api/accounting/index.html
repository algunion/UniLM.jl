Cost Tracking & Token Usage

Token accounting works across providers — Gemini and Anthropic usage is normalized to the shared shape at decode time, so these accessors and the pricing table apply uniformly to Chat, Responses, and the agentic verb.

For a worked walkthrough — reading usage, the silent-\$0 footgun on unpriced models, custom pricing, and per-Chat cumulative totals — see the Cost Tracking guide.

Token Usage

UniLM.TokenUsageType#
TokenUsage(; prompt_tokens=0, completion_tokens=0, total_tokens=0, cached_tokens=0, reasoning_tokens=0,
           cache_write_tokens=0, cache_write_extended_tokens=0, service_tier=nothing, inference_geo=nothing,
           prompt_audio_tokens=0, completion_audio_tokens=0, cached_audio_tokens=0)
TokenUsage(prompt_tokens, completion_tokens, total_tokens, cached_tokens, reasoning_tokens)

Token usage statistics returned by the API, in one shape for every provider.

prompt_tokens counts every input token, cache reads and cache writes included. Of them, cached_tokens were read from the prompt cache and cache_write_tokens written to it; cache_write_extended_tokens is the part of cache_write_tokens written at the extended retention (OpenAI "12h", Anthropic "1h"). reasoning_tokens is the part of completion_tokens spent on hidden reasoning. prompt_audio_tokens is the part of prompt_tokens that is audio input and completion_audio_tokens the part of completion_tokens that is audio output, as OpenAI Chat Completions reports them for a model that hears or speaks; prompt_audio_tokens also counts Gemini's audio input on the native endpoint and Gemini Interactions. cached_audio_tokens is the part of cached_tokens that is audio, as Gemini reports it on the native endpoint (cacheTokensDetails) and Gemini Interactions (cached_tokens_by_modality); no other provider reports it. The counts are 0 when the provider omits them, as GEMINIOpenAIServiceEndpoint does: its audio input is in prompt_tokens alone. service_tier is the tier the provider reports billing the call at (OpenAI's service_tier, for example) and inference_geo the inference region it reports; each is nothing when the provider reports none. One exception: on GEMINIOpenAIServiceEndpoint, whose replies name no billed tier, a Chat result's service_tier is the tier the request asked for, so "flex" is priced at the Flex rates and "priority" at the Priority rates — an upper bound, since Google bills a downgraded Priority request at Standard and this endpoint does not report the downgrade.

estimated_cost bills cached_tokens at the discounted cached-input rate and the rest at the standard rates, unless the provider's own pricing applies (see DEFAULT_PRICING): OpenAI bills the audio tokens at the model's audio-token rates and Gemini audio input, and the audio it reads from the cache, at the rates its pricing page states for the model; any other audio leaves the estimate at 0.0. Audio a provider does not count apart (GEMINIOpenAIServiceEndpoint's) is priced with the text in prompt_tokens. Positionally the fields go in the order listed, the five counts first; the fields left out take their defaults.

UniLM.token_usageFunction#
token_usage(result::LLMRequestResponse) -> TokenUsage

Extract token usage from a token-billed API result (chat, Responses, embeddings, image generation and FIM completions); failures of those APIs report zero usage.

Results from APIs that do not report token usage at all — audio, files, batches, moderations, vector stores, … — throw an ArgumentError. A zero would be indistinguishable from a genuinely free call and would quietly under-count spend.

Cost Estimation

UniLM.estimated_costFunction#
estimated_cost(result::LLMRequestResponse; model=nothing, pricing=DEFAULT_PRICING) -> Float64

Estimate the cost in USD of a single API call from the token usage its result carries.

The model priced is model when given; else the one the provider reports having served — result.model of a Chat result (LLMSuccess), result.response.model of a Responses or FIM result; else the one requested — result.self.model for Chat, result.embeddings.model for Embeddings.

Returns 0.0 for failures, which carry no billable usage, for an unpriced model, for audio tokens UniLM has no rate for (see DEFAULT_PRICING for the audio it prices) and for an embeddings reply that reported no usage (Gemini's OpenAI-compatible endpoint reports none); the last three also log a warning, once per model id (for audio, per model and endpoint). A local model — one an OllamaEndpoint serves from a server of your own, its name carrying no cloud tag — bills no one: unless model is given, it costs 0.0, without the warning, unless pricing holds a row you gave its exact name. The rows UniLM ships price hosted models, never a local model that bears one's name (Ollama's ollama cp llama3.2 gpt-3.5-turbo), in DEFAULT_PRICING or copied into a table such as merge(DEFAULT_PRICING, …); a row equal to a shipped one counts as the shipped one. A billed service tier the provider's pricing page lists no price for is estimated at the standard rates, with one warning per model and tier. Throws ArgumentError for result types outside the token-billed APIs — see token_usage — and, unless model is given, for an ImageSuccess: the Images API bills image tokens at rates a price row does not model, and a price this function cannot compute is not a zero it can report. pricing is any AbstractDict{String,PriceRow}.

Model lookup: the exact id first, then the id without a dated snapshot suffix (gpt-5.4-mini-2026-03-17 → gpt-5.4-mini, claude-opus-4-5-20251101 → claude-opus-4-5). A versioned Jev id with no row of its own (jev-X.Y.Z, e.g. a release newer than this table) is priced at the jev-latest row. That is an assumption: TypeSafe's Models page lists Jev 1.14 and Jev 1.13 at one price, USD 42 per billion input tokens (2026-10-25); a later version is assumed to keep it until the page says otherwise. The same lookup prices SystemOneSuccess results.

The row's rates bill fresh input tokens and cache writes at input, cache reads at cached_input and completion tokens at output, except where UniLM models a provider's surcharges, which apply to that provider's results (see DEFAULT_PRICING).

estimated_cost(result::SystemOneSuccess; model=nothing, pricing=DEFAULT_PRICING) -> Float64

Estimate the USD cost of one System One evaluation from its token usage and the price row of the model that answered (result.response.model), unless model overrides it. TypeSafe bills input tokens only — output tokens are currently free, which the shipped jev-* price rows encode as an output rate of 0.0. An id with a dated snapshot suffix uses its base id's row; a versioned jev-X.Y.Z id without its own row is priced at the jev-latest row (assuming a later Jev keeps the price TypeSafe's Models page lists for Jev 1.14 and Jev 1.13); any other unpriced name returns 0.0. An answer from a local model through an OllamaEndpoint costs 0.0, without a missing-price warning, unless pricing holds a row you gave the model's exact name (a row UniLM ships for a hosted model of that name does not count) or model is passed; a cloud model reached through it (a tag of cloud or ending in -cloud) is priced by the name requested, which an answer whose reply drops the tag keeps. A backend that bills otherwise is priced its own way: an answer from OpenAI's Decisions API (OpenAIDecisionsProtocol) costs its input tokens alone, and no output: the uncached ones at the row's input rate, cache reads at its cached-input rate, and cache writes and more than 272K input tokens at the surcharges OpenAI lists for the model (gpt-6-luna: a write at 1.25 times the input rate, 2.5 times for a 12-hour lifetime, and every rate twice above 272K).

UniLM.cumulative_costFunction#
cumulative_cost(chat::Chat) -> Float64

Return the estimated cost, in USD, that chatrequest! and prefix_complete calls on this Chat have accrued, priced with DEFAULT_PRICING as estimated_cost prices a result: a local model's turns add 0.0 unless you added a row for its exact name to the table (a row UniLM ships for a hosted model of that name does not count). A committed turn adds its result's cost. A call that ends without committing one adds what its provider reported billing it, a lower bound: the replies of a continued Gemini turn received before the failure or stop, and the usage a stream had reported when it was stopped, cancelled, timed out, cut off or ended by an exception from its callback or on_tool_call — Anthropic reports a request's input when its stream starts and Gemini the usage so far on every chunk, while OpenAI reports it after the finish reason. A request stopped before any usage arrived adds nothing, though the provider bills it, as do an attempt that was retried, a stream the provider ended with an error event, and an unstreamed reply UniLM could not decode.

UniLM.DEFAULT_PRICINGConstant#

Default per-token pricing; OpenAI, Anthropic and Gemini rows verified on 2026-10-22 (OpenAI's gpt-5-search-api on 2026-10-25, gpt-5.2-pro on 2026-10-26), TypeSafe rows on 2026-10-25, DeepSeek rows on 2026-09-24 (prices drift — re-verify before relying on them). Cached input is billed at the discounted cached_input rate; reasoning tokens are already counted within output tokens. The rows are standard short-context text rates. Where UniLM models a provider's surcharges — cache-write premiums, long-context tiers, service-tier, speed or region multipliers — estimated_cost applies them to these rates for that provider's results; every other result is billed at the standard rates. A billed service tier the provider's pricing page lists no price for — such as OpenAI's Scale tier, Fast on gpt-5.4-pro or on a gpt-5.5 prompt over 272K tokens — is estimated at the standard rates, with one warning per model and tier.

A row has no audio-token rates. estimated_cost bills the audio tokens (prompt_audio_tokens, completion_audio_tokens) of an OPENAIServiceEndpoint result at the model's audio-token rates, which UniLM has for gpt-audio-1.5, and the audio input of a native Gemini or Interactions result at the input price Google's pricing page states for audio, scaled by the billed tier and a long prompt's multiples as text is: the model's own audio price where the page lists one apart (gemini-3.1-flash-lite, gemini-3-flash-preview, gemini-2.5-flash, gemini-2.5-flash-lite), else the row's input rate, since the page spells modalities out wherever their rates differ and an input price that names none is every modality's. A cache hit bills at the row's cached rate, since a one-price model's cache price names no modality either, except the audio a usage reports among its cached tokens (cached_audio_tokens) on those four models, which bills at the cached-audio price their tables list apart. Any other audio — on a model the page prices without audio (the image models) or does not list, on another endpoint, Gemini audio output, or a cache hit on one of those four models whose usage reports more cached tokens than text tokens and cached audio together, so that its split is unknown — leaves the estimate at 0.0, with one warning per model and endpoint. GEMINIOpenAIServiceEndpoint reports no audio count, so its audio input is priced at the text rate, a lower bound where the model's audio price is its own; such a request warns once per model. Off-peak discounts, other multimodal rates and hosted-tool fees are not included.

A lock-guarded AbstractDict{String,PriceRow}: add or replace rows with DEFAULT_PRICING[model] = row from any task while requests are running.
