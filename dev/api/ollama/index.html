Reference · API: language models

Ollama

A local Ollama server: the endpoint, its runtime options, and the model-management verbs. The Ollama entry shows them at work.

Endpoint

UniLM.OllamaEndpointType#
OllamaEndpoint <: OpenAIWireEndpoint
OllamaEndpoint(; base_url=<OLLAMA_HOST or http://127.0.0.1:11434>,
               keep_alive=nothing, truncate=false, shift=nothing,
               runner=nothing, options...)

A local (or remote) Ollama server. Chat and Embeddings requests use Ollama's native /api/chat and /api/embed, which carry what the OpenAI-compatible routes ignore: the context window and the other OllamaOptions, how long the model stays loaded (keep_alive), and the think and truncate fields. respond, compact_response, FIMCompletion and transcribe use the OpenAI-compatible routes (/v1/responses, /v1/responses/compact, /v1/completions, /v1/audio/transcriptions), which carry none of the endpoint's keep_alive, OllamaOptions or runner.

  • base_url: server root, without /v1 or /api. Defaults to the OLLAMA_HOST environment variable, read with the rules of Ollama's own clients ("gpu-box" → http://gpu-box:11434), else http://127.0.0.1:11434.
  • keep_alive: seconds the model stays loaded after each request (0 unloads it at once, Inf keeps it loaded); nothing leaves the server's default (5 minutes unless OLLAMA_KEEP_ALIVE says otherwise).
  • truncate: whether Ollama may shorten an input to fit the context window. In chat it can cut inside a single over-long message, keeping its first tokens and its tail (Ollama 0.40.6: a 5,407-token message cut to 2,050 tokens, the first 4 kept), so the start of a long document is lost without a word, not only the oldest messages; in embeddings it drops the end of an input. false (the default) makes an input that does not fit a failure — HTTP 400 "exceeds the available context size" — instead of an answer to a silently shortened prompt; raise num_ctx, or set true for Ollama's own behaviour. On the MLX runner (Apple Silicon) the window does not bound a chat prompt: a longer one is not refused (verified with Ollama 0.40.6).
  • shift: whether generation that fills the context window may continue by dropping earlier context (nothing: the server's default, on). false ends such a reply with finish reason "length". Ollama reloads the model when this changes.
  • runner: the runner to serve a model with — :mlx (Apple Silicon), :llamacpp or :ggml; nothing (the default) leaves the choice to the server. Ollama matches it against the runner the model's manifest names, the one list_models reports as OllamaModel.runner. A model published for several runners is served by its variant for the one pinned (by Ollama's source; untested). A model published for one — every model measured — answers as if unpinned when that runner is pinned, and any other is the server's error, never a fallback: HTTP 400 no compatible manifest found for runners: <runner> (404 from model_info, and so from load_model), even while the model is loaded (Ollama 0.40.6: :llamacpp on kev:0.8b-q8_0 answered and running_models reported :llamacpp; :mlx and :ggml on it, and :llamacpp on tev1:0.8b, were that 400). Pin the runner the listing names, not the one running_models reports: a GGUF model listed as :ggml (qwen2.5-coder:1.5b-base, embeddinggemma:latest) answers pinned to :ggml, is served by llama.cpp, and is the 400 pinned to :llamacpp. The pin goes with every request of the endpoint, so a pinned endpoint fails for each model without a variant for its runner. Sent with chat, embeddings, System One, model_info, load_model, unload_model and pull_model requests; delete_model, the listings and the OpenAI-compatible routes (respond, compact_response, FIM, transcription) take none.
  • options...: keyword arguments of OllamaOptions, e.g. num_ctx=32_768. An embeddings request for EmbeddingGemma 2 (and its load_model) carries its trained 8,192-token window, num_ctx and num_batch 8192, unless the endpoint sets either: at Ollama's default batch the llama.cpp builds measured refuse long inputs — embeddinggemma-2:740m-q8_0 anything past about 2,037 tokens (Ollama 0.40.6).

A Chat's reasoning_effort, and a Respond's Reasoning effort, go to Ollama by name: "none" turns thinking off (think: false), and every other effort is sent as it is, for Ollama to resolve against the model, whose thinking levels are its own (thinking). On /api/chat, a model with thinking metadata applies a level it names and uses its default for any other name; a model without takes "low", "medium", "high" and "max", and answers another name, such as "minimal" or "xhigh", with HTTP 400 invalid think value (Ollama 0.40.11). On /v1/responses (OpenAI compatibility), a model without metadata reads "minimal" as "low" and "xhigh" as "max", a model whose levels are true and false takes any effort but "none" as true, and GPT-OSS reads "minimal" as "low" and "xhigh" as "high". model_info reports a model's thinking_levels and thinking_default.

A server of the caller's own gets no API key. Ollama's cloud does: a request to https://ollama.com (which OLLAMA_HOST=ollama.com names) carries the OLLAMA_API_KEY environment variable as Authorization: Bearer whenever it is set, read each time a request is built. Ollama asks for it for inference — "Direct cloud inference at https://ollama.com/api and https://ollama.com/v1 requires an API key" (authentication) — and lists the cloud's models without one (cloud). With the variable unset or blank, an inference request (chat, embeddings, respond, compaction, FIM, transcription, System One, a model's load or unload) is not sent — the call error's cause is an ArgumentError naming it — and list_models, model_info, running_models, pull_model and delete_model go without it. Local models cost nothing unless you price them: estimated_cost reports 0.0 for a chat, embeddings, respond or FIM result, without a missing-price warning, unless you gave the model's exact name a row, in pricing= or added to DEFAULT_PRICING; a row UniLM ships for a hosted model never prices a local model that bears its name. A cloud model reached through the local server — a model whose tag is cloud or ends in -cloud (clef:cloud, gpt-oss:120b-cloud) — is billed by Ollama and is priced by the name requested, never as a free local call: a System One, respond or FIM result whose reply drops the tag (gpt-oss:120b) keeps the requested name, and the server's stays in its raw, while a chat or embeddings result is priced by the model its request names; a name missing from the price table logs the missing-price warning. Every model a request to Ollama's cloud itself (https://ollama.com) names is priced the same way: the cloud bills it, and names its models without a tag, "such as gemma4:31b" (cloud). Through a local server a model is recognised as cloud by that tag alone, so a cloud model copied under a name without it (ollama cp) is priced as local: 0.0 unless you gave it a row.

ollama = OllamaEndpoint(num_ctx=32_768, keep_alive=600)
chat = Chat(service=ollama, model="gemma4:e4b")
UniLM.OllamaOptionsType#
OllamaOptions(; num_ctx=nothing, num_batch=nothing, num_gpu=nothing,
              main_gpu=nothing, num_thread=nothing, use_mmap=nothing,
              num_keep=nothing, top_k=nothing, min_p=nothing,
              repeat_last_n=nothing, repeat_penalty=nothing,
              draft_num_predict=nothing, typical_p=nothing)

The Ollama runtime and sampling options that Chat has no field for, sent as the options object of an OllamaEndpoint request; unset options are omitted, so the model's own defaults apply. Options Chat already names (temperature, top_p, seed, stop, max_tokens, presence_penalty, frequency_penalty) stay on the Chat, so no option can be set in two places.

  • num_ctx: context window in tokens. Ollama loads the model with this window; a model with vision gets at least 2,048 tokens (embeddinggemma-2:740m-q8_0 asked for 1,024 loaded with 2,048 on Ollama 0.40.6 and 0.40.7; Ollama's server/sched.go). On the llama.cpp and ggml runners a request with another num_ctx reloads the model, and a prompt longer than the window is refused (HTTP 400) unless truncate=true; on the MLX runner (Apple Silicon) the window applies when the model is loaded, a loaded model keeps it when a later request asks for more, and it does not bound a chat prompt (verified with Ollama 0.40.6 on the llama.cpp and MLX runners; ggml untested).
  • num_batch, num_gpu (layers offloaded to the GPU), main_gpu, num_thread, use_mmap: how the model runs on this machine.
  • num_keep: tokens of the prompt kept when the context is shifted.
  • top_k, min_p, repeat_last_n, repeat_penalty: sampling.
  • draft_num_predict: the most speculative draft tokens predicted per step when the model has a draft model: "Separate draft models default to 4; embedded MTP tensors require setting this parameter. Set to 0 to disable speculative drafting." (Modelfile).
  • typical_p: locally typical sampling. Ollama deprecates it — "typical_p is deprecated and may be removed in a future release" (its API reference) — and still reads it per request, logging "deprecated option provided" (Ollama 0.40.11).

Every option is passed through unchanged; the effect of those other than num_ctx on the MLX runner is not verified. Ollama's API reference also lists penalize_newline and numa, which Ollama 0.40.11 does not read (its log says "invalid option provided", and the request goes on without them), so OllamaOptions has neither.

The constructor throws ArgumentError for a value out of range: num_ctx, num_batch and num_thread must be positive, top_k non-negative (0 turns top-k off), min_p in [0, 1], typical_p in [0, 1], repeat_penalty and draft_num_predict non-negative, repeat_last_n and num_keep at least -1, num_gpu at least -1 and main_gpu non-negative.

Models

UniLM.model_infoFunction#
model_info(name; service=OllamaEndpoint(), config=nothing,
                 cancel=nothing)

What an Ollama server knows about the installed model name (POST /api/show): an OllamaSuccess holding an OllamaModelInfo — capabilities, context length, thinking levels, Modelfile parameters — or an OllamaFailure (404 for a model that is not installed) or an OllamaCallError. Transient statuses are retried under config (a RequestConfig); cancel (default: the ambient with_cancel token) ends the call with a UniLMCancelled in cause. The endpoint's runner goes with it: Ollama shows the variant it would run with that runner, and answers a model that has none with HTTP 404 no compatible manifest found for runners: <runner> (Ollama 0.40.6). An empty name throws ArgumentError before any request.

r = model_info("gemma4:e4b")
issuccess(r) && r.response.thinking_levels   # [false, true]
UniLM.pull_modelFunction#
pull_model(name; service=OllamaEndpoint(), progress=nothing,
           config=nothing, cancel=nothing)

Download name from the Ollama registry to the server (POST /api/pull). progress(p::OllamaPullProgress) runs once per report the server streams, in order, on the calling task; the last reports "success". Returns OllamaSuccess{Nothing} once the server reports success, an OllamaFailure for a non-200 reply, or an OllamaCallError: the server's message for a failure it reports on the stream (an unknown tag: "pull model manifest: file does not exist"), a stream that ends before success, an exception progress threw (in cause), a timeout, or a cancel.

One attempt, never retried. The response headers must arrive within min(request_timeout, remaining total_deadline) of the RequestConfig; after that only stream_idle_timeout — the longest gap between bytes, time spent in progress excluded — bounds the download, however long it runs. cancel (default: the ambient with_cancel token) stops it at once, with a UniLMCancelled in cause. The endpoint's runner goes with it: by Ollama 0.40.6's source (untested), from a model published for several runners Ollama pulls the variant for that runner, and a model published for another one fails with no compatible manifest found for runners: <runner>. An empty name throws ArgumentError before any request.

show_progress(p) = isnothing(p.total) ? println(p.status) :
    println(p.status, " ", p.completed, "/", p.total, " bytes")
r = pull_model("gemma4:e2b"; progress=show_progress)
issuccess(r)
UniLM.running_modelsFunction#
running_models(; service=OllamaEndpoint(), config=nothing,
                 cancel=nothing)

The models an Ollama server holds in memory now (GET /api/ps): an OllamaSuccess holding a Vector{OllamaRunningModel} — empty when none is loaded — or an OllamaFailure or OllamaCallError. config and cancel work as for model_info.

r = running_models()
issuccess(r) && foreach(println, r.response)
UniLM.load_modelFunction#
load_model(name; service=OllamaEndpoint(), config=nothing,
                 cancel=nothing)

Load name into memory now, so the first request does not wait for it. Loads name the way its kind allows (read from model_info): a chat model with an empty chat request, an embedding or decision model with an empty embeddings request (EmbeddingGemma 2 with the 8,192-token window its embeddings requests carry); the reply comes once the model is loaded. The endpoint's keep_alive and runner go with it, and so does what the model's own requests carry: a chat model's load the endpoint's OllamaOptions and shift, an embedding model's those options, and a decision model's no options at all, as System One requests carry none. Ollama loads the model with those settings, so load through the endpoint you will use. On the llama.cpp runner a later request with other options loads the model again; on the MLX runner a loaded model keeps its context when a later request asks for more: unload_model first to load it with another num_ctx. Returns OllamaSuccess{Nothing}, an OllamaFailure (404 for a model that is not installed), or an OllamaCallError, also for a reply that does not report the load. config and cancel work as for model_info; total_deadline bounds the whole call. An empty name throws ArgumentError before any request, and so does an endpoint with keep_alive=0: Ollama reads that request as an unload.

ollama = OllamaEndpoint(num_ctx=32_768, keep_alive=Inf)
load_model("gemma4:e4b"; service=ollama)  # 32k context, stays loaded
UniLM.unload_modelFunction#
unload_model(name; service=OllamaEndpoint(), config=nothing,
                   cancel=nothing)

Free the memory name holds now rather than when its keep-alive runs out (an empty chat request with keep_alive 0, which works for every kind of model; the endpoint's runner goes with it). Returns OllamaSuccess{Nothing}, an OllamaFailure, or an OllamaCallError, also for a reply that does not report the unload. config and cancel work as for model_info; an empty name throws ArgumentError before any request.

unload_model("gemma4:e4b")
UniLM.delete_modelFunction#
delete_model(name; service=OllamaEndpoint(), config=nothing, cancel=nothing)

Remove the installed model name from an Ollama server's disk (DELETE /api/delete). Returns OllamaSuccess{Nothing}, an OllamaFailure (404 for a model that is not installed), or an OllamaCallError. config and cancel work as for model_info. An empty name throws ArgumentError before any request. There is no undo: pull_model downloads it again.

delete_model("all-minilm:22m")
UniLM.OllamaModelType#
OllamaModel

One model installed on an Ollama server, as list_models reports it (/api/tags): name (e.g. "gemma4:e4b"), size on disk in bytes, content digest, modified_at (the server's RFC 3339 text), and from its details family, parameter_size (e.g. "8.0B"), quantization (e.g. "Q4_K_M") and context_length, the longest context the model supports. runner — the runner the server's listing names for the model (:mlx, :llamacpp, :ggml), the one an OllamaEndpoint's runner must name to reach it, which can differ from the one that serves it once loaded: OllamaRunningModel.runner (/api/ps) reports that — and format (:gguf, :safetensors), as Ollama 0.40 and later report them; nothing when not reported. capabilities holds what the server reports, e.g. :completion, :tools, :insert, :vision, :embedding, :thinking, :image and :audio. A detail the server does not report, or reports empty (""), is nothing; raw holds the unparsed entry.

UniLM.OllamaModelInfoType#
OllamaModelInfo

What model_info reports about one model (/api/show): the name asked for, its capabilities (as for OllamaModel), context_length (the longest context it supports, from its metadata), the thinking_levels it accepts — [false, true] for a model that thinks or not, names such as "low", "medium", "high" for one with levels, empty for a model that cannot think — and thinking_default. parameters are its Modelfile defaults with numbers parsed ("top_k" => 64); a parameter set more than once, such as stop, collects a Vector{String}. family, parameter_size and quantization come from its details, nothing when not reported or empty (""). runner — the runner /api/show's details name: :llamacpp or :mlx on Ollama 0.40.6, else nothing (a legacy GGUF model names none: embeddinggemma:latest, and qwen2.5-coder:1.5b-base even shown through an endpoint pinned to :ggml, while list_models reports :ggml for both), which can differ from OllamaModel.runner (/api/tags) and from the runner that serves it once loaded (OllamaRunningModel.runner, /api/ps) — and format (:gguf, :safetensors), as Ollama 0.40 and later report them; nothing when not reported or empty (""). raw holds the whole reply (template, license, model_info, …).

UniLM.OllamaRunningModelType#
OllamaRunningModel

A model loaded in an Ollama server's memory, as running_models reports it (/api/ps): name, size (bytes of memory it takes), size_vram (the part in GPU memory), the context_length it was loaded with, and expires_at, when it unloads unless used again (RFC 3339 text). runner — the runner serving it now (:mlx, :llamacpp, :ggml), as Ollama 0.40 and later report it; nothing when not reported or empty (""). raw holds the unparsed entry.

UniLM.OllamaPullProgressType#
OllamaPullProgress

One progress report of pull_model: status ("pulling manifest", "pulling <digest prefix>", "verifying sha256 digest", "writing manifest", "success") and, while a layer downloads, its digest and the completed and total bytes (nothing otherwise). completed is an Int whenever total is: Ollama leaves a zero count out of its report, and it is read back as 0.

list_models lists a server's installed models when its service is an OllamaEndpoint.

Results

UniLM.OllamaSuccessType#

Successful Ollama model-management result: response holds what the verb reports (nothing for pull_model, load_model, unload_model and delete_model).

UniLM.OllamaFailureType#

Ollama error result: HTTP status, the raw response body (Ollama's {"error": …}), and the request_id the server sent (x-request-id/request-id header), if any.

UniLM.OllamaCallErrorType#

Ollama call that produced no usable reply (no server, a timeout, a cancel, a malformed reply, or a failure reported on the pull stream); cause is the underlying exception — a UniLMTimeout for a timeout, a UniLMCancelled for a cancel.
