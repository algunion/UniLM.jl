Caching, cost & limits

Prompt caching

A Chat with prompt_cache_options turns on Anthropic's automatic caching: UniLM sends a top-level cache_control, {"type": "ephemeral"} with the options' ttl when one is set, and the API puts the cache breakpoint on the request's last cacheable block (prompt caching). PromptCacheOptions() asks for the cache's default lifetime, 5 minutes, and PromptCacheOptions(ttl="1h") for an hour. The options a Chat cannot send to Anthropic are refused before the request (Limits and refusals).

Anthropic's cache "references the entire prompt: tools, system, and messages (in that order)", and the breakpoint is where it is written: one entry, holding everything up to and including that block. Anthropic isolates caches by workspace: a later request in the same workspace (Options) that starts with the same blocks up to that breakpoint reads the entry while it lives, unless a change has invalidated it, and writes what follows them; the API checks at most 20 positions for such an entry, counting the request's breakpoint as the first and a run of consecutive tool_use blocks, or of consecutive tool_result blocks, as one position. Changed tools invalidate the entire cache, and a changed system prompt that prompt and the messages; a changed tool_choice, an image added or removed anywhere in the prompt and changed thinking parameters invalidate at least the messages, and Anthropic's table lists the other changes and what each invalidates (what invalidates the cache). A Chat builds each request from its fields as they are then, the whole conversation and tools included, so the next turn starts with the previous one's blocks as long as the tools, the system prompt and the earlier turns go out as they did before. A system message pushed mid-conversation can change that: it may join the top-level system prompt, and the request then reads none of what the earlier requests wrote and writes it all again, or move within the messages (Conversations says how UniLM places one). Two requests that share only a long system prompt, each with its own question, write two entries and read none: a Chat marks no breakpoint of its own. A prefix shorter than the model's minimum cacheable prompt, which Anthropic sets per model between 512 and 4,096 tokens, is not cached, and the API returns no error: the usage then shows neither a write nor a read.

The usage counts the reads and the writes (First call), and cache_write_extended_tokens the writes kept for an hour; what each costs is in Cost and usage. On most models, reads do not count toward Anthropic's rate limit of input tokens per minute (rate limits). Here a generated parts list is the system prompt of a conversation, and each turn asks about one part:

parts = join(("Part $(1000 + i): $(4 + i % 9) mm bolt, $(7i % 50) in stock." for i in 1:80), "\n")
chat = Chat(service=ANTHROPICServiceEndpoint, prompt_cache_options=PromptCacheOptions())
push!(chat, Message(Val(:system), "Answer questions about this parts list in one short sentence.\n\n" * parts))
push!(chat, Message(Val(:user), "How many of part 1042 are in stock?"))
result = chatrequest!(chat)
text(result)

u = result.usage
(; u.prompt_tokens, u.cache_write_tokens, u.cached_tokens, cost = round(estimated_cost(result); digits=6))

push!(chat, Message(Val(:user), "And part 1077?"))
result = chatrequest!(chat)
text(result)

u = result.usage
(; u.prompt_tokens, u.cache_write_tokens, u.cached_tokens, cost = round(estimated_cost(result); digits=6))

The first request wrote the system prompt and its question to the cache. The second read them back and wrote only what the conversation had added, the reply and the next question.

Cost and usage

estimated_cost prices a result with the row of the table below for its model (First call says which model that is), an id with a -YYYYMMDD snapshot suffix with the row of the id without it, and cumulative_cost adds up the calls of a Chat. Of the usage, it bills the uncached input at the input rate, the cache reads at the cached-input rate, the cache writes at 1.25 times the input rate, or 2 times for the writes kept for an hour (cache_write_extended_tokens), and all the output, thinking included, at the output rate (pricing). Every rate is then multiplied by each factor that applies, the factors stacking:

  • 2 for a call served in fast mode, whose usage reports service_tier == "fast" (Request options);
  • 1.1 for US-only inference, a usage that reports inference_geo == "us", except on the models whose inference_geo cell in the family table is "—", which bill the standard rates;
  • a model's long-prompt multiplier, for a prompt over its threshold, all of its input counted, cache reads and writes included.

Two kinds of model are priced otherwise: a model with a long-prompt multiplier bills more over its threshold, and a model of the family table without a price row is estimated at 0.0:

ModelEstimated
claude-haiku-5-5every rate × 5 for a prompt over 100,000 tokens
claude-mythos-preview0.0, with a warning: it has no price row

A call Anthropic reports at Priority Tier (service_tier == "priority") is estimated at the list rates, as a standard one is: Priority Tier draws down an organization's capacity commitment (service tiers), which no rate here models. A model with no row, one of the family table as above or any other id, is estimated at 0.0, with one warning per model id: pass estimated_cost a pricing table that holds its row, or add the row to DEFAULT_PRICING. A failure costs 0.0, since it carries no usage.

How a stream reports its usage, and what a stream that ends uncommitted adds, is on Streaming. cumulative_cost is a lower bound of the bill, refusals Anthropic does not bill aside: it adds nothing for an attempt UniLM retried, a stream Anthropic ended with an error event, or an unstreamed reply UniLM could not decode (Cost Tracking). It prices every refusal at the usage Anthropic reports, while Anthropic bills a refusal that arrives before any output only when its stop_details.category is one its page lists as billed: "bio", "frontier_llm" and "reasoning_extraction" on 25 October 2026 (how refusals are billed).

Rate limits, overload and failures

chatrequest! returns what the service or the network did as a typed result, and does not throw it (Results). An LLMFailure holds an HTTP status and, as response, what came with it: the body of a status other than 200; the event of an in-band overloaded_error, with status 529; or what a stream that ended before its turn had sent, with status 200. An LLMCallError holds, as error, the text of an exception or of another in-band error event, and the exception as cause when there is one. UniLM sends a request again after a transient status, 429 and 529 among them and Anthropic's 500 and 504, as often as the call's RequestConfig allows, and then returns the last answer (Timeouts & Retries); a streamed request is sent again only while none of its callbacks has run. A 429 of the monthly spend cap is not transient: UniLM returns it at once.

Models

The listing is the endpoint's models capability: list_models with service=ANTHROPICServiceEndpoint asks Anthropic's Models API (GET /v1/models) which models your key can use, fetches every page of the answer, and returns a ModelListSuccess whose models are ProviderModels, the most recently released first. Each holds the model's id and display_name, its release as created (nothing where Anthropic gives the Unix epoch, its value for an unknown date), its input_token_limit and its output_token_limit, the largest max_tokens a request may set, the capabilities object Anthropic sends, the dates it was deprecated (deprecated) and retires (retires), and the entry as sent in raw (Model Listings). Anthropic lists the active and the deprecated models, not the retired ones: raw["lifecycle"] says which, and a retires date may still move until the model retires (List Models). An error status on any page is a ModelListFailure, with its status, response and request_id; a call that brings no listing — no key, which it names, no connection, a timeout, a reply that is not the listing — is a ModelListCallError.

A listing bills no tokens and is not recorded, so its output here is quoted from a live run:

r = list_models(service=ANTHROPICServiceEndpoint)
r isa ModelListSuccess || error("the listing failed: $r")

The capabilities say what Anthropic takes on each model: its thinking types and effort levels, which the family table holds UniLM's requests to, image and PDF input, structured outputs, server tools and more. They show what a model newer than this release takes, too. Before you use a newly listed model, check that it has a price row, as the last line above does with the lookup of estimated_cost: a model without one is estimated at 0.0 (Cost and usage). UniLM's release gate runs the same listing, and fails when a listed Claude model of 4.5 or later has no price row, unless Anthropic publishes no price for it, or no row in the family table, or when a row's thinking types or effort levels differ from the listing's.

The OpenAI-compatible endpoint

Anthropic also serves the OpenAI-compatible wire, at https://api.anthropic.com/v1/chat/completions, "primarily intended to test and compare model capabilities", and not "a long-term or production-ready solution for most use cases" (compatibility layer). ANTHROPICServiceEndpoint does not use it. To evaluate it, give a GenericOpenAIEndpoint the bare host, since it appends /v1/chat/completions, and name a model:

compat = GenericOpenAIEndpoint("https://api.anthropic.com", "", "ANTHROPIC_API_KEY")
chat = Chat(service=compat, model="claude-opus-5-5")

There UniLM is an OpenAI-compatible client and no more:

  • No default model, no Anthropic rules. A Chat without model throws ArgumentError. Only the checks every Chat gets run, its constructor's among them (a temperature from 0 to 2, n of 1, …): every field the Chat sets is sent, temperature and reasoning_effort included, and no row of Limits and refusals applies. Anthropic ignores most fields it does not support, response_format, reasoning_effort and a tool's strict among them, and joins every system message into the top-level system prompt.
  • No refusal of other verbs. The endpoint declares the Responses, embeddings and FIM capabilities, so respond, embeddingrequest! and fim_complete send their requests rather than refuse them.
  • No Anthropic headers. The key goes as Authorization: Bearer, with no anthropic-version and none of the Options: no anthropic-workspace-id, which Anthropic asks for with a key that is not scoped to a workspace.
  • No caching, no thinking. Anthropic's layer supports no prompt caching and returns no thinking, and UniLM keeps no provider_content from it: reasoning_text gives nothing, and no thinking block goes back.
  • Standard rates. estimated_cost prices the model's row at its standard rates, none of the factors of Cost and usage applied, and a stream reports its usage only when the Chat sets stream_options=Dict("include_usage" => true).
