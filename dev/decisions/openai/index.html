Decisions · OpenAI Decisions API

OpenAI Decisions API

OpenAI's Decisions API reads an input — a text, a JSON value, pictures — and answers the predicate, choice and score questions you list about it with a probability for each answer you allowed, writing no text; OpenAI bills the input and no output (Decisions guide). OPENAIServiceEndpoint, the endpoint of the OpenAI language-model entry, speaks it at POST /v1/decisions for ask and the verbs built on it, with the same key, and no decision verb refuses the endpoint. Of the API, UniLM does not wrap an input_json part in the input, custom tool calls and their outputs, a developer message or an assistant message's phase, image URLs, a score level's description, explicit cache breakpoints, the organization's Decisions usage endpoint or GPT-Live's Decisions integration.

Setup

Set the API key of your OpenAI account in the environment Julia starts from:

export OPENAI_API_KEY="..."

A call goes to the Decisions API when it names service = OPENAIServiceEndpoint, or when it names no service and a with_system_one(OPENAIServiceEndpoint) scope encloses it; a call that names neither goes to the chapter's default provider (Decisions). A call's model is its own model = …; else, when it names no service, the scope's; else the default model at the top of this page. UniLM reads OPENAI_API_KEY when each request is sent, so a key exported after using UniLM takes effect; with none, a call sends nothing and returns a SystemOneCallError (When something fails). Requests go to https://api.openai.com, and no variable moves them.

OpenAI's guide, fetched on 25 October 2026, opens with "The Decisions API is now generally available" and lists what the API gained "since the public beta": prompt caching, pictures in question instructions, JSON input, up to 400 questions per request, image URLs, conversation history, usage reporting, GPT-Live's integration and Private Link (What's new). UniLM sends up to 400 questions, pictures and JSON data in a question's instructions, and a conversation as the input (Questions).

Options

The endpoint takes no constructor arguments. Three request options of the API are keywords of ask and ask_each, options = (…) on the natural-language verbs, or keywords of with_system_one for a scope; each is sent as a field of the request (Create a decision):

KeywordWhat OpenAI does with itChecked before sending
prompt_cache_key"Partition prompt cache reuse by caller-provided key."a String of at most 64 characters
safety_identifieran "opaque caller-provided end-user identifier, scoped by the verified org"a String of at most 128 characters
prompt_cache_optionsits mode and ttl choose the cache breakpoints and how long they lasta PromptCacheOptions of mode and a ttl of "30m" or "12h"

OpenAI reuses a request's shared input once it holds at least 1,024 tokens, with a breakpoint at its end unless mode = "explicit", and the questions are outside the reusable prefix (Reuse shared input with prompt caching). UniLM marks no breakpoint, so with mode = "explicit" a request uses no cache. OpenAI's reference calls "30m" "currently the only supported value" of ttl; UniLM also sends "12h", which OpenAI answered with HTTP 200 on 25 October 2026. None of the three changes an answer, so none is part of a recording's key (Testing and recordings), and a value outside the last column is refused before anything is sent (Limits and refusals).

First decision

One request carries the input once and every question about it; each answer comes back under the name you gave its question, which the API echoes (How decisions work):

const TEAM = (billing   = "payments, charges, invoices or refunds",
              technical = "the app or the website does not work as expected",
              shipping  = "a parcel that is late, lost or arrived damaged",
              other     = "anything else")
message = "I was charged twice for order #4471. Please refund the duplicate payment."

r = ask(message, "team" => choice("Which team should handle this message?", TEAM); service = OPENAIServiceEndpoint)
a = r["team"]
(a.choice, a.probabilities[a.choice], a.confidence)

a.choice is the most probable option, a.probabilities holds one probability per option, and a.confidence says how peaked they are (Confidence and tuning). A failed call has no answers: r["team"] throws a SystemOneError on it (When something fails), and a question OpenAI declines comes back as a RefusalAnswer, which has no choice (Declined questions).

r.response.model, token_usage(r).prompt_tokens, r.response.request_id

The call named no model, so it was sent with the default model at the top of this page, and r.response.model is the model OpenAI's reply names; r.response.request_id is the reply's x-request-id header. nl_classify makes the same kind of decision in one call and returns the key whose description fits (Dispatch on Meaning):

nl_classify(message, TEAM; service = OPENAIServiceEndpoint)

Models

OpenAI serves the Decisions API with one model, the default model at the top of this page: the guide calls it "the only currently supported model", and its model page gives one snapshot, under the same name. A call may name another model; UniLM sends it, and on 25 October 2026 OpenAI answered gpt-6-sol with HTTP 404 and the code model_not_found (When something fails). Each reply names the model that answered, and r.response.model holds it: log it with each decision, since a threshold tuned on one model is a claim about that model (Confidence and tuning).

list_models(service = OPENAIServiceEndpoint) lists every model OpenAI serves the key, the language models with this one (Models); no recording holds it, so inside a replay scope it reaches OpenAI with your key (Testing and recordings).

A conversation is evidence the questions are asked about: OpenAI's guide passes "conversation history in input to evaluate a request in context" (Evaluate a conversation). The other decision providers take the same vector as data, its messages as JSON objects (What each provider takes). This block is not run when the manual is built:

conversation = [Message(Val(:user), "My order #4471 arrived broken."),
                Message(role = RoleAssistant, content = "I am sorry: a refund is on its way.")]
ask(conversation, "resolved" => noul("Does the reply resolve the customer's problem?");
    service = OPENAIServiceEndpoint)

What reaches the model:

  • Question names travel. Each question carries its name, which the API echoes so that UniLM matches each answer to its question. OpenAI's pages do not say whether the model reads it, so write the whole question in its instructions.
  • Option names and descriptions travel. A Choice's option names and their descriptions are both in the request; OpenAI's guide asks for "distinct values and descriptions that explain when each option applies" (Select from fixed options).
  • Instructions may hold pictures and data. Every question needs instructions: a string, or the parts that stand in its place — a picture, a JSON object, or a vector or tuple of strings, pictures and JSON objects (or arrays of objects), sent in order as input_text, input_image and input_json parts. OpenAI's guide puts the evidence every question shares in the input, and gives each question its own picture to compare against it (Include images in question instructions).
  • Other guidance is text. An option's description and a Score level are strings, and a predicate has no place for a Noul's yes and no, so fold them into its instructions. Anything else is a refusal (Limits and refusals).

A question with a picture of its own, compared against the one the state holds for every question (this block is not run when the manual is built):

reference, candidate = ImageAttachment("reference.png"), ImageAttachment("candidate.png")
ask(["The shared image is reference image A.", reference],
    "variant" => noul(["Is candidate image B a derivative or variant of reference image A?", candidate]);
    service = OPENAIServiceEndpoint)

A Choice takes 2 to 255 options (Create a decision) and a Score 2 to 10 levels (Score against a rubric), and a request 1 to 400 questions (Ask multiple questions); a request outside these is refused before it is sent (Limits and refusals). A picture goes in the state, as the table shows, or in a question's instructions; where each provider takes one is on Choosing a decision provider. Reading the answers and the decision rules on them are on Route and Decide.

Declined questions

OpenAI may decline any question: "Any question can return a refusal instead of an answer; other questions can still receive answers" (Create a decision). UniLM returns such an answer as a RefusalAnswer, whose raw holds what OpenAI sent and which has no value to read: after ask, test a isa RefusalAnswer before you read a.choice, a.score or a.noul; the other answers of the request read as usual. nl_classify, nl_dispatch and @branch take a refusal as a decline whatever their policy, which never sees it: fallback runs (the _ line, in @branch), or DecisionDeclinedError is thrown with the refusal as its answer.

route(::nl"the customer wants a refund", msg)           = :refunds
route(::nl"the customer reports a bug in the app", msg) = :engineering
route(::nl"anything else", msg)                         = :frontline

nl_dispatch(route, message; service = OPENAIServiceEndpoint, fallback = msg -> :person)

@branch message service = OPENAIServiceEndpoint min_confidence = 0.5 begin
    "the customer wants a refund"           => :refunds
    "the customer reports a bug in the app" => :engineering
    _                                       => :person
end

Had OpenAI declined either question, the fallback and the _ line would have answered :person. nl_dispatch sends the arguments it dispatches on as a JSON object, which OpenAI receives as its JSON text; a picture among them is refused, since that text holds no picture: pass state = [image, "…"] to send one (Limits and refusals). A verb whose call offers a single option is refused too, since a Choice takes two or more (Limits and refusals): add a fallback option such as "other", which OpenAI's guide advises "when your categories don't cover every possible input" (Select from fixed options).

Confidence and tuning

A predicate's answer is the probability that its statement holds; a Choice or a Score answer carries a probability distribution and "a separate confidence field", and OpenAI tells you to set thresholds on "labeled examples from your application", by "the cost of false positives and false negatives" (Interpret the answers). OpenAI computes confidence and UniLM passes it on; in the replies recorded for this manual it equals the Choice formula of Reading answers, to two decimals. Those replies give every probability and confidence to two decimals, so ask accepts a distribution within 0.005 per outcome of a sum of 1, and a chosen option at most 0.01 below the most probable one; a reply further off is a SystemOneCallError.

The bar is yours: below min_confidence, a natural-language verb returns what fallback returns, and with no fallback it throws LowConfidenceError. Of the six messages of a support desk's inbox, the cracked phone is the unclear one:

const MESSAGES = [
    "I was charged twice for order #4471. Please refund the duplicate payment.",
    "The app crashes every time I open my order history. iPhone 15, latest version.",
    "My parcel was due last Monday and the tracking hasn't moved in six days.",
    "Do you ship to Norway, and how much does delivery cost?",
    "The phone I received has a cracked screen and the box was crushed. I want my money back.",
    "Your update deleted my saved addresses and now I can't check out. Third time this month!",
]

seen = SystemOneSuccess[]
team = nl_classify(MESSAGES[5], TEAM; service = OPENAIServiceEndpoint, min_confidence = 0.6,
                   fallback = message -> :person, on_response = r -> push!(seen, r))
answered = only(seen)["classify"]
(team, findfirst(==(answered.choice), TEAM), answered.confidence)

OpenAI's best guess, billing, came with a confidence below the 0.6 asked for, and the message went to a person. On a labelled set of ours, OpenAI's top probabilities ran below how often it was right: the model is under-confident there, so a bar tuned on another provider, or on another set, hands a different share of the work to a person here. Tune min_confidence on messages of your own, on this provider; where some mistakes cost more than others, price each one and let a decide policy choose the cheapest action (When mistakes have different prices), once you have checked that the probabilities are calibrated. The decision rules on every provider are on Act on the answer, and the same messages on each provider are on Choosing a decision provider.

Evidence

Measured on 20 October 2026 on our 129 labelled support tickets (60 clear, 32 borderline, 15 adversarial, 22 out of scope), one Choice of seven intents per ticket, each option a name with a description, one call at a time, on gpt-6-luna: accuracy 0.946, expected calibration error 0.080 (10 bins), Brier score 0.076, mean top probability 0.89; 101 tickets at a confidence of 0.8 or more, all of them right, so 28 went to a person at that bar; in every bin above 0.5, accuracy was at least the mean top probability. Latency 0.48 s at the median and 2.44 s at the 95th percentile; $0.0000296 a ticket. Limits: one labelled set, one run, one way of writing the options.

Cost

OpenAI bills a decision's input tokens and no output: uncached input at the model's input rate, while "prompt cache hits receive discounted input pricing; cache writes are charged", both at the model's caching rates; "regional processing premiums and long-context input pricing multipliers apply" (Pricing and availability). The rates are the default model's row of Cost and usage.

u = token_usage(r)
(u.prompt_tokens, u.cached_tokens, u.cache_write_tokens, u.completion_tokens, estimated_cost(r))

prompt_tokens is OpenAI's input_tokens, which includes the cached and the cache-written ones, cached_tokens its cached_tokens and cache_write_tokens its cache_write_tokens. estimated_cost prices them as the guide does: the uncached input at the model's input rate, the cache reads at its cached-input rate, the cache writes at its write rate — a 12-hour write, counted in cache_write_extended_tokens, at its own — every rate twice for a request of more than 272K input tokens, and no output; it adds no regional premium, which a response does not show. A request whose shared input is under the 1,024 tokens caching needs, such as the one above, reads and writes no cache. Totals across calls and prices of your own are on Cost Tracking.

Testing and recordings

with_recorded_answers records an exchange with the Decisions API once and replays it with no key and no network: ask, ask_each and the verbs built on them. A recording is filed under /openai-decisions/v1/decisions, the request's path behind the namespace openai-decisions, so a question asked of two providers is two recordings, and it is keyed on the exact request: its method, that path, and its body, which names the model. prompt_cache_key, safety_identifier and prompt_cache_options are sent and left out of the key and the file, and a picture is keyed and written as data:<mime>;sha256,<hex>, the SHA-256 of its base64 text, never its bytes.

recordings = mktempdir()      # in a package: a directory committed next to the tests
recorded = with_recorded_answers(recordings; mode = :record) do
    ask(message, "team" => choice("Which team should handle this message?", TEAM); service = OPENAIServiceEndpoint)
end
JSON.parsefile(only(readdir(recordings; join = true)))["request"]["path"]

replayed = withenv("OPENAI_API_KEY" => nothing) do
    with_recorded_answers(recordings) do
        ask(message, "team" => choice("Which team should handle this message?", TEAM);
            service = OPENAIServiceEndpoint, prompt_cache_key = "support-inbox")
    end
end
replayed["team"].probabilities == recorded["team"].probabilities

The replay names a prompt_cache_key the recording did not, and is answered from it. Recording takes OPENAI_API_KEY, and replaying takes nothing; in this manual's build the recording scope above replays the manual's own recordings, so the example reaches no service either (How this manual runs its examples). list_models on this endpoint is not recorded: inside a scope it goes to OpenAI, with the key, as outside one.

  • What a recording cannot hold. OpenAI declines a question when it chooses to, so no recording can be made to hold a refusal. Requests go to https://api.openai.com alone, so to test what your code does with one, declare an endpoint of your own that speaks this API's wire to a local server, through the protocol seam (Write your own decision provider); _api_base_url is an internal hook. Run such tests outside with_recorded_answers. This block is not run when the manual is built:
using UniLM, HTTP, JSON, Test

struct DecisionsMock <: UniLM.ServiceEndpoint end
UniLM.provider_capabilities(::Type{DecisionsMock}) = Set([:system_one])
UniLM.system_one_protocol(::Type{DecisionsMock}) = UniLM.OpenAIDecisionsProtocol()
UniLM._api_base_url(::Type{DecisionsMock}) = "http://127.0.0.1:8124"     # internal hook
UniLM.auth_header(::Type{DecisionsMock}) = ["Content-Type" => "application/json"]

TEAM = (billing = "payments, charges, invoices or refunds", other = "anything else")
server = HTTP.serve!("127.0.0.1", 8124; verbose = false) do req
    # A refusal of the one question, as OpenAI's reference shapes it; the name is the question's.
    body = (model = "gpt-6-luna", answers = [(type = "refusal", name = "classify")],
            usage = (input_tokens = 42, output_tokens = 0))
    HTTP.Response(200, ["Content-Type" => "application/json"], JSON.json(body))
end

@testset "a declined question" begin
    @test nl_classify("Where is my parcel?", TEAM; service = DecisionsMock, fallback = m -> :person) === :person
    @test_throws DecisionDeclinedError nl_classify("Where is my parcel?", TEAM; service = DecisionsMock)
    r = ask("Where is my parcel?", "classify" => choice("Which team?", TEAM); service = DecisionsMock)
    @test r["classify"] isa RefusalAnswer
end
close(server)
  • A pipeline with a language model. A test that also calls a language model records each request with its own provider's key and replays with none (Test a decision + LLM pipeline offline).

Previews of what a call sends, tests of the methods and of the judgment, and an audit trail are on Test and Develop.

When something fails

A call that reaches OpenAI returns a SystemOneSuccess; a SystemOneFailure for a status other than 200, with the status, OpenAI's message, its error_type — the error's code, else its type — and the request_id; or a SystemOneCallError when no usable response came. A 200 whose answers do not fit the request — a question unanswered, answers out of the order asked, an option that was not offered, probabilities that are no distribution within the rounding above — is a SystemOneCallError too. Reading an answer of a failed call (r["name"], answer, answers) throws a SystemOneError.

UniLM sends a request again after a 408, 429, 500, 502, 503, 504, 520 to 524 or 529, up to max_attempts times within total_deadline, waiting at least what the reply's retry-after-ms header asks for, else its Retry-After, as the shared backoff of ask_each does. A 429 whose code is a spent credit, a spend or usage limit, or insufficient_quota is not sent again, since "retrying billing, spend, or quota errors won't restore API access" (Error codes); any other status comes back as it is. With no RequestConfig of your own, a call to the Decisions API is bounded by 60 s per attempt and 150 s in all, and ask_each keeps 16 requests in flight unless its ntasks says otherwise (Many requests at once); a config of your own replaces the bounds, per call or for a scope:

scoped = with_request_config(request_timeout = 20.0, max_attempts = 5) do
    ask(message, "team" => choice("Which team should handle this message?", TEAM); service = OPENAIServiceEndpoint)
end
issuccess(scoped)

OpenAI sets its rate limits per organization and project, and they "vary by the model being used" (Rate limits).
