Thinking, tools & output

ANTHROPICServiceEndpoint turns each request field of a Chat into its Messages API counterpart. A field with none is refused before the request is sent, except n, which a Chat takes only as 1: the one reply every request gets.

Tools

Each Tool in tools goes out with its name, its description when it has one, its parameters as input_schema — {"type": "object", "properties": {}} for a function without parameters — and its strict flag when its FunctionSignature sets one: strict=true makes the API validate each call's name and input against the tool's schema. The Messages API takes tool names of 1 to 128 letters, digits, _ and -. UniLM sends a name as given, and mcp_tools(session; service), with service this endpoint, advertises each tool of an MCP server under such a name: its own, or that name with each character outside that set replaced by _, one over 128 characters cut and marked with a hash of its MCP name; with no service, the names it gives are at most 64 characters (MCP). Anthropic's MCP connector, a beta (mcp-client-2025-11-20), allows you to "connect to remote MCP servers directly from the Messages API without a separate MCP client", the servers named in an mcp_servers array of the request (MCP connector). UniLM sends no mcp_servers: an MCP server's tools reach Claude through mcp_tools, which calls the server from your process.

tool_choice becomes the API's own: "auto" sends {"type": "auto"}, "none" sends {"type": "none"}, "required" sends {"type": "any"}, and UniLM.GPTToolChoice(func=:get_weather) sends {"type": "tool", "name": "get_weather"}. A forced choice, "required" or a named tool, is refused on the models whose Forced tool choice cell in the family table is "—", and any other string on every model (Limits and refusals).

A Chat with tools has parallel_tool_calls = false unless it sets another value, and sends it as disable_parallel_tool_use: true on its tool_choice, which is {"type": "auto"} when it sets none: the model then makes at most one tool call per turn. Set parallel_tool_calls = true to let it make several in one turn; a tool_choice of "none" carries no such flag.

An assistant turn that called tools goes back in the blocks it arrived in, as Conversations describes; a turn that holds none of Anthropic's blocks, written by hand or answered by another provider, goes as its text and one tool_use block per call. The tool messages that answer it become tool_result blocks, consecutive ones in one user turn. A tool message whose tool_call_id matches no tool call of an earlier assistant turn is refused (Limits and refusals).

tool_loop! runs the calls and sends their results back until the model answers in text. Here the model thinks before it calls the tool:

weather = CallableTool(
    Tool(func=FunctionSignature(name="get_weather", description="The current weather in a city",
        parameters=Dict("type" => "object", "properties" => Dict("city" => Dict("type" => "string")),
                        "required" => ["city"]))),
    (name, args) -> "18 °C and sunny in $(args["city"])")
chat = Chat(service=ANTHROPICServiceEndpoint, tools=[weather], reasoning_effort="high")
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user),
    "What is the weather in the capital of the country that hosted the 2016 Summer Olympics?"))
loop = tool_loop!(chat; tools=[weather])
text(loop.response)

call = chat.messages[3]   # the turn that called the tool
[b["type"] => first(get(b, "signature", ""), 12) for b in call.provider_content.blocks]

The turn that called the tool holds a signed thinking block before its tool_use block, and tool_loop! sent that turn back unchanged, the tool result after it, in the request that got the answer: Anthropic requires a tool result to come with the thinking blocks of the turn that called the tool, complete and unmodified (thinking in tool workflows). A streamed turn's tool calls are on Streaming, and the loop every provider shares is on Tool Calling.

Structured output

A JSON Schema response_format becomes output_config.format = {"type": "json_schema", "schema": …}: Claude's structured outputs, which constrain the reply to the schema. Only the schema is sent; the format's name, description and strict have no counterpart.

using JSON
capital = UniLM.json_schema("capital", "A capital city and its country",
    Dict("type" => "object",
         "properties" => Dict("city" => Dict("type" => "string"), "country" => Dict("type" => "string")),
         "required" => ["city", "country"], "additionalProperties" => false))
chat = Chat(service=ANTHROPICServiceEndpoint, response_format=capital)
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "Give the capital of Norway."))
JSON.parse(text(chatrequest!(chat)))

The reply's text is the JSON document. ResponseFormat(), a json_object format, is refused (Limits and refusals). Strict tool calls are a flag of each tool (Tools), and the formats every provider shares are on Structured Output.

Reasoning

reasoning_effort sets the effort of a request, output_config.effort. With adaptive thinking the model decides on each request whether to think and how much, and the effort steers that decision (thinking). A model id takes the row of the same id, or of that id without a -YYYYMMDD snapshot suffix, never the row of an id it merely starts with; an id no row names, such as a model newer than this release, is refused only by the rules that name no column of the table. The columns:

  • Thinking: the model's thinking mode, which decides what reasoning_effort sends (the table above).
  • Effort levels: the reasoning_effort levels from "low" to "max" the model takes; "—": it takes no reasoning_effort at all. What "none" does follows the Thinking cell (the table above).
  • Forced tool choice: whether tool_choice may force a call (Tools).
  • Prefill: whether a request may end with an assistant turn (Request options).
  • Mid-conversation system messages and Thinking prefix check: where a system message pushed after the conversation starts goes (Conversations).
  • Fast mode: whether service_tier="fast" is served, and the beta header it needs where it is in research preview (Request options).
  • inference_geo: whether the model takes the endpoint's inference_geo (Options).

reasoning_text reads the summary of a turn's thinking:

chat = Chat(service=ANTHROPICServiceEndpoint, reasoning_effort="low")
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "What is the smallest positive integer that leaves a remainder of 1 " *
    "when divided by 2, 3, 4, 5 or 6, and is divisible by 7? Answer with the number only."))
result = chatrequest!(chat)
text(result)

reasoning_text(result)

u = result.usage
(; u.completion_tokens, u.reasoning_tokens)

reasoning_text joins the text of a turn's thinking blocks with a blank line, and gives nothing for a turn with none; a redacted_thinking block carries no text and adds none. Thinking is billed in full as output, whatever summary comes back (thinking cost), and estimated_cost prices it at the output rate (Cost and usage); how the usage counts it is on First call, and how max_tokens bounds it on Setup.

The blocks of a reply that is not a refusal — thinking blocks with their signatures, redacted_thinking blocks, text and tool calls — are kept in its message's provider_content and go back on the next request (Conversations). A streamed reply keeps them only when every block arrived whole: with one cut short — its stop event lost, or a tool call's input that is no JSON object on a turn cut at max_tokens or the context window, which drops that tool call — the message holds no provider_content, and the turn goes back as the text and tool calls it holds, or is left out when it holds neither; on a turn that stops with tool_use, end_turn or stop_sequence, such an input makes the result an LLMCallError, and nothing is appended. Kept blocks go back whatever Claude model the next request names, and a turn cut at max_tokens that holds only thinking blocks goes back too, as Anthropic's guide to continuing such a turn asks. Another provider's encoder ignores them and sends the turn's text and tool calls alone.

Attachments

A user message's attachments go out as base64 blocks before its text, in their order — the order Anthropic's vision and PDF guides recommend: an ImageAttachment (PNG, JPEG, GIF or WebP) as an image block, and a DocumentAttachment (PDF) as a document block, without its filename. A message with empty text sends the blocks alone.

chat = Chat(service=ANTHROPICServiceEndpoint)
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "What colour is the shape? One word.",
                    ImageAttachment("../../assets/red_circle.png")))
text(chatrequest!(chat))

The one-page PDF holds one sentence:

chat = Chat(service=ANTHROPICServiceEndpoint)
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "What does the report conclude? Answer in one sentence.",
                    DocumentAttachment("../../assets/bridge_report.pdf")))
text(chatrequest!(chat))

An AudioAttachment and an image's detail level are refused before the request (Limits and refusals). UniLM checks no size or page count of its own: the API answers for media past its limits. Which models read images and PDFs is in each model's capabilities, listed by list_models (Models); the attachment types are on Attachments.

Request options

safety_identifier, user and metadata["user_id"] each name the end user, and the Messages API has one field for that, metadata.user_id: set one of them, or set them to the same id. metadata holds no other key.

service_tier takes the Messages API's "auto" and "standard_only", sent as they are, and "fast": fast mode, sent as speed: "fast" without a service_tier. Fast mode is served on the models whose Fast mode cell in the family table is "yes", and on those whose cell names a beta header only through an endpoint whose betas hold it; UniLM refuses it on the other rows, and sends it unchecked for an id no row names. How a fast call is reported and priced is on First call and Cost and usage. Where inference runs is the endpoint's inference_geo (Options).

stop becomes stop_sequences, a single string a list of one, and stream=true becomes stream: true (Streaming). n is not sent: a Messages API request has one reply, and a Chat takes no n other than 1.

A response prefill, a request that ends with an assistant turn for the model to continue, is a Chat with history=false whose last message is an assistant message: with history=true, chatrequest! throws InvalidConversationError for such a conversation, since the reply could not be appended. UniLM sends a prefill on the models whose Prefill cell is "yes" and for an id no row names, and refuses it on the others (Limits and refusals).

UniLM.encode_request returns the body chatrequest! sends, or throws the refusal the table in Limits and refusals lists, with no key and no request:

chat = Chat(service=ANTHROPICServiceEndpoint, service_tier="fast", stop="END", safety_identifier="user-42")
push!(chat, Message(Val(:system), "You are a concise assistant."))
push!(chat, Message(Val(:user), "Count to five."))
print(UniLM.encode_request(chat.service, chat))

JSON.json(chat) is not this body: it writes the Chat in the Chat Completions shape of the OpenAI-compatible wire.

Limits and refusals

A request's output stops at its max_tokens (Setup), and a model's largest max_tokens and its input limit are in its list_models entry (Models). UniLM checks a request against neither, and leaves the size of media to the API (Attachments). Rate limits and overload are on Rate limits, overload and failures.

A field the Messages API has no counterpart for, n aside, is refused, not dropped, since dropping it would send a request other than the one asked for; so is each request in the table below that the API would answer with an error, or would run other than asked. chatrequest! and tool_loop! throw these ArgumentErrors before anything is sent. A rule that names a column of the family table holds for the ids of its rows, and an id no row names meets only the other rules. Building an endpoint refuses an option value that breaks its rule (Options).
